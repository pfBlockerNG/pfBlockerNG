1. THE MANIFEST 'abp' TAGGING + WHAT THE RAW NOW CONTAINS
================================================================================
* pfb_unbound_python_sources($feeds) (inc:~2385) now reads a per-row 'format' key
  ('abp'|'plain'; defaults 'plain' if absent) and writes it as the manifest
  format_hint. For an 'abp' feed it copies the per-feed '.txt' lines into the
  per-feed '.raw' VERBATIM (rtrim \r\n only; skip empty) -- NO col1 extraction, NO
  comma-split (so a /re/ with commas survives intact). For a 'plain' feed it keeps
  the ADR-06 col1 bare-domain extraction unchanged.
* WHO SETS 'format' (two $pfb_py_feeds[] sites in the DNSBL download loop):
    - parse path  (inc:~8362): 'format' => $easylist ? 'abp' : 'plain'.
    - reuse path  (inc:~7806): 'format' => file_exists("{$header}.abp") ? 'abp'
      : 'plain'  (a reused feed is NOT re-parsed, so $easylist is unknown there).
* THE '.abp' MARKER (inc:~8367): on the parse path, when $easylist is TRUE PHP
  @touch()es "{$pfbfolder}/{$header}.abp"; otherwise unlink_if_exists() it. This
  persists the ABP-ness so the reuse path carries the format_hint forward across
  builds. (It lives next to the feed's .txt/.orig; the unused-alias sweep at
  inc:~8410 only globs $pfb['dnsalias'], so the marker is not collected there.)
* WHAT REACHES PYTHON for an 'abp' feed: the RAW ABP lines as downloaded, minus
  (a) the ABP header line + '!'/'[' comment/control lines (PHP `continue`s on them
  so the raw is dense; Python's parse_abp would skip them anyway), and (b) the
  IP-anchored/hosts-IP lines (diverted to the firewall, SS3). Everything else --
  ||domain^, @@||domain^, /re/, @@/re/, $important, $badfilter, $options,
  ##/path/page-context lines -- flows VERBATIM; parse_abp keeps the in-scope ones
  and skips the out-of-scope ones (Phase-4/6 logic, unchanged this phase).
* The '.txt' content for an 'abp' feed is now raw ABP lines (written by the loop's
  new easylist branch, SS2). $list_cnt = grep -c ^ {header}.txt still counts lines.
  The hardcoded unbound-checkconf $result (inc:~8290) is a post-ADR-06 no-op (it
  never runs checkconf), so the '.bk' holding raw ABP lines is harmless.

3. THE DNSBL-IP ABP-ANCHOR HANDLING (coexistence, ADR-06 fact 7)
================================================================================
NEW helper pfb_dnsbl_abp_extract_ip($line) -> string (inc:~2320):
  * ||host^[$options]   -> strips the $options suffix, takes the token before '^',
    returns it iff is_ipaddrv4||is_ipaddrv6 (else '').  e.g. ||1.2.3.4^ -> '1.2.3.4'.
  * "<sink-ip> <target>" (hosts) -> returns the 2nd token iff BOTH tokens are IPs
    (e.g. 0.0.0.0 203.0.113.99 -> '203.0.113.99'). A hosts line whose target is a
    DOMAIN returns '' (the domain flows to Python as a raw line).
NEW easylist branch in the download loop (inc:~7907 onward):
  1. if dnsbl_ip != 'Disabled': $abp_ip = pfb_dnsbl_abp_extract_ip($line).
       - IPv4 -> sanitize_ipaddr/validate_ipv4 -> $domain_data_ip[]; updateip=TRUE.
       - IPv6 -> validate_ipv6 -> $domain_data_ip6[]; updateip=TRUE.
       - then `continue` -- IP -> firewall ONLY, NOT passed to Python.
     (When dnsbl_ip IS 'Disabled', the IP-anchored line falls through to the raw
      passthrough; Python's parse_abp then drops it via the IP-anchor skip -> still
      no DNS leak, exactly today's "firewall off" intent.)
  2. skip '' / '!' / '[' lines (raw stays dense).
  3. else: @fwrite($dhandle, "{$line}\n"); $domain_data="{$line}\n"; `continue`.
     The raw ABP line is the output; $domain_data is set non-empty so the feed
     takes the success/validation path (inc:~8290) and is kept.
The $domain_data_ip/_ip6 arrays then flow UNCHANGED into the existing dedup ->
{header}_v4.ip/_v6.ip -> glob -> DNSBLIP_v4.txt/_v6.txt -> DNSBLIP_v4/_v6 pf alias
machinery (inc:~8190+, ~8480+). NO double-handling: IP keys never enter dataDB/
zoneDB/regexDB (proven by the new test, SS5), domains/regex never enter the IP set.

pfb_py_count (the LOADED entry total, inc:~3364) -- UNCHANGED. Python still emits
len(dataDB)+len(zoneDB) via dnsbl_emit_count(pfb["pfb_py_count"], ...). Its value
rises legitimately as ABP @@/regex/un-pruned entries load (by design, NOT a
regression; ADR §2). No PHP change needed for it this phase.

DNSBL_Regex alias (the P6/P7 carry-over item) -- RECONCILED:
  * PYTHON now emits the ADMITTED regex total to a NEW file
    /var/unbound/pfb_py_regex_count (pfb["pfb_py_regex_count"]) at init, AFTER both
    the user REGEX-ini load AND the feed-regex merge:
        dnsbl_emit_count(pfb["pfb_py_regex_count"], len(regexDB) + len(allowRegexDB))
    Because the P7 static cap drops over-cap feed AND user patterns at load, this
    live size is exactly the cap-filtered admitted count (= user-admitted + feed
    block-admitted + feed allow-admitted). Single source of truth.
  * PHP reads it for the alias (inc:~8443): $pfb['unbound_py_regex_count']. The
    alias is now surfaced when dnsbl_regex=='on' OR the Python file reports a
    non-zero admitted count (so FEED regex with no user regex still shows). When the
    file exists+numeric it is used; else PHP FALLS BACK to today's configured
    user-regex line count (the file is written at resolver (re)load, so on a first
    run / pre-reload it may be stale or absent -- same nature as pfb_py_count).
  * The file is unlink_if_exists()'d on the full DNSBL clear path (inc:~8609) so a
    stale count doesn't linger. Value CHANGES BY DESIGN (ADR §2 "Emit + counts").
inc:3149 note (RESULTS/01/06): no further reconcile required -- pfb_py_count policy
is unchanged; the only count whose value/semantics shift is the DNSBL_Regex alias,
handled above.
