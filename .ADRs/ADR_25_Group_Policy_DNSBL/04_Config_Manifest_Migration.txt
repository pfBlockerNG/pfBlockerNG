WHY THIS PHASE EXISTS
The Python decision layer (Phase 5) reads policy-groups from the manifest. This phase defines
how groups are stored (config.xml), how the legacy single-bypass migrates into the new model,
and how groups + the alias->bit map + per-group subscribed bitmask + client-CIDR->group map +
allow/deny lists + per-group schedule ranges + default-group policy are published into the
manifest the chroot reads.

ACTION PLAN (ordered)
1. config.xml schema: define a policy-groups section (follow existing pfblockerng config
   nesting + pfb_*/gp* naming). Each group: name, enabled, client CIDR list, subscribed
   DNSBL_ aliases, action tier (Block|Warn), allow-domain list, deny-domain list, and an
   OPTIONAL schedule reference (a pfSense Schedule name, like a firewall rule's `sched`).
   Define the DEFAULT group policy (all aliases, Block) for unmatched clients.
2. Migration: convert legacy pfb_gp + pfb_gp_bypass_list into a Bypass policy-group (empty
   alias subscription, no deny rules, no schedule => always-on PASS for its CIDRs). Idempotent;
   absent legacy keys => no group created, output byte-identical to today. Keep the legacy keys
   readable for one release if needed (decide + document).
3. Manifest extension: add to the $manifest the groups, the alias->bit map (mirroring Phase 3
   exactly), per-group subscribed bitmask, client-CIDR->group map, per-group allow/deny lists,
   the per-group SERIALISED SCHEDULE TIME RANGES (resolved from the <schedules> section into a
   form the chroot can evaluate; TZ-explicit per ADR SS3 so the wall-clock window is correct;
   a missing/dangling schedule ref => "always in force"), and the default-group policy.
   Validate every CIDR (sanitize_ipaddr / pfb_filter) and every domain rule before it enters
   the manifest (PFBL-01). With no groups configured, the manifest must be byte-identical to
   today (no new keys, or keys that the OFF path ignores).
4. Tests (PHPUnit, in tests/php/): schema decode (incl. the schedule ref); migration (legacy
   present -> Bypass group; ASSERT before-state then after-state; absent -> no-op); manifest
   shape before/after a group exists; the alias->bit map matches Phase 3; schedule
   serialisation (ranges emitted; dangling/removed ref -> always-on); invalid CIDR/domain
   rejected.
