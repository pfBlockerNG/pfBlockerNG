HOW THE EXISTING LOOP WAS EXTENDED
------------------------------------

The existing $log_types group/loop (~:396) was extended to add a second
Form_Select per log inside the same Form_Group:

  foreach ($log_types as $logdescr => $logtype) {
      $group = new Form_Group($logdescr);
      $first = TRUE;
      foreach ($logtype as $descr => $type) {
          // existing max-lines select (unchanged)
          $group->add(new Form_Select('log_max_' . $type, ...));
          // new schedule select — adjacent in the same group cell
          $rotate_sel = $group->add(new Form_Select(
              'log_rotate_' . $type, 'Schedule',
              $pconfig['log_rotate_' . $type], $options_log_rotate
          ))->setWidth(2);
          if ($first) {
              $rotate_sel->setHelp($rotate_help);   // once per group
              $first = FALSE;
          }
      }
      $section->add($group);
  }

The $log_types array covers all 10 log types (General: log/unilog/errlog/extraslog;
IP: ip_blocklog/ip_permitlog/ip_matchlog; DNSBL: dnslog/dnsbl_parse_err;
DNS Reply: dnsreplylog) — 10 max-lines selects → 10 schedule selects.

The section title was updated from 'Log Settings (max lines)' to
'Log Settings (max lines / rotation schedule)'.

LOAD WIRING
-----------

  $pconfig['log_rotate_<type>'] = PfbConfig::read('log_rotate_<type>');

All 10 reads go through PfbConfig::read() (lines ~:92–101). The registered
default ('off') is applied when the key is absent — no ?:'off' fallback needed.
No direct config_get_path() for these keys.

SAVE WIRING
-----------

Per-log validation handled in a separate loop (not via the existing
${"options_$s_option"} mechanism — that would cause PHPStan to flag
$options_log_rotate_<type> as undefined variables for all 10 keys):

  foreach ($log_rotate_keys as $rkey) {
      if (is_array($_POST[$rkey])) { $_POST[$rkey] = 'off'; }
      elseif (!array_key_exists($_POST[$rkey], $options_log_rotate)) { $_POST[$rkey] = 'off'; }
  }

Persist (lines ~:236–245): written into $pfb['gconfig']['log_rotate_<type>']
so the existing PfbConfig::writeSection() call picks them up with the rest of
the section. Using PfbConfig::write() then writeSection() would have overwritten
them (writeSection replaces the whole section with $pfb['gconfig']). No direct
config_set_path() for registered keys — PHPCS RequireConfigGateway: 0 errors.

HELP TEXT WORDING

  statistics reflect the current period only. Independent of the max-lines limit.
