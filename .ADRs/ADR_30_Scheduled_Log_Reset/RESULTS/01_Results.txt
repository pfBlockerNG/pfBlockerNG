PERIOD-KEY FORMAT
-----------------

  'off' or ''           -> '' (schedule disabled)
  'daily'               -> 'YYYY-MM-DD'   (PHP date('Y-m-d', $ts))
  'weekly'              -> 'YYYY-Www'      (PHP date('o-\WW', $ts) — ISO week-year)
  'monthly'             -> 'YYYY-MM'       (PHP date('Y-m', $ts))
  any unrecognised      -> '' (off-default, defensive)

ISO WEEK-YEAR DECISION
----------------------

Used date('o') (ISO 8601 week-YEAR) not date('Y') (calendar year) for
the weekly period key. This correctly handles year-end splits: 2027-01-01
falls in ISO week 2026-W53 (not 2027-W01), because the ISO year 2027 only
begins on 2027-01-04. The test asserts this concretely.

EDGES HARDENED
--------------

  - '' (empty string) is treated identically to 'off' in both functions.
  - Unrecognised schedules (e.g. 'DAILY', 'bogus', 'yearly') default to
    off-behaviour (return '' / FALSE) — asserted.
  - ISO week-year: date('o') chosen over date('Y') to avoid the
    calendar-year/ISO-year split — concretely asserted with 2027-01-01 and
    2027-01-04 which straddle the 2026-W53 / 2027-W01 boundary.
  - Empty $last_key (never reset) => TRUE for any active schedule —
    asserted for all three active schedules.
  - Timestamps in tests use mktime() (same timezone as date()) to avoid
    hardcoded epoch values that break across timezone environments.
