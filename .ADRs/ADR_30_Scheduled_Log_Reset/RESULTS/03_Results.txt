FUNCTIONS ADDED
---------------

All three new functions are in pfblockerng.inc, inserted between pfb_log_mgmt()
(line 1823) and pfb_logger() (formerly line 1826).

1. pfb_log_rotate_marker_parse(string $contents): array
   PURE — no I/O. Splits the marker file contents (one "<type>=<key>" per line)
   into a [type => key] map. Blank lines and garbled lines (no '=', leading '=',
   or invalid type chars) are silently skipped — absent/garbled => '' for that
   type => pfb_log_should_reset treats it as "never reset".

2. pfb_log_rotate_marker_serialize(array $entries): string
   PURE — no I/O. Emits "<type>=<key>\n" for each entry, sorted by type name for
   stable output. Returns '' for an empty map.

3. pfb_log_reset(): void
   The main per-log reset function. Calls pfb_global(), loads and parses the
   marker file once, then iterates the same 10-type array pfb_log_mgmt() uses.
   For each log:
     - Reads log_rotate_<type> via PfbConfig::read() (RequireConfigGateway).
     - Looks up its last period key from $entries[$logtype] ?? ''.
     - Calls pfb_log_should_reset($schedule, $last_key, time()); if FALSE, skips.
     - On TRUE: truncates the log to empty IN PLACE via "/bin/cp /dev/null".
       For python logs (dnslog, dnsreplylog, unilog): resolves through the chroot
       (checks is_dir("{$chroot_folder}/var/log/pfblockerng")), uses
       "{$chroot_folder}{$pfb[$logtype]}" as the final path, then @chown/chgrp
       'unbound' — identical to pfb_log_mgmt()'s python-log handling.
       For other logs: uses $pfb[$logtype] directly.
     - On exec failure: calls pfb_logger(), continues (that log's marker unchanged).
     - On success: writes the new period key to $entries[$logtype] and sets $changed.
   After the loop, persists the marker file if $changed (LOCK_EX).

MARKER FILE
-----------

Path:    /var/db/pfblockerng/log_rotate.last  ({$pfb['dbdir']}/log_rotate.last)
Format:  one line per log: "<type>=<period-key>\n"
         e.g.:  ip_blocklog=2025-07-15
                dnslog=2025-W29
                unilog=2025-07
Scope:   one entry per log type that has had at least one reset; absent = ''
         = "never reset" = eligible on next tick.

LOG SET (same as pfb_log_mgmt())
---------------------------------

  log, errlog, extraslog, ip_blocklog, ip_permitlog, ip_matchlog,
  dnslog, dnsbl_parse_err, dnsreplylog, unilog

Each read independently via PfbConfig::read('log_rotate_' . $logtype).

CRON CALL SITE
--------------

  src/usr/local/www/pfblockerng/pfblockerng.php:771 (pfb_log_mgmt() call)

  pfb_log_reset() is called immediately AFTER pfb_log_mgmt():

    pfb_log_mgmt();

    // ADR-30: reset each log that has a configured schedule and whose calendar
    // period has rolled over. Called after pfb_log_mgmt() so the line-cap trim
    // runs first; the reset then empties the log for the new period. Per-log
    // boundary-gated: a no-op for every log except those whose period just rolled.
    pfb_log_reset();

  It is NOT called on the settings-save path (pfblockerng.inc:9607 — that site
  calls pfb_log_mgmt() only; pfb_log_reset() is not wired there).

INODE + OWNERSHIP PRESERVATION
--------------------------------

  Non-python logs:
    exec("/bin/cp /dev/null " . escapeshellarg($pfb[$logtype]))
    cp /dev/null overwrites the existing file content in place without changing
    the inode. No mv, no unlink, no recreate.

  Python logs (dnslog, dnsreplylog, unilog):
    Identical chroot/ownership handling as pfb_log_mgmt():
      - $chroot_folder = '/var/unbound' (same constant)
      - if (is_dir("{$chroot_folder}/var/log/pfblockerng"))
            $final_log_file = "{$chroot_folder}{$pfb[$logtype]}"
        else
            $final_log_file = $pfb[$logtype]
      - exec("/bin/cp /dev/null " . escapeshellarg($final_log_file))
      - @chown($final_log_file, 'unbound')
      - @chgrp($final_log_file, 'unbound')
    Re-applying unbound ownership mirrors pfb_log_mgmt() exactly.

SNIFF COMPLIANCE
----------------

  RequireConfigGateway:
    Every schedule read is PfbConfig::read('log_rotate_' . $logtype) — no direct
    config_get_path() calls for registered keys. PHPCS: 0 errors.

  PFBL-01 RequirePfbFilter:
    pfb_log_reset() is NOT in the sniff's scopeFunctions allow-list, so its exec()
    calls are not in the sniff's scope. The sniff only guards in-scope input-handling
    surfaces (pfb_manage_dnsbl_vip etc.) — pfb_log_reset() is a management function
    that operates on controlled paths ($pfb[$logtype] from top-level config). The
    exec calls use escapeshellarg() for shell quoting. PHPCS: 0 errors.
