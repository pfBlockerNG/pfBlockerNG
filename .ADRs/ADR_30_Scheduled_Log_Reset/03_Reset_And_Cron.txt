WHY THIS PHASE EXISTS
With the deciders (P1) and per-log config fields (P2) in place, wire the actual reset: on
each cron tick, for EACH log, if its own log_rotate_<type> is set AND its calendar period
rolled over since its last reset, truncate THAT log to empty IN PLACE (inode + ownership
preserved, exactly as pfb_log_mgmt()), then record its new period. Cron cadence is
operator-defined, so the per-log boundary check makes each log reset once per period and be
a no-op otherwise (ADR §1.2/§2.2). Each log is independent.
