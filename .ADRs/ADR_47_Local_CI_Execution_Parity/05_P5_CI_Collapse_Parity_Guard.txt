--- scripts/resolve-legs.sh (NEW) — two families of subcommands; REUSE, never re-derive ---
A. `resolve-legs.sh legs --test-dir <DIR> [--label marker|tier] [--base-ref origin/devel]`
   The leg-filter shared by both prepare jobs. Reads env CI_MATRIX/EVENT_NAME/SCOPE_INPUT/
   VERSION_INPUT/PYTEST_K_INPUT. Owns EXACTLY the three identical blocks, verbatim semantics:
   1. SCOPE ladder: schedule→full; explicit SCOPE_INPUT; workflow_call→full; else impacted; then
      `case impacted|full` validate. (The workflow_call→full vs bare-dispatch→impacted split is
      LOAD-BEARING for test.yml/release.yml callers — get it wrong and they silently narrow to
      impacted, a green coverage regression. Preserve exactly.)
   2. THREE-WAY leg jq: version-exact `[.[]|select(.pfsense_version==$v)]` + zero-match `::error::`
      guard; full keep-all; impacted min-CE `[.[]|select(.channel=="CE")] |
      sort_by(.pfsense_version|split(".")|map(tonumber)) | .[0:1]` (NUMERIC sort — 2.8 < 2.10, not
      lexical) + empty `::error::` guard. Emit the WHOLE matched entry as RAW JSON — do NOT project
      (smoke forwards mac/freebsd_major/php_version/py_flavor/abi/image_name to smoke-single.yml;
      ui projects itself).
   3. -k DERIVATION: PYTEST_K_INPUT overrides; else impacted → `git fetch --no-tags --depth=200
      origin devel:refs/remotes/origin/devel 2>/dev/null || true` then `K="$(sh
      scripts/impacted-tests.sh "$BASE_REF" "$TEST_DIR" || true)"`; empty K → log whole-marker
      fallback. The only deltas are `--test-dir` (tests/smoke vs tests/smoke/ui) and `--label`
      (log noun only).
   AMENDMENT (major — output contract): PRINT the resolved legs JSON to STDOUT ALWAYS (so ui can
   capture `LEGS="$(resolve-legs.sh legs ...)"` and PROJECT/build_matrix/tier-cross in the SAME
   step — you cannot read a value back out of $GITHUB_OUTPUT within the step that wrote it). Append
   ONLY scope= and pytest_k to $GITHUB_OUTPUT (smoke consumes ci_matrix cross-step; emit it there
   too for smoke, but the legs MUST also be on stdout). Document this in the script header.
B. Per-leg helper subcommands (the smoke-single.yml<->ui-tests.yml duplication). Each
   parameterizes the genuine per-workflow delta, DENY-BY-DEFAULT (secret-safe):
   - `image-ref`: env INPUT_REF/IMAGE_NAME/VERSION(TAG)/SMOKE_IMAGE_REPO/GITHUB_REPOSITORY_OWNER →
     REF (smoke-single.yml:258-272 == ui-tests.yml:399-413; differ only in the feeding env var).
   - `digest <ref>`: oras login + `oras resolve` with `oras manifest fetch --descriptor|jq -r
     .digest` fallback + `sha256:*` guard + `k=${DIGEST#sha256:}` (identical; reused for civm).
   - `exact-image-name <ref>`: the 4×-repeated `%@*`/`##*/`/`%%:*` strip.
   - `vm-identity [--civm-mac <MAC>]`: emit RESOLVED_VM_MAC/RESOLVED_VM_SMBIOS_UUID/RESOLVED_REDACT
     + the per-MAC `::add-mask::` loop. AMENDMENT (BLOCKING secret-leak): the civm CLIENT_MAC fold
     is smoke-ONLY (smoke-single.yml:498-525); ui has no civm. `--civm-mac` defaults EMPTY → ui can
     NEVER resolve/redact a civm MAC and smoke can NEVER drop civm redaction. Deny-by-default.
   - `scrub --root "<dirs>" [--keep <pat>]`: the `esc()` one-`-e`-per-BRE-metachar escaper +
     `redact.sed` (`s#…#REDACTED#gI`) + `sed -i -f` over vm*.log/text. AMENDMENT (BLOCKING
     data-loss): smoke scrubs `smoke-diag`; ui scrubs `smoke-diag test-results` AND keeps
     test-results/ui-screenshots (drops only console screen-*.png/.ppm for non-CE). Parameterize
     --root + --keep so the UI Playwright shots are NEVER deleted and test-results IS scrubbed.
     The esc() copy MUST stay in lock-step with helpers.py `_sed_escape_literal` (note the mirror).
   RESOLVED_REDACT empty (CE leg) → scrub is a strict no-op → CE diagnostics byte-identical.

--- scripts/lib/git-env-scrub.sh (NEW) + the chokepoint ---
A sourceable POSIX-sh lib (model: lib/run-id.sh; no side effects/set -e/traps). ONE function:
  pfb_scrub_git_env() { unset GIT_DIR GIT_INDEX_FILE GIT_WORK_TREE GIT_PREFIX GIT_OBJECT_DIRECTORY GIT_COMMON_DIR; }
A FUNCTION (not a bare unset at source time) is mandatory — it must run IN-CONTEXT in the caller's
shell; a subprocess can't unset the parent's vars. Production rewire (source then call, placed
BELOW each script's self-dir computation — AMENDMENT: the pinned `unset` lines are pre-self-dir, so
move the source+call next to where the script resolves its own dir / sources lib/run-id.sh, still
before any git use): build-leg.sh, smoke-on-box.sh, select-box.sh, and resolve-legs.sh all
`. "${DIR}/lib/git-env-scrub.sh"; pfb_scrub_git_env`.
Shellspec chokepoint: in tests/shell/spec_helper.sh source the lib once and expose
`scrub_git_env() { pfb_scrub_git_env; }`; replace the inline `unset GIT_*` at every current site
with a `scrub_git_env` call — in setup() for the 5 standard specs, and INSIDE each `( )` subshell
after its cd for read_version_matrix_test_spec.sh (the outlier — a top-level BeforeEach would not
reach the forks; the sourced function does).
META-ASSERTION (the "stops being a must-remember" gate — home it as a dedicated check, e.g.
scripts/git-env-scrub-guard.sh + spec, wired into the same lint slot; keep parity-guard.sh's scope
workflow-YAML-only): two mechanical clauses — (1) NO raw inline `unset GIT_DIR` anywhere under
tests/shell/ or scripts/ EXCEPT scripts/lib/git-env-scrub.sh (this is the clause that kills the
must-remember; `grep 'unset GIT_DIR'` catches both single-line and continuation forms); (2)
AMENDMENT — make a bare `git ` command the PRIMARY trigger: any spec whose text runs `git ` must
call `scrub_git_env` (the script-name allowlist — sparse-clone-ports.sh/build-leg.sh/… — is a
best-effort SECONDARY; note that invoked production scripts self-scrub, so the allowlist gap is
non-load-bearing).
