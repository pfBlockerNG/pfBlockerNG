EXECUTION MODEL (ADR §5.4 — the maintainer's resolved decision; build to THIS)
- A local run leases a box and runs the WHOLE smoke ON it via `select-box.sh -- <on-box cmd>`
  (lease-held form; default mode self-releases — do NOT use `eval "$(select-box.sh)"`).
- Repos live under /root on each box (e.g. /root/pfBlockerNG, the FreeBSD-ports tree under /root).
- THE RUN CHECKS OUT THE REF IT WANTS. The orchestrator passes a ref (commit/branch); the on-box
  bootstrap `git fetch` + checks it out, THEN re-execs the now-at-ref entrypoint, so the run uses
  that ref's own scripts/tests. The bootstrap one-liner (cd + fetch + checkout + exec) is
  ref-stable. FreeBSD-ports (under /root) is brought up-to-date on pfblockerng/use-github via
  sparse-clone-ports.sh (P1, idempotent).
- Images live in /root/images, pre-baked into the LXC clones but possibly stale: `oras pull` to
  REFRESH when the GHCR digest differs AND PULL when absent — do BOTH (digest-compare +
  tolerate-missing). Then point SMOKE_IMAGE_DIR/SMOKE_CLIENT_IMAGE_DIR at /root/images (or the
  per-kind subdirs; the harness needs exactly one *.qcow2 per dir — keep pfSense and civm in
  SEPARATE dirs, see the runbook).
- pkill qemu runs ON THE BOX (single-writer per lease) before boot — safe (never another box's
  VMs) AND reaping (clears this box's stale qemu, incl. the fixed lane port).
- CI is the degenerate case: the runner IS a pre-leased, already-checked-out box — it mints with
  --print-id (no lease, no on-box bootstrap) and calls run-smoke.sh DIRECTLY. So run-smoke.sh +
  the host prep are the shared surface; the lease + on-box bootstrap are the one legitimate
  local-only orchestration divergence.

DELIVERABLES (single commit)

--- scripts/run-smoke.sh (NEW) — the one canonical pytest argv ---
Emit ALWAYS, in order: <PYTHON> -m pytest <PATHS> -m <MARKER> --override-ini="addopts="
  --override-ini="timeout_func_only=true" --timeout=<TIMEOUT> --timeout-method=signal -v
  [-k <K>] [passthrough...]. This is the shared core all three copies already agree on.
Params + defaults (defaults reproduce the LOCAL no-arg run; CI passes the others):
  --paths P     default tests/smoke     (UI passes tests/smoke/ui)
  -m/--marker M default smoke           (CI smoke: smoke|repo; UI: ui_render|ui_e2e|ui_browser)
  --timeout N   default 30              (UI passes 300)
  -k EXPR       optional, rides as ONE arg (never word-split); omit when empty
  trailing passthrough after the known flags → forwarded to pytest verbatim
Fold in from local-smoke.sh: the `-m` guard (if a `-m` is in the passthrough, do NOT inject the
default `-m`; caller's marker wins — detect the bare `-m` form, same caveat as today); the PYTHON
resolution (PYTHON env override; else $REPO_ROOT/.venv/bin/python if executable; else python3).
AMENDMENT (bare-path parity): a caller-supplied positional PATH must REPLACE the default
`--paths tests/smoke`, NOT be appended — else `local-smoke.sh -m ui_render tests/smoke/ui` runs
the whole tree. (Translate a bare positional path into --paths, or suppress the default when a
passthrough path is present.)
AMENDMENT (PYTHON/CI parity): parity with CI's literal `python3` holds only because CI has no
repo-root .venv. Either gate the .venv preference off when GITHUB_ACTIONS is set, OR add a spec
asserting PYTHON falls to python3 when no .venv exists — and document the coupling.
run-smoke.sh is the pytest argv ONLY — no sysctl/pkill/oras/civm (those are the caller's/box's
job). Reads RUN_ID/PFB_DIAG_DIR/SMOKE_LANE from env only to let them reach pytest by inheritance.

--- scripts/smoke-on-box.sh (NEW) — the on-box entrypoint (local path only) ---
Runs ON the leased box (invoked by local-smoke.sh via `select-box.sh -- "sh .../smoke-on-box.sh
<args>"`). Single-writer on its box. Responsibilities, in order:
  1. Ref: cd the /root pfBlockerNG repo; `git fetch` + checkout the requested ref; re-exec the
     now-at-ref smoke-on-box.sh once (guard against infinite re-exec, e.g. a PFB_ONBOX_REEXEC=1
     sentinel). The cd+fetch+checkout+exec bootstrap is ref-stable.
  2. Ports: ensure the /root FreeBSD-ports tree is current on pfblockerng/use-github via
     sparse-clone-ports.sh (idempotent; it fetches + checks out the REF).
  3. Images: oras pull into /root/images — refresh when the remote GHCR digest differs from the
     local, pull when absent; tolerate a missing dir/file. Set SMOKE_IMAGE_DIR/
     SMOKE_CLIENT_IMAGE_DIR (separate dirs, one *.qcow2 each).
  4. Host prep ON the box: the stub-:53 relay + the ip_unprivileged_port_start sysctl (moved here
     from local-smoke.sh) + `pkill -9 -f qemu-system-x86_64` (lease-gated — this box only).
  5. Build: build-leg.sh → SMOKE_PKG (the branch .pkg for this ref).
  6. Run: run-smoke.sh with the lane/diag/marker/-k from the lease + caller.
  Use SMOKE_LANE/PFB_DIAG_DIR from the lease env. Quote everything; POSIX sh; shellcheck clean.

--- scripts/local-smoke.sh (REWIRE) — the orchestrator ---
KEEP: required-var validation; the -k/-m passthrough (now delegated to run-smoke.sh).
CHANGE: require PFB_BOXES; lease + drive the on-box entrypoint via `select-box.sh -- "<bootstrap
that cd /root/pfBlockerNG && git fetch && git checkout <REF> && exec sh scripts/smoke-on-box.sh
<args>>"` (lease-held; trap-release is automatic in the `-- <cmd>` form). The orchestrator decides
the REF (default: the current HEAD/branch under test) and forwards the smoke args + any SMOKE_*
overrides the box needs. MOVE the host prep (stub-:53, sysctl, civm pull, pkill) ONTO the box
(smoke-on-box.sh) — drop the unconditional local `pkill qemu`. Beware select-box.sh's `-- <cmd>`
space-joins argv over ssh (RESULTS/02_Results.txt): pass the on-box command as a single carefully
quoted `sh -c '...'` string; a `-k "a and not b"` must survive remote re-tokenisation as one arg.
If running the whole workload through one ssh command string proves too fragile, the fallback is a
lease-and-hold mode on select-box.sh (emit KEY=value, suppress auto-release) + a local --release
trap — but PREFER the `-- <cmd>` form (no change to the P2-frozen select-box.sh); if you must add
the mode, add its spec case and flag it in the handoff.
