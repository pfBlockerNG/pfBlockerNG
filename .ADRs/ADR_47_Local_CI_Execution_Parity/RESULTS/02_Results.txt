RED→GREEN EVIDENCE — reclaim-side double-grant (§7)
  two-concurrent-reclaimers (bad rmdir+mkdir):   winners=2  ← RED  (double grant proven)
  two-concurrent-reclaimers (rename-capture):    winners=1  ← GREEN (exactly one wins)
  Both assertions are reliable, not flaky:
    - bad: rm-rf idempotent + ignored mkdir status → both callers always return 0
    - good: rename(2) on the same source is atomic → at most one caller returns 0

RED→GREEN EVIDENCE — acquire-side double-grant (gate-review fix, second race)
  Defect: a lease was created in three separate ssh calls (mkdir → .created →
  owner). Between mkdir and .created the lock existed with neither file, and the
  reclaim rule treated a no-owner + no-.created lock as IMMEDIATELY reclaimable —
  so a concurrent reclaimer landing in that window stole a freshly-acquired,
  still-in-flight lease (two runs on one box).
  Fix part 1: _sb_claim_lock creates lock + .created + owner in ONE ssh call
              (mkdir && .created && owner.tmp && mv owner). Used by BOTH the
              acquire path and the reclaim "take fresh lock" tail. A lock is now
              never observable without its .created and owner.
  Fix part 2: reclaim rule — a no-owner lock is reclaimable ONLY when .created
              exists AND now-created >= grace. A missing .created (torn-acquire
              window) is NOT immediately reclaimable.
  New test cases:
    acquire-window (no .created):  RED  refused=no  (pre-fix stole the lock, rc=0)
                                   GREEN refused=yes (post-fix refuses, lock intact)
    acquire-window (young .created): GREEN refused=yes (guard; already correct pre-fix)
  The (no .created) case is the load-bearing red→green; verified RED against the
  pre-fix "no .created → immediate reclaim" code and GREEN after both fix parts.

RESIDUAL LIMITATION (documented, not a blocker)
  A true torn acquire — remote sh -c killed BETWEEN mkdir and the .created write
  inside the single ssh call — leaves a no-.created lock that is now never
  auto-reclaimed (needs manual `rm -rf` of the lock dir). The window is a few
  microseconds on the box (no network gap), so this is astronomically unlikely; a
  conservative TTL sweep for it is deferred per the gate review ("NEVER
  immediate-reclaim; no fixed sleep as a coordination primitive").

scripts/select-box.sh CONTRACT
  Acquire (default mode):
    - Requires PFB_BOXES (space-separated ssh targets)
    - Iterates pool in random order (avoids thundering herd); tries all once per retry
    - Atomic claim in ONE ssh call: mkdir (exclusive) && .created && owner.tmp && mv owner
      — a lock is never observable without its .created + owner; mkdir EEXIST short-circuits
      the chain → fall through to reclaim
    - Stale/crashed locks reclaimed via atomic rename-capture; the fresh lock is re-taken
      with the same atomic _sb_claim_lock call
    - owner file = "runid host epoch"; .created = epoch (drives the missing-owner grace check)
    - EXIT/INT/TERM trap releases the lease on exit
    - Emits eval-able KEY=value to stdout:
        RUN_ID=local-<boxtok>-<epoch>-<rand8hex>
        PFB_BOX=<ssh-target>
        PFB_RUN_DIR=<PFB_RUN_ROOT>/<RUN_ID>
        PFB_OUT_DIR=<PFB_RUN_DIR>/out
        PFB_DIAG_DIR=<PFB_RUN_DIR>/smoke-diag
        SMOKE_LANE=0
  --print-id:
    - Mints ci-<GITHUB_RUN_ID>-<GITHUB_RUN_ATTEMPT>-<LEG> to stdout; no lease, no ssh
  --release <RUN_ID>:
    - Finds box holding lease, verifies owner rid matches, removes lock dir; idempotent

SSH STUB SHAPE (for P4 reuse)
  PFB_SSH variable (default: "ssh -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null
    -o BatchMode=yes -o ConnectTimeout=10 -o LogLevel=ERROR") is word-split; the command is
  the whole string and the target + single-string command are appended as two positional args:
    ${PFB_SSH} <target> <cmd-string>
  The fake ssh in select_box_spec.sh:
    - Strips -o val, -i val, -p val, bare -flag pairs
    - Skips the target (first non-option arg)
    - exec sh -c "$remaining_arg"
  The lease dir (PFB_LEASE_DIR) is a local temp dir in tests; all remote commands
  reference paths that resolve locally, so no network is needed.

TOKEN NOTE

  (six digits: dots are non-alnum). Any test fixture that pre-creates lock dirs MUST use
  this computed token, not a hardcoded five-digit approximation. Spec uses box_tok() helper.
