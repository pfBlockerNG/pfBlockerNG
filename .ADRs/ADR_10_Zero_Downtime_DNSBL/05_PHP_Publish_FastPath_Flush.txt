WHY THIS PHASE EXISTS
The watcher (Phase 4) is inert until something flips the sentinel safely. Today a
DNSBL update calls pfb_reload_unbound -> pfb_stop_start_unbound -> TERM unbound
(the downtime). This phase replaces that, for DATA-ONLY updates in Python mode, with:
write-temp -> fsync -> atomic rename -> flip sentinel (generation advance). Config
changes and any failure still restart (fail-safe). It also fixes the allow->block
TTL-staleness the restart never addressed.
