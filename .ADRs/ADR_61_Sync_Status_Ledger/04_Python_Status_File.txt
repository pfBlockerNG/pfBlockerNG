WHY THIS PHASE EXISTS
pfb_unbound.py's parse/load failures only reach py_error.log today -- freetext, no
structured item/reason the widget can enumerate. This phase gives Python its OWN
structured status file (mirroring the pfb_py_reload/.applied marker convention: Python
writes it, PHP only ever reads it) so DNSBL parse-stage failures become as visible and
symmetric as everything else this ADR wires.
