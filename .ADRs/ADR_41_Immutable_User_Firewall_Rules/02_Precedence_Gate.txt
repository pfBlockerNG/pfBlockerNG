WHY THIS PHASE EXISTS
pass_order is a firewall-precedence (security) control. The immutable-user design (Phase 3) splices
the pfB rule block at ONE anchor per pass_order; that only works if pf precedence is per-interface
first-match (so inter-interface order is irrelevant and the anchor controls only same-interface
pfB-vs-user precedence). This MUST be verified on real pf, not assumed — a wrong anchor is a
block-bypass or a LAN lockout.
