BASE-OS STRATEGY (seed once, upgrade in place)
-------------------------------------------------------------------
SEED (once, archived, maintainer-driven OFF-RUNNER):
  - One clean manual pfSense CE install on Proxmox, hardware = the §4 profile,
    provisioned per §3, pfBlockerNG NOT baked, powered off.
  - Published with scripts/image-publish.sh <version> --proxmox root@pve.lan:
    qm config -> pvesm path -> qemu-img convert -c (zstd, zlib fallback) on the
    Proxmox host over SSH -> stream the compressed qcow2 back -> oras push.
    Reads a host disk over SSH, so it CANNOT run on a GH runner (no Proxmox/LAN).
  - build-image.yml `seed` mode therefore does NOT create a seed: it asserts the
    requested seed tag already exists (oras manifest fetch) and lets verify-image
    round-trip it. Creation stays the runbook step.

UPGRADE IN PLACE (every subsequent CE release, incl. major):
  - scripts/image-upgrade.sh: pull the prior tag (local oras) -> boot a writable
    copy under KVM -> run the upgrade over SSH -> wait for the new version ->
    power off cleanly -> compress -> push the new tag. Source tag UNTOUCHED.
  - In CI it runs LOCALLY on the runner (the runner is the KVM host: no
    --proxmox); the maintainer runs it from a workstation against Proxmox.
  - UPGRADE COMMAND / FLAGS:  yes | /usr/local/sbin/pfSense-upgrade -d
      -d = non-interactive/batch; `yes |` hedges any residual prompt.
      EXACT flags should be re-confirmed per CE release (ADR §6 flags this);
      completion is detected independently of the flags (see readiness).
  - READINESS / COMPLETION: poll /etc/version over SSH (NOT a fixed sleep) —
      record the pre-upgrade version, wait out the reboot, treat "version
      changed" as done. Hard timeout --upgrade-timeout (default 1800s). Target
      tag defaults to the upgraded box's reported version (-RELEASE stripped)
      unless --to is given.

SANITY GATE (publish-on-pass, fail closed):
  - The smoke round-trip itself. build-image.yml's verify-image job pulls the
    freshly published tag, installs the branch .pkg, runs
    tests/smoke/{boot_vm,wait_ready,roundtrip}.sh. Red round-trip -> workflow
    fails -> the bad image is not trusted. Manual re-seed is the fallback only
    when the gate fails. (ADR-09 automates the scheduled refresh + this gate
    across the version matrix.)

-------------------------------------------------------------------
WHERE SEED + SNAPSHOTS ARE ARCHIVED (GHCR)
-------------------------------------------------------------------
  Every CE version is its own immutable tag under the same GHCR repo; the seed
  and EVERY upgrade snapshot are retained (never overwritten — image-publish.sh
  and image-upgrade.sh both refuse to clobber an existing tag without --force).
  This keeps the upgrade chain recoverable (rebuild from the last clean base)
  and auditable. Package is PRIVATE to the org (ADR §3 redistribution risk).

-------------------------------------------------------------------
GHCR REF / TAG SCHEME + EXACT oras pull
-------------------------------------------------------------------
  Ref (no tag):  ghcr.io/<org>/pfsense-ce       (env SMOKE_IMAGE; default
                 ghcr.io/<owner>/pfsense-ce, owner from GITHUB_REPOSITORY_OWNER)
  Tag scheme:    :<PFSENSE_CE_VERSION>           e.g. :2.8.1
  Artifact-type: application/vnd.netgate.pfsense-ce.disk.v1
  Layer type:    application/vnd.qemu.qcow2
  Pull:          oras pull ghcr.io/<org>/pfsense-ce:2.8.1 -o ./image
  Pin by digest: oras manifest fetch --descriptor ghcr.io/<org>/pfsense-ce:2.8.1

  PFSENSE_CE_VERSION (validated slice): 2.8.1 (FreeBSD 15 base ABI).

WHAT IS BAKED (provisioning) — pfBlockerNG NOT baked
-------------------------------------------------------------------
  - Root SSH pubkey  : SMOKE_SSH_PUB_KEY -> root authorized_keys; root SSH on.
                       Private half = SMOKE_SSH_PRIV_KEY (the workflow secret).
  - Admin password   : SMOKE_ADMIN_PASSWORD (bcrypt) in config.xml. Not
                       exercised by the round-trip (SSH=key, WebUI=reachability).
  - WAN pass rules   : host -> 22 (SSH), 80 (WebUI HTTP), 53 (DNS). Mandatory —
                       single-NIC WAN is default-deny, no anti-lockout.
  - Unbound ACL      : access-control: 10.0.2.0/24 allow (SLIRP subnet; Unbound
                       REFUSEs WAN-side recursion by default).
  - Block-private/bogons: DISABLED if present (10.0.2.2 is RFC1918; not
                       auto-added on a single-interface install).
  - Unbound local-data control name(s)+answer:
                       default smoke-control.pfb.test -> 192.0.2.123
                       (workflow inputs local_data_name / local_data_ip).
                       Per-case control records are SSH-injected in Phase 4, not
                       baked.
  - DNS/SSH listen   : DNS Resolver in forwarding mode -> Cloudflare
                       1.1.1.1 / 1.0.0.1, DNSSEC off (fail-closed under egress
                       block). SSH = root key on :22. Do NOT forward to the
                       SLIRP 10.0.2.3.
  - WAN addressing   : DHCP (SLIRP lease 10.0.2.15, gw 10.0.2.2). NEVER a static
                       WAN IP (breaks SLIRP).
  - Serial console   : retained (post-mortem; readiness gauged by SSH).

-------------------------------------------------------------------
SOURCE-VM HARDWARE PROFILE (do NOT change without re-baking)
-------------------------------------------------------------------
  machine : pc (i440fx; Proxmox pc+pve0)
  cpu     : host (re-probed by FreeBSD; keeps AES-NI; not a fingerprint axis)
  smp/mem : 2 vCPU (sockets=1,cores=2) / 4096 MB
  disk    : VirtIO-SCSI (virtio-scsi-pci + scsi-hd); guest sees da0
  NIC     : single virtio-net-pci, MAC pinned BC:24:11:37:9C:AC (source VM's
            MAC; not sensitive, hardcoded in boot_vm.sh + image-upgrade.sh)
  smbios  : type=1,uuid=58fd7964-c40c-4f47-bf02-3fdad18f8b00
  DISK EXPORT: source VM disk exported wholesale —
    qemu-img convert -O qcow2 -c -o compression_type=zstd <zvol> out.qcow2
    (zstd, zlib fallback) on the Proxmox host (image-publish.sh). Published base
    is read-only + never booted directly; boot_vm.sh boots an ephemeral
    copy-on-write overlay (qemu-img create -b base -F qcow2).
  pfSense keys interface assignment to NIC type/MAC/count — change any and a
  clean boot drops to the console reassignment prompt. boot_vm.sh mirrors this
  exactly; image-upgrade.sh boots with the same MAC.

  Host<->guest exposure (SLIRP):
    127.0.0.1:2222/tcp -> 22 SSH ; 8080/tcp -> 80 WebUI ;
    5353/tcp+udp -> 53 DNS ; guest -> runner via 10.0.2.2.

RECONCILIATION WITH THE EVOLVED HARNESS
-------------------------------------------------------------------
  The harness already (Phase 1):
    - PULLS a clean pfSense CE qcow2 from PRIVATE GHCR by IMMUTABLE DIGEST
      (SMOKE_IMAGE_REF), cached in CI (actions/cache keyed on the ref).
    - Builds the branch-under-test into a real .pkg SEPARATELY on a FreeBSD 15
      VM-IMAGE (build-pkg.yml / scripts/build-pkg.sh), installed via pkg add
      (scripts/install-pkg.sh). pfBlockerNG is NOT baked into the image.
  Phase 2 fits this cleanly:
    - build-image.yml PRODUCES the version-tagged qcow2 that Phase 1 consumes;
      the seam is the same (oras + GHCR + the §4 hardware profile boot_vm.sh
      mirrors).
    - The verify-image job reuses the EXACT Phase-1 chain (build-pkg.yml +
      boot_vm.sh + wait_ready.sh + roundtrip.sh) — same .pkg-built-separately,
      pkg-add-install model — so the published image is proven the way it will
      actually be used.
    - smoke-spike.yml pins SMOKE_IMAGE_REF by DIGEST; build-image.yml publishes
      a :version TAG. After publishing, take the descriptor digest
      (oras manifest fetch --descriptor :<version>) and set SMOKE_IMAGE_REF to
      ...@sha256:<digest> for the per-PR smoke workflow — tag for humans,
      digest for the pinned pull.
