ACTION PLAN
1. Create src/usr/local/www/pfblockerng/pfblockerng_diagnostics.php:
   - Standard pfSense page bootstrap (require_once the package includes incl. the
     new pfblockerng_diagnostics.inc); render the tab bar with a new
     **Diagnostics** tab marked active.
   - One section/card "Export sanitized configuration" with brief help text
     (what it does, what is stripped) and a POST button.
   - POST handler: call the Phase 1 public function, then stream the string with
     Content-Type application/octet-stream + Content-Length + Content-Disposition
     attachment; filename="pfblockerng-config-sanitized.xml"; exit after.
   - Validate/guard the POST (CSRF token as other pages do); no user input feeds a
     filesystem path or shell — the engine reads a fixed /conf/config.xml.
2. Add the **Diagnostics** entry to the $tab_array of every page that renders the
   bar (grep for `display_top_tabs` / the General|IP|DNSBL|… array). Keep the
   ordering sensible (e.g. after Logs, before Sync) and identical across pages.
3. Add `pfblockerng/pfblockerng_diagnostics.php` to the
   `page-firewall-pfblockerng` match[] list in pfblockerng.priv.inc.
4. Tests under tests/smoke/ui/:
   - Tier A: GET the Diagnostics page -> 200, a page-specific marker present, body
     free of Fatal/Parse/Warning/Notice/Uncaught, no new on-box php_error.log

     and that the downloaded body contains a known NON-secret marker and NOT a
