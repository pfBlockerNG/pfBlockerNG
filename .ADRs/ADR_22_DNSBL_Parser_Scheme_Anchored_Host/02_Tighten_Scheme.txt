ACTION PLAN (ordered)

1. CHANGE `pfb_dnsbl_strip_scheme()` return type to `string|false`:

   RFC 3986 scheme grammar: `ALPHA *( ALPHA / DIGIT / "+" / "-" / "." )`
   Regex: `^[a-zA-Z][a-zA-Z0-9+\-.]*$`

   ```php
   function pfb_dnsbl_strip_scheme(string $line): string|false {
       $pos = strpos($line, '://');
       if ($pos === FALSE) {
           return $line;
       }
       $scheme = substr($line, 0, $pos);
       if (!preg_match('/^[a-zA-Z][a-zA-Z0-9+\-.]*$/', $scheme)) {
           return FALSE;
       }
       return substr($line, $pos + 3);
   }
   ```

   Notes:
   - `$pos = strpos($line, '://')` finds the first `://`.
   - `$scheme = substr($line, 0, $pos)` extracts the potential scheme text.
   - `preg_match('/^[a-zA-Z][a-zA-Z0-9+\-.]*$/', $scheme)` validates it:
     - `^[a-zA-Z]` — must start with a letter.
     - `[a-zA-Z0-9+\-.]*` — followed by letters, digits, `+`, `-`, `.`.
     - `$` — anchored end (no trailing junk).
   - If validation FAILS → return `FALSE`.
   - If validation PASSES → `substr($line, $pos + 3)` strips `scheme://` (same as today).
   - Note: `evil.com://junk` → scheme `evil.com` → matches the regex (`.` is valid!) →
     returns `junk`. This is intentional — `pfb_filter` downstream catches `junk` (no `.`).
     Behavior unchanged from current. Do NOT special-case this.
