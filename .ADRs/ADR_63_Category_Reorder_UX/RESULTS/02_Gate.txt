   idempotent; order-read is a no-op re-read). WATCH-ITEM for Phase 3/4: if the
   page's onAfterMove marks the form dirty / touches Save-button state, a no-op
   click would spuriously mark dirty — carried into Phase 3 notes.

   order preserved); firewall_rules.php was not required reading this phase.
   Pinned by 3 straddle tests + a 3-line comment. Fidelity vs core's exact UX is
   a Phase 3/4 / PR-review comparison point, not a Phase-2 blocker.
3. A GENUINE bug found + fixed — in the TEST FIXTURE glue, not the component:
   core delete_row() removes the row before a container-delegated gutter-refresh
   handler bubbles, so the handler is silently skipped. Root-caused via hypothesis
   ledger (H1 confirmed), fixed by binding directly per delete button + rebinding
   after add_row() (core's own convention). This is exactly the load-bearing
   pfSenseHelpers.js quirk Phase 2 exists to surface — carry-forward item 3 warns
   Phase 3/4's page-level wiring.
