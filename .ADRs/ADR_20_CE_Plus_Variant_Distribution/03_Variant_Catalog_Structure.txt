WHY THIS PHASE EXISTS
Splitting manifests per variant (Phase 2) is useless without a catalog that serves
each variant from a distinct URL path. This phase creates `ce/${ABI}/` and
`plus/${ABI}/` subtrees in the published catalog so that `pkg` fetching from
`pfblockerng.github.io/pkg/ce/FreeBSD:15:amd64/` gets only CE packages and
`.../plus/FreeBSD:16:amd64/` gets only Plus packages. The legacy `${ABI}/` path
(serving the CE build) is retained during the transition window.

Note: the matrix may contain N CE + M Plus entries simultaneously (N, M ≥ 1) during
version-transition windows. `build-repo-portable.py --variant CE` must handle ALL
active CE entries in one pass — e.g. during a CE 2.8.x → 2.9.x transition it emits
BOTH `ce/FreeBSD:15:amd64/` and `ce/FreeBSD:16:amd64/` subtrees. The catalog
generator loops over all matching `.pkg` files; each (channel, ABI) pair becomes a
distinct subtree automatically.
