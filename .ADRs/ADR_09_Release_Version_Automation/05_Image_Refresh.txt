ACTION PLAN (ordered)
1. REFRESH WORKFLOW: on a KVM runner, triggered by the version-tracker (Phase 4) for a
   new CE entry: `image-upgrade.sh --from <current-tag>` -> pfSense-upgrade (any bump,
   incl. major) -> produce the candidate image.
2. SANITY GATE (the publish guard — §2): boots; SSH answers; /etc/version == expected
   release; `pfctl -sr` loads; `install-from-repo.sh` installs pfBlockerNG and
   `pfblockerng.php update` exits 0; a `dig` of a baked control/blocked name returns the
   expected shape. ANY miss -> DO NOT publish; fail the job.
3. PUBLISH ON PASS ONLY: oras push the new tag only when the gate passes. Keep the old
   tag (don't overwrite). On fail, leave GHCR untouched and surface the failure.
4. FALLBACK NOTE: document that a gate failure -> manual seed (image-publish.sh) for that
   version is the fallback (not the default).
5. SELF-TEST (false-green guard): a deliberately-broken upgrade (or a forced bad
   /etc/version) MUST fail the gate and publish nothing.
