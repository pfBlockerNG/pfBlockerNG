ACTION PLAN (ordered)
1. Add an orchestrator: read pfb_feed_mgmt_mode; if off -> return (no scan). Else load catalog ->
   index (P1) -> read user rows -> plan (P2).
2. notify: emit file_notice + collect a structured change list for the UI; write NOTHING.
3. auto: apply each action -- rewrite_url (validate via PFB_FILTER_URL before writing),
   disable_discontinued (set state, never delete) -- take a write_config backup, then
   write_config once; emit a notification summarising what changed. Idempotent (re-run -> no
   actions).
4. Wire the orchestrator into the install/update entry point and a manual "Recheck Feeds"
   handler (UI hook lands in Phase 5; expose the callable now).
5. Tests (PHPUnit, assert before THEN after): off -> config byte-identical, no notice; notify
   -> config byte-identical + expected notice list; auto -> exactly the planned rows changed +
   backup taken + idempotent + custom feeds untouched + discontinued disabled not deleted.

CONSTRAINTS
- PHP tabs; PHP 8.3; no die()/exit().
- Any feed URL written MUST be validated (PFB_FILTER_URL) before the write (PFBL-01).
- NEVER delete a user row; discontinued -> disable. notify path MUST NOT call write_config.
- Do NOT add a cron; triggers are install/update + manual only.
