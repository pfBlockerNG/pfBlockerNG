WHY THIS PHASE EXISTS
Every later phase claims "net PRODUCTION (manifest-built) decisions are unchanged" and "the query
channel is decision-equal to a real query." Those claims need a falsification harness that exists
BEFORE any code moves. This phase builds it: a golden oracle of what the production (manifest-built)
matcher decides + would log today, plus a CHARACTERIZATION of how the legacy .txt fallback DIVERGES
from the manifest (it is NOT decision-equal -- with pfb_tld OFF the fallback is exact-only while the
manifest wildcards a registrable domain; ADR SS1.1). Phase 5 removes the fallback precisely because
it is a divergent, manifest-failure-only path -- so this oracle pins the manifest decisions, it does
NOT assert manifest==fallback.
