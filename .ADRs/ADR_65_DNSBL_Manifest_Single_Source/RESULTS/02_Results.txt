CARRY-FORWARD FOR PHASE 3
--------------------------------------------------------------------------------
- Request/reply file paths (chroot-relative, under /var/unbound):
  `pfb["pfb_py_query"]` = "pfb_py_query", `pfb["pfb_py_query_reply"]` =
  "pfb_py_query.reply".
- Request JSON schema: `{"id": <non-empty str>, "domain": <str>,
  "qtype": <str, ignored by the decision>}`.
- Reply JSON schema: `{"id", "blocked": bool, "b_type", "group", "b_eval",
  "feed", "p_type"}` -- `blocked=false` => the five attribution fields are
  all `""`.
- Miss-shaped-reply rule: an invalid/empty/non-string `domain` (with a valid
  `id`) gets the SAME miss shape as a genuine non-block (blocked=false, five
  empty strings) -- Phase 4 cannot distinguish "no verdict" from "clean" by
  this reply alone; if that distinction matters downstream, Phase 4 needs
  its own signal (this phase did not invent one -- not asked for).
  Phase 4 maps any blocked=false to "Unknown" per the brief.
  0 also: a domain not correlatable at all (missing/invalid `id`) gets NO
  reply file update whatsoever -- the PHP client must poll/timeout on its
  own, not assume a reply always appears.
- Settle semantics: an UNCHANGED request record (byte-for-byte, via Python
  dict equality) is answered exactly once; the PHP client MUST use a FRESH,
  unique `id` per query (a reused id with the same domain will not
  re-trigger a fresh answer if the record is otherwise identical).
- Perms contract: the request file's 0660 root:unbound is the PHP WRITER's
  duty to set at create time (Python never creates/touches the request
  file, confirmed by test_watcher_never_writes_or_deletes_the_request_file).
  The reply file arrives at mode 0640 (Python-owned, set by
  `_pfb_write_query_reply`).
- `_evaluate_cfg(snap)` (module-level) and `dnsbl_query_answer(domain,
  qtype)` are the two new public symbols Phase 3/4 may call directly if a
  future phase needs the SAME decision computation outside the file
  channel (e.g. an in-process caller) -- `dnsbl_query_answer` is the
  channel's own pure decision function and requires no qstate/Unbound
  context.
