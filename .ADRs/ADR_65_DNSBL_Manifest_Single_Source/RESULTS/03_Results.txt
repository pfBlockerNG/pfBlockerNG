CARRY-FORWARD FOR PHASE 4
--------------------------------------------------------------------------------
- Client signature: `pfb_dnsbl_query(string $domain, string $qtype = 'A',
  float $timeout_s = 5.0): ?array`, defined in
  src/usr/local/pkg/pfblockerng/pfblockerng_extra.inc.
- Return contract: NULL = no verdict obtained (invalid domain / write
  failure / encode failure / timeout / malformed-forever reply). An array
  with `blocked => FALSE` (five attribution keys `""`) = the matcher
  answered "not blocked". Phase 4 MUST map BOTH to "Unknown" -- the client
  gives no way (and is not asked) to distinguish "no verdict" from "clean".
- Verdict array keys (exactly six, `id` stripped): `blocked` (bool),
  `b_type`, `group`, `b_eval`, `feed`, `p_type` (all string).
- The 0660 chmod on the request file happens INSIDE this function,
  immediately after a successful `pfb_unbound_py_atomic_write_root()`
  publish -- Phase 4 does not need to (and must not) re-chmod it.
- Single-writer assumption: no flock -- this channel has one event-at-a-time
  caller per ADR SS2.1's transport row. If Phase 4 introduces concurrent
  callers of `pfb_dnsbl_query()` from the same process, that assumption
  needs revisiting (out of THIS phase's scope; flag it there if it arises).
- Fresh-id requirement: every call MUST use its own fresh `uniqid()` --
  already internal to the function, Phase 4 needs no awareness of it beyond
  "each call is independent."
- Default timeout 5.0s (matches the sibling
  `pfb_unbound_py_wait_control_applied()` default and the watcher's 2.0s
  poll-fallback cadence) -- Phase 4 may pass a different `$timeout_s` per
  its own latency budget (e.g. a webserver-hit attribution path may prefer
  a shorter timeout than the default).
- Vendor/ hygiene reminder for the next phase's implementer: after any
  `git rebase` onto a newer origin/devel, re-run `composer install` before
  trusting `composer phpstan`/`vendor/bin/phpunit` -- a stale `vendor/`
  from an earlier phase in the same worktree produces false gate failures
  (see the ENVIRONMENT NOTE above).
