WHY THIS PHASE EXISTS
`dnslog`/`dnsreplylog` (written by `pfb_unbound.py`, inside Unbound's chroot) use `make_timestamp()`,
which has no year and can return `""` on a real (if rare) `TypeError`-twice path. This is the last
remaining no-year format after Phases 2-3. But `dnslog` (`/var/log/pfblockerng/dnsbl.log`) has a
SECOND writer the ADR's §1.8 sweep found: `pfb_log_event()` (`pfblockerng.inc:13725`), used in
Unbound-native-mode DNSBL logging (as opposed to Python-mode), still on `date('M j H:i:s', time())`.
Both writers must convert together in this phase — fixing only `make_timestamp()` would leave
`dnsbl.log` mixed-format depending on which DNSBL mode wrote which line, which is worse than today's
uniformly-wrong state.
