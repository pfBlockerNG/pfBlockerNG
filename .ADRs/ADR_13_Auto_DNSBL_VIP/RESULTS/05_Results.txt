What changed (one commit on adr/13)

1. README.md
   Added a new "DNSBL sinkhole VIP" subsection (under the existing "DNSBL list
   build" section) documenting the "Create VIPs automatically" feature:
   - The checkbox (pfb_dnsvip_auto, default off) and what it does.
   - Address scheme: 10.10.10.53 / fd00::53, sweeping to the next free .53 on
     conflict (X = 0..15 bounded sweep).
   - Ownership marker: pfB_AUTO_VIP_v4 / pfB_AUTO_VIP_v6; only VIPs with that
     exact marker are ever managed or removed.
   - Enable/disable lifecycle: VIP created on enable, removed on disable
     (including uninstall); the pfb_dnsvip_auto setting and address choice
     persist across enable/disable cycles.
   - "Range fills up" edge: if auto is on and the range later fills, the
     checkbox renders disabled+unchecked with a warning; stored pfb_dnsvip_auto
     stays 'on' until the next save; the lifecycle manager no-ops safely.
   - IPv6 mandatory rule: auto mode provisions fd00::53; manual mode raises an
     input error / force-disables DNSBL if no v6 VIP is present.
   - HA / CARP: each node manages its own node-local lo0 VIP.
   - Manual workflow (when auto is off): unchanged — pre-create VIP at
     Firewall > Virtual IPs, select from dropdowns.
   - Link to ADR-13 for full design.

Smoke case decision
-------------------
DEFERRED to manual smoke. A functional auto-create smoke case (flip
pfb_dnsvip_auto on, assert pfB_AUTO_VIP_v4 appears, block sinks to it) would
require driving the live pfSense PHP/pf/Unbound stack — beyond what the local
pytest collection covers. Adding a skeleton that would be skipped locally
(missing SMOKE_PKG) but exercise the matrix in CI was considered; deferred
because:
  - The existing matrix already tests the DNSBL VIP block path (via
    ensure_dnsbl_vip, the manual-injection path).
  - Adding an auto-create matrix case risks touching the enable/disable
    lifecycle in ways that interact with the shared deployed_vm fixture.
  - The ADR §7 manual smoke covers this explicitly.
It is documented as the first item to add after on-box smoke confirms the
feature works end-to-end.
