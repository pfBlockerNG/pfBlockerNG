WHY THIS PHASE EXISTS
Issue #265 item 2, generalised to short-circuiting: put the cheap enum/bool guard first in a
boolean expression so an expensive test (preg, filesystem, lookup, function call) only runs when the
cheap guard already passed. Now that flags are enums/bools (Phases 4-5), the cheap guard is obvious.

ACTION PLAN
1. Reorder a boolean expression to put the cheap guard first ONLY when the reorder is provably
   side-effect-free: no operand performs an assignment, increments, or calls a function with side
   effects, and no later operand depends on an earlier one having run. If in doubt, LEAVE IT.
2. For any non-trivial reordered condition, add/extend a golden test asserting identical truth value
   AND identical side-effect behaviour across the relevant input classes (before- and after-state per
   the Test-coverage mandate).
3. Do not change enum adoption (done) or regex (Phase 7).

CONSTRAINTS
- Behaviour-preserving: truth values and side effects identical. §2.3.3 is absolute — never reorder a
  side-effecting or order-dependent condition.
- Tabs; PFBL-01 green; clean diff (only reordered conditions + their tests).
