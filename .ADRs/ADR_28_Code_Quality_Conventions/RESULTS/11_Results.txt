2. WHAT THE CASE PROVES
-----------------------

ADR-28 §2.2 hard-freeze: "config.xml stored values never change — every checkbox
'on'/''/… stays byte-identical across upgrade. No migration routine exists in this
package." A drift is a reject criterion (ADR §7).

The test exercises the round-trip contract for all four field categories:

  Field path                           Adapter        Value snapshotted
  ---------------------------------    -----------    ----------------
  dnsbl_lenient    (CFG_DNSBL)         PfbLenient     'on'
  dnsbl_vip_auto   (CFG_DNSBL)         PfbToggle      'on'
  pfb_dnsbl        (CFG_DNSBL)         PfbToggle      'on'
  pfb_idn          (CFG_DNSBL)         EXCLUDED       'all'  (canonical; 'on'
                                       (kept string)  normalises to 'all' on read;
                                                      write emits canonical 'all')

DNSBL runtime probe: domain uuid-a344db4286a4.com (from dnsbl_plain.txt fixture),
VIP block shape, drill @127.0.0.1 on-box. Asserted BEFORE and AFTER upgrade.


3. CASE STRUCTURE (Given-When-Then)
------------------------------------

Given:
  - Prior-release build (<V>_1) installed from our file:// repo above Netgate's.
  - Representative config written into config.xml:
      enable_cb='on', pfb_dnsbl='on', dnsbl_vip_auto='on',
      dnsbl_lenient='on', pfb_idn='all'.
  - BEFORE snapshot: all four fields read back; values match expectations.
  - DNSBL feed wired (write_local_feed + inject + reload("updatednsbl")).
  - BEFORE DNS probe: uuid-a344db4286a4.com -> NOERROR + VIP (DNSBL live).

When:
  - Repo rebuilt in-place with the branch build (<V>_9).
  - pkg_update() re-reads the catalog.
  - pkg_upgrade() installs the branch build over the lower build.
  - Sanity: installed version == <V>_9, no "Missing dependency".

Then:
  - AFTER snapshot read from config.xml.
  - _assert_snapshot_identical(before, after): every field byte-identical.
    (Failure lists ALL drifted fields, not just the first — exhaustive.)
  - reload("updatednsbl") on the upgraded build.
  - AFTER DNS probe: same domain -> NOERROR + VIP (runtime contract unchanged).

Finally (cleanup):
  - pkg_delete; rm -rf UPGRADE_REPO_DIR.

7. DESIGN NOTES
---------------

  - Uses repo_vm fixture (module-scoped, inherits smoke_vm) — exactly the same
    pattern as test_repo_install.py::test_pkg_upgrade_moves_to_our_newer_build.
  - _setup_dnsbl_feed() calls h.inject() with hsts=False to prevent the HSTS
    override from silently changing the VIP probe to NULL (belt-and-suspenders:
    uuid-a344db4286a4.com is not an HSTS-preload name, but this makes the test
    behaviour explicit).
  - config_get() reads each field via pfSsh.php/config_get_path with delimiters —
    the same oracle the PHP adapters use. Reading the stored string bypasses the
    adapters, so any drift in the stored value (migration artefact) is visible.
  - dnsbl_vip_auto is set in CFG_DNSBL (dnsbl-settings config/0) — confirmed
    from helpers.py set_dnsvip_auto() writing to CFG_DNSBL_SETTINGS.
  - ensure_dnsbl_vip() used for the VIP injection (pfb_dnsvip_auto defaults OFF;
    the harness injects the lo0 VIP alias directly so the probe returns the VIP).
  - The test does NOT call reload("update") before writing config — config is
    written via php_eval/write_config directly; the first reload (updatednsbl)
    picks up the full config state on the lower build.
