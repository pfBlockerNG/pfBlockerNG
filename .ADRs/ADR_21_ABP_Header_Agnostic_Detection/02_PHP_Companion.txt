ROLE
You are on the `adr/21-abp-header-agnostic-detection` branch performing Phase 2
of ADR-21. This phase modifies `pfblockerng.inc` at two call sites: the download
loop and the manifest builder. It completes the pipeline so that PHP correctly
feeds `||`/`@@||` lines from non-ABP feeds through to the Python `.raw` file
where Phase 1's detection can pick them up. One commit, push directly.

WHY THIS PHASE EXISTS
Phase 1 wired Python's `build()` to detect `||`/`@@||` lines in `.raw` files.
But for non-ABP feeds, PHP currently drops those lines at `pfb_filter()` domain
validation before they ever reach `.raw`. Without this PHP fix the pipeline is
only half-repaired: the Python routing in `build()` is correct but the lines
never arrive. This phase inserts two short guards — one in the download loop
(writes verbatim to `.txt`) and one in the manifest builder (writes verbatim to
`.raw`) — completing the end-to-end path.

ACTION PLAN (ordered)

1. DOWNLOAD LOOP change in `pfblockerng.inc`:

   Insertion point: after `$line = trim(trim($line), '.');` (~line 9754) and
   BEFORE the `if (empty(pfb_filter(…)))` block (~line 9757).

   Exact guard to insert:
   ```php
					// ABP-anchored line in a non-ABP feed: write verbatim to
					// allow Python per-line detection in build() (ADR-21).
					if (str_starts_with($line, '||') || str_starts_with($line, '@@||')) {
						@fwrite($dhandle, "{$line}\n");
						$domain_data = "{$line}\n";
						continue;
					}
   ```

   Notes:
   - Tabs for indent (PHP house style).
   - The `$domain_data` assignment matches the pattern used at line 9451 in the
     ABP path; it carries the last-written raw line for any post-loop consumer.
   - `@fwrite($dhandle, ...)` matches the pattern used by both the ABP path
     (line 9450) and the plain path (line 9777).
   - Do NOT touch the ABP-header path above this (`if ($easylist) { ... }`) or
     the IP-collection / IDN / dot-trim logic above the insertion point.
   - The DNSBL-IP coexistence check for ABP (`pfb_dnsbl_abp_extract_ip()` at
     lines 9418–9438) runs only inside `if ($easylist)` — it does NOT run here.
     A `||1.2.3.4^` line in a non-ABP feed passes this guard and reaches Python,
     which calls `parse_abp()` and returns `None` for IP anchors (ADR-06 no-leak
     contract). This is correct — no double-handling.
   - Similarly, `@@||1.2.3.4^` is not a valid domain anchor; `parse_abp()` skips
     it. No regression.

2. MANIFEST BUILDER change in `pfblockerng.inc`:

   Insertion point: inside the `while (($line = @fgets($in_h)) !== FALSE)` loop,
   AFTER the `if ($format === 'abp') { ... continue; }` block (~line 3595) and
   BEFORE the `$cols = explode(',', $line, 3)` line (~line 3600).

   The current 'plain' path is:
   ```php
				// 'plain': extract bare domains (col1) from the 6-col CSV ...
				$cols = explode(',', $line, 3);
				if (isset($cols[1]) && $cols[1] !== '') {
					@fwrite($raw_h, "{$cols[1]}\n");
				}
   ```

   After the fix:
   ```php
				// ABP-anchored verbatim line from non-ABP feed: pass through
				// to Python without CSV extraction (ADR-21).
				$rawline = rtrim($line, "\r\n");
				if (str_starts_with($rawline, '||') || str_starts_with($rawline, '@@||')) {
					@fwrite($raw_h, "{$rawline}\n");
					continue;
				}
				// 'plain': extract bare domains (col1) from the 6-col CSV ...
				$cols = explode(',', $line, 3);
				if (isset($cols[1]) && $cols[1] !== '') {
					@fwrite($raw_h, "{$cols[1]}\n");
				}
   ```

   Notes:
   - `rtrim($line, "\r\n")` strips the trailing newline before the `str_starts_with`
     check; the explicit `\n` added on write ensures a clean line. This matches the
     pattern used by the ABP path at line 3591–3593.
   - Do NOT touch the `if ($format === 'abp')` block above (lines 3587–3595).
   - Do NOT touch the manifest row builder (lines 3618–3625) — `format_hint` stays
     `'plain'`.
