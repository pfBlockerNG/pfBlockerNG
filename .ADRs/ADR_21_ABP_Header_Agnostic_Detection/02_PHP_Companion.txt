ROLE
You are on the `adr/21-abp-header-agnostic-detection` branch performing Phase 2
of ADR-21. This phase modifies `pfblockerng.inc` at three call sites: the
download loop guard, the manifest builder guard, and the header sniff. It
completes the pipeline so that PHP correctly feeds `||`/`@@||` lines from
non-ABP feeds through to the Python `.raw` file where Phase 1's detection can
pick them up, and broadens whole-feed ABP detection to the generic header
convention. One commit, push directly.

WHY THIS PHASE EXISTS
Phase 1 wired Python's `build()` to detect `||`/`@@||` lines in `.raw` files.
But for non-ABP feeds, PHP currently drops those lines at `pfb_filter()` domain
validation before they ever reach `.raw`. Without this PHP fix the pipeline is
only half-repaired: the Python routing in `build()` is correct but the lines
never arrive. This phase inserts two short guards — one in the download loop
(writes verbatim to `.txt`) and one in the manifest builder (writes verbatim to
`.raw`) — completing the end-to-end path.

1. DOWNLOAD LOOP change in `pfblockerng.inc`:

   Exact guard to insert:
   ```php
					// ABP-anchored line in a non-ABP feed: write verbatim to
					// allow Python per-line detection in build() (ADR-21).

						@fwrite($dhandle, "{$line}\n");

					}
   ```

   Notes:
   - Tabs for indent (PHP house style).
   - The `$domain_data` assignment matches the pattern used at line 9451 in the
     ABP path; it carries the last-written raw line for any post-loop consumer.
   - `@fwrite($dhandle, ...)` matches the pattern used by both the ABP path
     (line 9450) and the plain path (line 9777).
   - Do NOT touch the ABP-header path above this (`if ($easylist) { ... }`) or

     it. No regression.

3. BROADEN the header sniff (ADR §2.4 — replaces the dropped per-feed selector):

   Current code (`pfblockerng.inc:9507–9514`):
   ```php
   if (!$validate_header) {
   	if (strpos($line, '[Adblock Plus ') !== FALSE ||
   	    strpos($line, '[Adblock Plus]') !== FALSE ||
   	    strpos($line, '[uBlock Origin') !== FALSE ||
   	    strpos($line, '! Title: AdGuard') !== FALSE) {

   ```

   Replace the four magic-string tests with three generic prefix checks:
   ```php
   if (!$validate_header) {
   	// ADR-21: generic ABP header convention -- any '[Adblock'/'[uBlock'
   	// variant or any '! Title:' (not only AdGuard) flags the feed as
   	// whole-feed ABP. Safe: parse_abp() is a superset parser (keeps bare
   	// domains + hosts lines).
   	$hline = ltrim($line);
   	if (str_starts_with($hline, '[Adblock') ||
   	    str_starts_with($hline, '[uBlock') ||
   	    str_starts_with($hline, '! Title:')) {
   		$easylist = $validate_header = TRUE;
   		continue;
   	}
   ```

   Notes:
   - PREFIX check (`str_starts_with`), not `strpos(...) !== FALSE` — a '! Title:'
     token mid-line in a data line must not flip the feed. The `ltrim()` tolerates
     leading whitespace only.
   - The scan WINDOW is untouched: the `elseif (substr($line, 0, 1) === '!')` /
     `else { $validate_header = TRUE; }` arms below stay exactly as they are, so
     sniffing still stops at the first non-`!` non-header line.
   - The three prefixes cover all four legacy strings ('[Adblock Plus ' /
     '[Adblock Plus]' → '[Adblock'; '[uBlock Origin' → '[uBlock';
     '! Title: AdGuard' → '! Title:'). Pin all four legacy strings in tests.
   - No manifest-builder change: `format_hint` already follows `$easylist`
     ('format' => $easylist ? 'abp' : 'plain', ~line 9991).
   - NO new config key, NO UI field, NO per-feed selector — explicitly dropped
     (ADR §2.4).
   - TESTABILITY: extract the predicate into a small pure helper in
     `pfblockerng.inc` — `pfb_dnsbl_is_abp_header(string $line): bool` — and call
     it from the sniff. The download loop itself is not unit-testable
     off-appliance, but the helper is: add PHPUnit cases to `tests/php/` (loads
     the real pfblockerng.inc via the bootstrap shims) pinning: all FOUR legacy
     magic strings → TRUE; '! Title: HaGeZi ...' → TRUE; '[uBlock Origin' →
     TRUE; 'x.com' / '0.0.0.0 x.com' / '||x^' / '! plain comment' / a data line
     CONTAINING '! Title:' mid-line → FALSE.
