# Version-bump runbook (stubs, matrix, smoke images)

Scope: minimum-pfSense-version bump runbook. Load when: bumping min CE/Plus.

Steps for bumping minimum supported pfSense version and regenerating PHP stubs. **Rules** (when to regenerate, stub-over-baseline preference) live in `CLAUDE.md` → "Updating documentation"; this file = step-by-step.

## Regenerating `stubs/pfsense/`

Run when min CE bumped:

```sh
python scripts/update-pfsense-stubs.py            # newest public source
python scripts/update-pfsense-stubs.py --version X.Y.Z
```

Downloads pfSense source, emits one stub per module (`util.php`, `interfaces.php`, …) with cross-file dedup. Defaults to **2.7.2** (`STUB_SOURCE_VERSION`): public mirror frozen there (no `RELENG_2_8_0`), signatures stable 2.7→2.8, covers all PHPStan level 0 needs (symbol existence). Regenerate from real 2.8 checkout if/when available.

Also regenerate (or hand-edit) when pfBlockerNG calls new un-stubbed pfSense function — add to right `stubs/pfsense/` file manually. `globals.php` **always** hand-maintained (array shapes not auto-derivable); `logging.php` + `supplemental.php` likewise never regenerated (`supplemental.php` holds CE-2.8 functions absent from 2.7.2 source, e.g. `config_read_file`). PHPStan = gate; prefer real stub over `phpstan-baseline.neon` suppression.

## ADR-08 IDN homoglyph analyzer — no UCD table to regenerate

ADR-08 IDN homoglyph analyzer (inlined in `src/usr/local/pkg/pfblockerng/pfb_unbound.py`, backing **IDN Blocking → Confusable**) ships **no** Unicode data table: resolves each code point's script from **stdlib `unicodedata.name()`** leading token (`LATIN…`→Latin, `CJK…`→Han, …), so nothing regenerates on UCD bump. Reads runtime stdlib UCD (Python 3.11 ships 14.0.0, 3.12/3.13 15.1.0, 3.14 16.0.0); name tokens stable across those for scripts in scope. Corpus/oracle GOLDEN (`tests/fixtures/adr08_*`) pinned to UCD 15.1.0 and `tests/test_adr08_*` proves analyzer agrees with it across versions. Lives **in `pfb_unbound.py`** (not sibling module) so it rides existing chroot copy + `pkg-plist` entry — no new shipped file, no extra deploy wiring.

## When the minimum pfSense version changes

1. **Update the supported-version matrix** — edit `supported-versions.json` on **`ci-metadata` orphan branch** via PR against `ci-metadata`. Single source of truth for supported versions + their `(freebsd_version, php_version)` build pair; workflows read it at runtime via `scripts/read-version-matrix.sh` + `.github/actions/read-version-matrix/` (see `scripts/README.md`). **No `arch` field** (issue #1806 — every port `NO_ARCH`); if new entry shares `freebsd_major` with existing one, its `php_version`/`py_flavor` MUST match (BUILD matrix dedupes by major, hard-errors on mismatch) and add `extra_pkgs` only for dependency this edition's own upstream repo doesn't carry (e.g. CE's `textproc/py-charset-normalizer`). Build + CI: every `ci: true` entry — **CE and Plus** (ADR-24) — gets `.pkg` builds **and** live-VM smoke. Plus runs from **PRIVATE, licensed** GHCR image (`pfsense-plus`); its VM identity (NIC MAC + SMBIOS uuid, keying Netgate Device ID) comes from `SMOKE_PLUS_MAC`/`SMOKE_PLUS_SMBIOS_UUID` (+ optional `SMOKE_PLUS_NDI`) secrets — **never** matrix — and harness redacts it from diagnostics. Adding entry + letting **version-tracker** (`version-tracker.yml`) run (or dispatching it) triggers `build-pkg-linux.yml`, `image-refresh.yml` (CE **and** Plus — see step 2), `smoke.yml` automatically — **no workflow YAML edit needed**. When bump **drops old minimum**, inspect its last released `.pkg` before choosing EOL state. In same `ci-metadata` PR, set `role` to `"route-only"` (ADR-27 Part 2) only when last tag has post-#1806 wildcard-ABI asset. Version then leaves build/CI/smoke (`--print-build`/`--print-ci`/`--print-test` exclude it) while its frozen release catalog stays served. Pre-#1806 tag has only concrete-ABI assets, unservable route-only: drop its matrix entry, producing clean 404, and do not repackage frozen tag at EOL. Whether post-#1806 family whose last `.pkg` declares dependencies represented by `extra_pkgs` needs those packages folded into its frozen catalog = open question in [issue #1828](https://github.com/pfBlockerNG/pfBlockerNG/issues/1828). Semantics + lifecycle table: `scripts/README.md`.
2. **Refresh the smoke images** (ADR-04 + ADR-09) — `image-refresh.yml` (`Upgrade pfSense smoke
   images`) accepts two planning modes for **CE and Plus**. The daily or manually dispatched `version-tracker.yml` reconcile job boots the newest published image per channel, probes `/etc/version`, `pfSense-repoc -p`, and `pfSense-upgrade -c`, then dispatches each planned `republish` or `publish_new` action as one fully specified, validated `direct_leg`. For a manual operator republish, `self_refresh=true` selects the newest eligible amd64 entry per channel (after any `pfsense_version` filter) and emits `from == target`, `--force` legs. `direct_leg` takes precedence over `self_refresh`; a bare dispatch plans no legs. Same-version legs run `scripts/image-upgrade.sh --type ce|plus --upgrade-pkgs`; cross-version legs omit `--upgrade-pkgs` so `pfSense-upgrade` owns the OS transition. A leg passes `--branch <id>` when the planner selects a **pre-release / development** branch — stored in pfSense's `system/pkg_repo_conf_path` and applied via `pkg_switch_repo()`. The script pulls the current GHCR tag, conditionally upgrades baked dependencies, runs `pfSense-upgrade`, then applies an **alive health gate** (≤300 s for webConfigurator HTTP or a live `pfctl` ruleset) and publishes only when healthy — fail-closed. GA/patches within a floating tag (2.8.0→2.8.1, both tag `2.8`) self-replace that tag (`--force`); a new Major.Minor publishes a new tag. The **Plus** leg takes license/NDI identity from `SMOKE_PLUS_MAC`/`SMOKE_PLUS_SMBIOS_UUID` secrets and refuses to boot on mismatch. Non-blocking post-publish smoke runs per variant on a discarded overlay (informational; authoritative validation = fan-out, step 3; Plus post-smoke skips cleanly if Plus secrets are absent). Manual seed via `scripts/image-publish.sh` remains the fallback when the gate fails (and for the initial Plus image seed). See `legacy/ADRs/ADR_04_VM_Smoke_Tests/IMAGE_RUNBOOK.md`. (ADR-09 supersedes ADR-04 §2's "re-baseline on a major jump": `image-refresh.yml` handles all jumps via upgrade-in-place; a fresh re-seed is triggered only by gate failure. Reconciling ADR-04 §2 text = tracked follow-up.)
3. **Run the smoke fan-out** — dispatch `smoke.yml` (no inputs; reads CI matrix). Runs ADR-04 suite against **all** `ci: true` entries — **CE and Plus** (ADR-24) — in parallel (`fail-fast: false`); `all-smoke-passed` AND-gate fails if **any** leg fails. version-tracker triggers it daily; dispatch manually to verify new image.
4. **Re-diff the portable `.pkg` against a real `make package` build** (manual; also do whenever FreeBSD-ports fork's `Mk/` framework moves). `build-pkg-portable.py` = sole `.pkg` builder — its `make package` fidelity validated by one-time field-by-field diff (FreeBSD `build-pkg.yml` oracle retired in `68992f4c`), and that validation rots as libpkg and ports framework evolve. On FreeBSD box (dev pfSense VM works): check out same port + source commit, run `make package`, then diff two archives member-by-member (`tar -tvf`; extract both `+MANIFEST`s, compare field-by-field after `json`/UCL normalization). Expected benign divergences — file `sum` type (`1$sha256` vs modern `2$blake2b`), tar flavor/uid, mtime, best-effort dep versions — enumerated in `docs/build-pkg-portable.md` ("Fidelity vs `make package`"); anything else = builder bug to fix before bump lands.
5. **Sweep the version-literal checker + seeded escapes** (issue #940) — as soon as matrix moves, `test.yml`'s tripwire step (`scripts/check_version_literals.py --verify-matrix`) fails if new version falls outside checker's **windowed CE/Plus numeric shapes** (`_TOKEN_ALTERNATIVES`); widen window and update checker's tests. Then sweep every `version-literal-ok` escape (`git grep -n version-literal-ok -- src scripts .github`): escaped `workflow_dispatch` fallback defaults and dev-tooling defaults still name OLD version and need bumping by hand — escape comment exempts them from gate, so nothing else will remind you.
