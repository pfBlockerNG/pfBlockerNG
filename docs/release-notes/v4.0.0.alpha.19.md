## Features

- **IPv6 and any-mask Suppression.** Suppression now accepts IPv6 prefixes and any CIDR mask, not just a narrow set of IPv4 masks. You can un-suppress an IPv6 or arbitrary-mask entry directly from the Alerts page and the widget, and the kill-states pass spares suppressed prefixes ([#422](https://github.com/pfBlockerNG/pfBlockerNG/issues/422), [#760](https://github.com/pfBlockerNG/pfBlockerNG/issues/760)).
- **Opt-in plain-text feed sanity scan.** Text-based feeds can be scanned for malformed or junk content before import, so a corrupt download is caught instead of being loaded as blocklist data ([#829](https://github.com/pfBlockerNG/pfBlockerNG/issues/829)).

## Improvements

- **Feed download validation now explains itself.** When entries or a whole feed are rejected during download validation, the reason is logged per entry and per stage, so a feed that imports fewer entries than expected is diagnosable from the log ([#807](https://github.com/pfBlockerNG/pfBlockerNG/issues/807), [#811](https://github.com/pfBlockerNG/pfBlockerNG/issues/811)).
- **Archive feeds fail safe.** A failed ZIP or archive extraction now surfaces an error instead of silently importing an empty feed, and extraction is hardened against hostile archive member names ([#808](https://github.com/pfBlockerNG/pfBlockerNG/issues/808), [#819](https://github.com/pfBlockerNG/pfBlockerNG/issues/819)).
- **Suppression drops reserved address space.** Documentation, multicast, NAT64 and CGN ranges are excluded from suppression, and an IPv6 CIDR floor prevents over-broad IPv6 suppressions ([#760](https://github.com/pfBlockerNG/pfBlockerNG/issues/760)).
- **Faster Alerts page on large tables.** Table-membership lookups on the Alerts page are batched behind a prefetch pass instead of being resolved one row at a time ([#809](https://github.com/pfBlockerNG/pfBlockerNG/issues/809)).
- **Scheduled log maintenance runs from the cron tick**, with the next run anchored so the schedule no longer drifts over time ([#573](https://github.com/pfBlockerNG/pfBlockerNG/issues/573)).
- **Delegated operator access.** Operators with the appropriate privilege can now reach the query-string report pages and refresh the dashboard widget ([#707](https://github.com/pfBlockerNG/pfBlockerNG/issues/707)).
- The IP alias-table **apply path (incremental delta vs full replace) is now logged**, so the reload strategy for each table is observable ([#722](https://github.com/pfBlockerNG/pfBlockerNG/issues/722)).
- The **Software tab is hidden** from users who lack the Package Manager privilege.

## Bug Fixes

- **Download and logging hardening sweep** ([#713](https://github.com/pfBlockerNG/pfBlockerNG/issues/713), [#714](https://github.com/pfBlockerNG/pfBlockerNG/issues/714)): fixed a filterlog daemon crash when `filter.log` is absent, honored the log-truncation "No Limit" setting, corrected the IPv6 filterlog port index, recovered a corrupt SQLite state DB instead of failing, stopped a truncated archive being masked by the `tar`/`zstd` pipeline, kept the ASN cache expiring when reporting is off, and fixed a widget status-icon freeze and null-deref on an unknown hash.
- **ET category over-block.** Emerging Threats categories no longer over-block from substring matching ([#713](https://github.com/pfBlockerNG/pfBlockerNG/issues/713)).
- **DNSBL matching fixes**: correct wire-format dname decoding ([#717](https://github.com/pfBlockerNG/pfBlockerNG/issues/717)); keep ABP `||host^` wildcard zones effective at any anchor depth ([#718](https://github.com/pfBlockerNG/pfBlockerNG/issues/718)); accept underscore labels and lowercase the TLD label for TLD-Allow and HSTS comparisons ([#720](https://github.com/pfBlockerNG/pfBlockerNG/issues/720), [#723](https://github.com/pfBlockerNG/pfBlockerNG/issues/723)); and read the correct domain label when checking a CNAME against TLD-Allow/HSTS ([#706](https://github.com/pfBlockerNG/pfBlockerNG/issues/706)).
- **Report TTL 0 as `0`** instead of `Unk` in the DNS-reply log ([#723](https://github.com/pfBlockerNG/pfBlockerNG/issues/723)).
- **Reject RFC 4632-invalid IPv4 masks** instead of silently substring-rewriting them ([#719](https://github.com/pfBlockerNG/pfBlockerNG/issues/719)).
- **Local IP collection** now splits alias addresses that hold multiple IPs and resolves nested alias references, guarding against non-string entries ([#782](https://github.com/pfBlockerNG/pfBlockerNG/issues/782), [#784](https://github.com/pfBlockerNG/pfBlockerNG/issues/784)).
- **Alias rename** now follows through into the DNSBL and GeoIP configuration sections ([#708](https://github.com/pfBlockerNG/pfBlockerNG/issues/708)).
- **Yandex DoH.** Replaced a malformed Yandex DNS-over-HTTPS entry with the real Yandex endpoints ([#740](https://github.com/pfBlockerNG/pfBlockerNG/issues/740)).
- The **pending-changes marker is cleared on package uninstall** ([#738](https://github.com/pfBlockerNG/pfBlockerNG/issues/738)).
