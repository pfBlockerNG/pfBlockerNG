### Bug Fixes

- Upgrading or reinstalling the package no longer fails during post-install configuration: the package's own resync path could reach the IP-suppression pass with an uninitialized state flag, crashing `sync_package_pfblockerng()` with a `TypeError` and leaving the install half-configured ([#1840](https://github.com/pfBlockerNG/pfBlockerNG/issues/1840)). The flag is now seeded unconditionally for every sync pass. Anyone whose 4.0.0.alpha.22 upgrade errored in POST-INSTALL should reinstall or upgrade to this build.
- Suppressing or unlocking an alert whose alias table is not currently loaded into the firewall's ruleset (a fresh install where the alias is not yet referenced by a rule) now reports that the address is not currently blocked, instead of reporting a failure and logging an internal error ([#1852](https://github.com/pfBlockerNG/pfBlockerNG/issues/1852)). Genuine `pfctl` failures are still reported, now including the underlying diagnostic.
