<!-- SUMMARY: Log handling fixes -->

## Improvements

- **Hook stdout now reaches the persistent log.** Both normal-pass update hooks and
  package lifecycle hooks (install/upgrade/uninstall) now stream their output into
  `pfblockerng.log`, not just the live per-run tail on the Update page
  ([#973](https://github.com/pfBlockerNG/pfBlockerNG/issues/973),
  [#988](https://github.com/pfBlockerNG/pfBlockerNG/issues/988)).
- **pfctl table-apply failures are now also logged to error.log**, not just the main
  log ([#980](https://github.com/pfBlockerNG/pfBlockerNG/issues/980)).
- **A GUI notice now appears when a misconfigured DNSBL VIP force-disables DNSBL**
  ([#331](https://github.com/pfBlockerNG/pfBlockerNG/issues/331)).
- The Logs tab's file viewer is now marked read-only, matching the Update page.

## Bug Fixes

- DNSBL and generic IP-list feed parsing and logging fixes: parse-error reporting no
  longer spams the log with one line per bad entry, no longer falsely flags valid
  addresses in feeds that mix IPv4 and IPv6, correctly skips comment-style lines some
  feeds embed mid-body, and alias-update log lines are clearer.
- The Logs tab no longer double-escapes (or wrongly escapes) log content — raw log
  text now displays correctly instead of as literal HTML entities.
- The Logs tab's download/clear and file-viewer AJAX handlers no longer reuse an HTTP
  success code for a rejected or failed request.
