This is an incremental alpha in the 4.0.0 series, adding several new controls and a
batch of fixes on top of `v4.0.0.alpha.3`. It remains test-only: keep a config
backup and do not run it on a production firewall. Feedback and bug reports are
welcome.

## Features

- **DNS redirect.** A new option on the DNSBL settings page can redirect clients'
  outbound DNS to the firewall's resolver, with server-side validation of the
  settings.
- **DoT/DoQ blocking.** A new control blocks DNS over TLS and DNS over QUIC, so
  clients cannot bypass DNSBL with encrypted DNS.
- **Syslog export of pfBlockerNG events.** IP and DNSBL block events can be sent to
  syslog under a dedicated log facility and file, with a live on/off toggle in Log
  Settings.
- **Opt out of DNSBL NAT.** A new toggle skips generation of the DNSBL NAT rules for
  setups that handle that redirection themselves
  ([#381](https://github.com/pfBlockerNG/pfBlockerNG/issues/381)).
- **Uninstall from the GUI.** pfBlockerNG can now be uninstalled from its own
  Software page, gated behind the Package Manager privilege
  ([#485](https://github.com/pfBlockerNG/pfBlockerNG/issues/485)).

## Improvements

- **Fewer unnecessary reloads.** DNSBL no longer reloads (or restarts Unbound) when
  the rebuilt blocklist is unchanged, and a change to the shipped HSTS list now
  triggers a zero-downtime reload instead of a full restart
  ([#520](https://github.com/pfBlockerNG/pfBlockerNG/issues/520)).
- **DNSBL survives a reboot on RAM-disk installs.** The DNSBL cache is kept separate
  from the IP alias tables and restored at boot, so domain blocking is no longer lost
  after a reboot on systems that use a RAM disk for `/var`
  ([#468](https://github.com/pfBlockerNG/pfBlockerNG/issues/468)).
- **Cleaner uninstall.** Uninstalling now fully removes pfBlockerNG's live objects and
  configuration, with an option to keep settings
  ([#484](https://github.com/pfBlockerNG/pfBlockerNG/issues/484)).
- **More accurate update hooks.** A re-block forced by unlocking an entry is now
  reported to post-update hooks as a change
  ([#517](https://github.com/pfBlockerNG/pfBlockerNG/issues/517),
  [#519](https://github.com/pfBlockerNG/pfBlockerNG/issues/519)).
- **Hardened feed scripts.** Per-feed pre/post and hook scripts now run contained to
  their directory and under a timeout.
- **Log Settings layout** regrouped into aligned per-log rows
  ([#489](https://github.com/pfBlockerNG/pfBlockerNG/issues/489)).

## Bug Fixes

- **An IP rule on an interface no longer drops that interface's other firewall rules
  on reload.** A managed-interface rule with no rule order set could remove existing
  pass rules — for example the default LAN allow — from the configuration on the next
  update, cutting the interface off
  ([#532](https://github.com/pfBlockerNG/pfBlockerNG/issues/532)).
- **No more spurious Unbound restart on upgrade**, caused by an incorrect internal
  state reset.
- **Duplicate firewall-rule trackers** are now de-duplicated against unrelated filter
  rules ([#482](https://github.com/pfBlockerNG/pfBlockerNG/issues/482)).
- **Correct change detection after file updates**, by reading fresh modification times
  rather than cached ones
  ([#536](https://github.com/pfBlockerNG/pfBlockerNG/issues/536)).
- **Malformed interface entries** are now skipped when collecting local IP addresses
  instead of raising an error
  ([#461](https://github.com/pfBlockerNG/pfBlockerNG/issues/461)).
