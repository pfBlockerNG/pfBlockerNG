### Features

- **Self-hosted dependency packages** (#1806): pfSense CE's package repository does not carry `py311-charset-normalizer` (the feed-encoding detector added in 4.0.0.alpha.21), so the pfBlockerNG package repository now builds and serves it itself. The dependency is built straight from its FreeBSD-ports definition (checksum-pinned source, pinned build backend) and installs like any other `pkg` dependency; which editions need which extra packages is driven by a new `extra_pkgs` field in the supported-version matrix.
- **NO_ARCH packages and arch-less catalogs** (#1806): all pfBlockerNG packages are now architecture-independent (`FreeBSD:<major>:*`) — one package per FreeBSD major serves every CPU architecture, including future ARM (aarch64) appliances, with no extra builds. Repository catalogs drop the architecture path segment (`release/<edition>-<version>/`), and release builds collapse to one per FreeBSD major.
- **Post-upgrade dependency reconciliation** (#1806): after a pfSense image upgrade, the runtime dependency set is verified and repaired against the new version's requirements (including Python-flavor flips, e.g. `py311` → `py312`), and packages the new version no longer needs are removed. A verification failure blocks the image from publishing.
- **Daily image-reconcile loop** (#1823): the pfSense version tracker was replaced with a reconcile loop that treats a booted VM as the source of truth — probing beta availability, detecting patch/GA drift via image annotations, and opening matrix-update PRs automatically.

### Improvements

- Smoke/UI test legs install extra dependencies the way a real user would (`pkg add` before the package under test) instead of baking them into the CE image, so the test images stay faithful to a stock pfSense install (#1806).
- Release verification suites receive the same dependency packages as regular CI legs, and the release healthcheck accounts for dependency assets attached to the GitHub Release (#1806).
- Guest fact-gathering commands run under `/bin/sh` explicitly, avoiding pfSense's `tcsh` root-shell quirks (#1823).
- TLD Allow lists, the HSTS preload list, and the Public Suffix List were refreshed from their upstream sources.

### Bug Fixes

- The version matrix reader no longer leaks stray `arch`/`ci` keys into merged build rows, and mismatched PHP/Python versions across entries sharing a FreeBSD major are a hard error instead of a silent merge (#1806).
- A dropped extra dependency can never remove a package the new pfSense version still needs (name-collision guard in the post-upgrade reconcile) (#1806).
- The dependency builder tolerates minimal build hosts: it bootstraps `pip` via `venv` when the system Python has none, and keeps its output contract clean so harness captures can't pick up build chatter (#1806).
