WHY THIS PHASE EXISTS
`parse_abp()` is already the complete DNS-only ABP parser with full `@@`,
`$important`, `$badfilter`, and regex support. The only missing piece is the
routing: in `build()` the non-ABP feed loop calls `parse(fmt, raw_line)` for
every line, which silently drops `||domain^` entries (they look like invalid
domains to the plain parser). This phase adds a single `startswith` guard before
`parse()` that routes any `||` / `@@||` line to `parse_abp()` instead, with
identical provenance/feed/group/log plumbing as the existing ABP feed path.
Tests prove all §4 acceptance requirements, with before-state assertions.

ACTION PLAN (ordered)

1. UNDERSTAND the exact insertion point in `build()`:

   Current structure (non-ABP loop, ~lines 3899–3917):
   ```python
   for raw_line in line_reader(feed_row["raw"]):
       entry = parse(fmt, raw_line)
       if entry is None:
           continue
       domain = normalise(entry.value)
       if domain is None:
           continue
       if entry.kind != DNSBL_KIND_BLOCK:
           continue
       ...  # band/payload, data_db or zone_db
   ```

   New structure — insert before `parse()`:
   ```python
   for raw_line in line_reader(feed_row["raw"]):
       stripped = raw_line.strip()
       if stripped.startswith("||") or stripped.startswith("@@||"):
           rule = parse_abp(stripped, provenance=provenance, feed=feed,
                            group=group, log=log_flag)
           if rule is not None:
               abp_rules.append(rule)
           continue
       entry = parse(fmt, raw_line)
       ...  # unchanged
   ```

   Critical: `abp_rules` is already declared before the feed loop at ~line 3870;
   it is the list that feeds `reconcile()` in Stage-B. Confirm `abp_rules` is in
   scope and used correctly.

      Scenario: `||domain.com^` in a non-ABP feed produces a DNSBL block.
      Background: `format_hint='plain'` feed with lines: `domain.com`, `||block-me.com^`.
      Given: `block-me.com` is NOT in the result before the new routing.
        (Assert the BEFORE: build a feed with only `domain.com` → `block-me.com` absent.)
      When: feed contains `||block-me.com^`.
      Then: `block-me.com` is in `data_db` or `zone_db` with `band=PRIO_FEED_BLOCK`.
      Also assert: `domain.com` is still blocked (no regression to plain path).

   b. `test_plain_feed_abp_anchor_allow_overrides_plain_block`:
      Scenario: `@@||allow.com^` in a non-ABP feed overrides a plain block in the
      same feed.
      Background: feed with `allow.com` (plain block) and `@@||allow.com^` (ABP allow).
      Given: `allow.com` IS blocked when only the plain line is present.
        (Assert BEFORE: plain-only feed → `allow.com` in block DB.)
      When: `@@||allow.com^` is added to the same feed.
      Then: `allow.com` is NOT in the block DB (allow overrides block).

   c. `test_plain_feed_important_modifier`:
      Scenario: `||domain.com^$important` sets `important=True` in the result.
      Background: `format_hint='plain'` feed with `||domain.com^$important`.
      Given: without `$important`, an `||domain.com^` entry has `important=False`.
      When: `$important` is present.
      Then: the reconciled payload for `domain.com` has `"important": True`.

   d. `test_plain_feed_badfilter_cancels_block`:
      Scenario: `||domain.com^$badfilter` cancels a block for `domain.com`.
      Background: feed with `domain.com` (plain) and `||domain.com^$badfilter`.
      Given: `domain.com` is blocked when only the plain entry is present.
      When: `||domain.com^$badfilter` is also present.
      Then: `domain.com` is NOT in `data_db` or `zone_db`.

   e. `test_plain_path_unchanged_no_abp_lines`:
      Scenario: a plain feed with no `||` lines is processed exactly as before.
      Background: feed with `example.com`, `subdomain.example.com`.
      Then: both are in the block DB; no exceptions; no entries in `white_db` / `abp_rules`.

   f. `test_abp_header_feed_unchanged`:
      Scenario: ABP-header feed (`format_hint='abp'`) is unaffected by this change.
      Background: feed with `||block.com^`, `@@||allow.com^`, `plain.com`.
      Then: `block.com` is blocked; `allow.com` is allowed; `plain.com` is blocked
      (all three are handled by `parse_abp()`'s existing plain-bare-domain logic).
      Regression guard: this result must be IDENTICAL before and after Phase 1's
      `build()` change — the new `startswith` guard must NOT run for `fmt == "abp"`.

   g. `test_wildcard_and_path_anchors_skipped`:
      Scenario: `||domain.com/path^` and `||*.com^` in a plain feed → skipped.
      Then: neither domain appears in the block DB (parse_abp returns None for `/`
      and `*`).

   h. `test_page_context_option_skipped`:
      Scenario: `||domain.com^$third-party` in a plain feed → skipped (page-context
      option, not DNS-relevant).
      Then: `domain.com` NOT in the block DB.
