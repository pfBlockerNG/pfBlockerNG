ACTION PLAN (ordered)
1. MARKER CONSTANTS: define machine-detectable markers for auto-created VIPs —
   'pfB_AUTO_VIP_v4' and 'pfB_AUTO_VIP_v6' (the `descr` value the package will stamp).
   Put them where other pfb constants/globals live; one source of truth.
2. CANDIDATE GENERATOR `pfb_dnsbl_vip_candidates(int $family): array`:
   - AF_INET  -> ['10.10.10.53', '10.10.11.53', ... ] bounded sweep (e.g. X=0..15) keeping the
     `.53` DNS homage.
   - AF_INET6 -> ['fd00::53', 'fd00:1::53', ... ] bounded ULA sweep keeping `::53`.
   - Ordered, preferred-first. Pure (no side effects).
3. FREE-ADDRESS PICKER `pfb_pick_free_dnsbl_vip(int $family, string $interface): ?string`:
   - Walk the candidates; return the FIRST that is (a) not an existing VIP (pfb_get_vips) and
     (b) overlaps no configured subnet (where_is_ipaddr_configured — SAME call shape as
     pfb_validate_vips). Return null if none free.
4. V6-LISTEN DETECTION `pfb_unbound_listens_v6(): bool`:
   - True iff the DNS Resolver is configured to listen on at least one IPv6 address. Base it on
     the resolver's active interfaces resolved to addresses (document the exact predicate you
     chose and why, citing the upstream source you read). Be conservative/correct over clever.
5. KEEP IT UNWIRED: do NOT call these from pfb_create_dnsbl, pfb_global, the UI, or anywhere.
