WHY THIS PHASE EXISTS
The auto VIP is just another managed artifact. pfBlockerNG already creates/destroys its
DNSBL NAT inside pfb_create_dnsbl($mode) — and the call-site comment already reads
"Modify DNSBL NAT AND VIP and lighttpd web server conf" (inc:8697). This phase makes that
true: create the marked VIP on 'enabled'+auto, delete only marker+IP-matched VIPs on
'disabled'. This rides the existing enable/disable/uninstall paths and HA sync for free.

ACTION PLAN (ordered)
1. CONFIG KEY: add `pfb_dnsvip_auto` (on/off) under the DNSBL settings config
   (installedpackages/pfblockerngdnsblsettings/config/0). Default OFF. Read it in pfb_global()
   alongside the other dnsbl flags (do NOT yet add UI — that is Phase 4).
2. MANAGER `pfb_manage_dnsbl_vip(string $mode): void`:
   - mode 'enabled' AND pfb_dnsvip_auto on:
     * For v4 (always) and v6 (when required — see Phase 3; for now: when a v6 VIP is already
       requested/needed): ensure a VIP with descr == the marker exists on $pfb['dnsbl_iface'].
       IDEMPOTENT: if a marked VIP already exists, reuse it (do not duplicate); else create one
       at pfb_pick_free_dnsbl_vip(...) with a fresh uniqid, subnet_bits 32 (v4) / 128 (v6),
       mode 'ipalias', type 'single', and apply via interface_ipalias_configure().
     * Set pfb_dnsvip4 / pfb_dnsvip6 to the "_vip{uniqid}" id(s); write_config once if changed.
     * If the picker returns null (no free address), do NOT create; leave config as-is and log.
   - mode 'disabled' (DNSBL or pfBlockerNG disabled), OR auto turned off, OR a family no longer
     managed: DELETE only VIPs where descr == marker AND subnet == the IP currently resolved from
     the stored pfb_dnsvip4/6 config — interface_vip_bring_down() + remove from virtualip/vip +
     clear the corresponding pfb_dnsvip4/6 id; write_config once if changed.
   - NEVER touch a VIP lacking the marker. NEVER delete on marker-only without the IP match.
3. WIRE: call pfb_manage_dnsbl_vip($mode) from pfb_create_dnsbl($mode) — place create in the
   enabled path (before/with the NAT create so NAT sees the VIP) and delete in the disabled path.
   Keep the boot/install call site (:6686) correct (it passes 'enabled').
4. GUARD ADDITIVITY: with pfb_dnsvip_auto off, pfb_manage_dnsbl_vip returns immediately →
   pfb_create_dnsbl is byte-identical to today.
