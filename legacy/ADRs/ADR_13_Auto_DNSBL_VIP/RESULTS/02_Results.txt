Manager signature + lifecycle predicates
-----------------------------------------
  function pfb_manage_dnsbl_vip(string $mode): void

  Pure ownership predicate it relies on:
    function pfb_find_marked_vip(array $vips_config, string $marker, ?string $match_ip): ?int
      Returns the integer key of the first virtualip/vip entry where:
        (1) ($vip['descr'] ?? '') === $marker   (MARKER, always required), AND
        (2) when $match_ip is a non-empty string: ($vip['subnet'] ?? '') === $match_ip
            (IP MATCH). $match_ip === null OR '' matches on the marker alone.
      null otherwise. (Guards $idx with is_int so a non-list array can't return a
      string key.)

  Top-level guards (in order):
    * $mode not in {'enabled','disabled'} -> return (no-op).
    * $mode === 'enabled' && auto OFF      -> return immediately (BYTE-IDENTICAL no-op).

  EXACT CREATE predicate (mode 'enabled' AND pfb_dnsvip_auto on):
    * v4 family ALWAYS managed; v6 family managed iff
        $want_v6 = !empty($pfb['dnsblconfig']['pfb_dnsvip6']) || pfb_unbound_listens_v6()
      (a v6 VIP already requested OR resolver listens on IPv6).
    * For each managed family: IDEMPOTENT ensure —
        $idx = pfb_find_marked_vip($vips, MARKER, null)   // reuse by marker alone
        if found  -> reuse it (backfill a missing uniqid only);
        else      -> $address = pfb_pick_free_dnsbl_vip($family, $interface);
                     if null -> DO NOT create, log, leave config as-is (continue);
                     else append entry {mode:'ipalias', interface:$pfb['dnsbl_iface'],
                          type:'single', subnet:$address, subnet_bits:'32'|'128',
                          descr:MARKER, uniqid:uniqid()}.
      Then set $dnsblconfig[idkey] ('pfb_dnsvip4'|'pfb_dnsvip6') = "_vip{uniqid}"
      (only if it changed).

  EXACT DELETE predicate (family NOT managed — i.e. mode 'disabled', OR auto OFF on
  the disabled path, OR a family no longer managed such as v6 no-longer-wanted):
        $match_ip = (string)(get_configured_vip_ipv4|ipv6($dnsblconfig[idkey] ?? '') ?? '');
        if ($match_ip === '') continue;                       // nothing resolvable to delete
        $idx = pfb_find_marked_vip($vips, MARKER, $match_ip); // MARKER **AND** IP both required
        if ($idx === null) continue;                          // not ours / no IP match -> skip
        interface_vip_bring_down($vips[$idx]); unset; array_values;
        unset $dnsblconfig[idkey].
    => A VIP is deleted ONLY when descr === PFB_AUTO_VIP_DESCR_V4/_V6 AND its subnet
       equals the address the stored pfb_dnsvip4/6 id currently resolves to. A manual
       (unmarked) VIP is NEVER touched; a marked VIP whose address no longer matches
       stored config is NEVER deleted on the marker alone.

  write_config: fires exactly ONCE, and only when $changed is TRUE (a create, a
  uniqid backfill, an idkey repoint, or a delete actually happened). With auto OFF
  and no pre-existing marked VIP, $changed stays FALSE -> no write_config -> the
  config.xml and the update pass are byte-identical to today.

VIP entry fields + apply sequence
---------------------------------
  Entry (mirrors pfblockerng_install.inc:46-67 canonical shape):
    mode='ipalias', interface=$pfb['dnsbl_iface'] (default 'lo0'), type='single',
    subnet=<picked address>, subnet_bits='32' (v4) / '128' (v6),
    descr=PFB_AUTO_VIP_DESCR_V4/_V6, uniqid=uniqid(); selectable id "_vip{uniqid}".

  Apply sequence VERIFIED against upstream pfSense firewall_virtual_ip.inc
  (saveVIP/applyVIP, read at master per CLAUDE.md upstream-source rule;
  source of truth https://github.com/pfsense/pfSense): CONFIG FIRST, THEN APPLY —
    config_set_path('virtualip/vip', $vips);
    config_set_path('installedpackages/pfblockerngdnsblsettings/config/0', $dnsblconfig);
    write_config('pfBlockerNG: saving DNSBL auto-VIP changes');
    foreach managed family: interface_ipalias_configure($vip);   // bring alias up live
  Removal mirrors applyVIP's teardown: interface_vip_bring_down($vip) BEFORE dropping
  the entry from config. After write+apply the manager calls pfb_global() once to
  refresh $pfb so the NAT create that follows sees the new dnsbl_vip4/6 addresses.

Auto-off byte-identical (confirmed by trace)
--------------------------------------------
  * mode 'enabled' & auto off -> 2nd top guard returns immediately; pfb_create_dnsbl
    proceeds exactly as before (no VIP read/write).
  * mode 'disabled' & auto off (feature never used) -> delete loop runs but every
    candidate requires the MARKER; a manual/absent VIP yields no match -> $changed
    stays FALSE -> early return BEFORE any config_set_path/write_config. No config
    mutation, no interface call. Byte-identical.
  * Only when a marked auto-VIP actually exists (i.e. auto was on earlier) does the
    disabled path delete it — the intended teardown, not a regression.
