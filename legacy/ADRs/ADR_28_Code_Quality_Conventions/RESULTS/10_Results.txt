1. NEW SNIFF — PfBlockerNG.CodeStyle.UppercaseBooleanLiteral
-------------------------------------------------------------

File: tests/phpcs/PfBlockerNG/Sniffs/CodeStyle/UppercaseBooleanLiteralSniff.php

What it flags:
  Any T_TRUE or T_FALSE token whose text is not exactly uppercase — i.e.
  lowercase ("true", "false") or PascalCase ("True", "False") boolean VALUE
  literals. Emits a fixable error (ADR-28 item 5).

Type-declaration exclusion mechanism:
  PHPCS's own PHP tokenizer (PHP.php) converts T_TRUE/T_FALSE back to T_STRING
  when they appear in type-declaration context (after T_FUNCTION for return
  types, inside parameter type hints, in union types following T_TYPE_UNION |).
  This means "string|false", "?true", ": false" return types, and param types
  never arrive at the sniff as T_TRUE/T_FALSE — they arrive as T_STRING and are
  invisible to register() which only listens for T_TRUE and T_FALSE. The sniff
  requires zero custom context inspection; the exclusion is structural.

Implementation approach:
  Extends Generic.PHP.UpperCaseConstantSniff (which extends
  Generic.PHP.LowerCaseConstantSniff), inheriting the full type-declaration
  skip logic (property modifiers, T_FUNCTION/T_CLOSURE/T_FN, T_CONST paths).
  Overrides:
    - register(): returns T_TRUE + T_FALSE (not T_NULL — out of scope).
    - processConstant(): skips non-T_TRUE/T_FALSE tokens, reports uppercase
      violations only with error code "Found" and auto-fixable replacement.

Out of scope (not flagged):
  - Type declarations (string|false, ?true, etc.) — structural exclusion.
  - String literals ('true', "false").
  - Identifiers and method names.
  - null/NULL — ADR-28 §2.4 explicitly excludes NULL.
  - JS — the sniff only registers PHP token types.
