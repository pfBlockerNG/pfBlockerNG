  pfb_cfg_toggle_write(toggle: PfbToggle) -> str

  pfb_cfg_lenient_read(stored: str | None) -> PfbLenient
  pfb_cfg_lenient_write(lenient: PfbLenient) -> str

How a field declares its "off" vocabulary:
  - PfbToggle: "off" is '' (empty string — checkbox unchecked / key absent).
  - PfbLenient: "off" is 'off' (explicit string — ADR-22 strict mode).
  - PfbIdnMode: "off" is 'off' (explicit string — IDN feature disabled).
  No single global toggle: each field's adapter is field-specific per ADR-28 §2.2.

------------------------------------------------------------

  Canonical: 'on', ''
  Junk (-> Off = ''): 'yes', '1', 'off'
  null / None (-> Off)
  Round-trip: write(read('on')) == 'on'  ✓
              write(read(''))  == ''     ✓

PfbLenient / pfb_dnsbl_lenient:
  Canonical: 'on', 'off'
  Absent/blank (-> Off = 'off'): ''
  null / None (-> Off)
  Junk (-> Off): 'yes', '1', 'enabled'
  Round-trip: write(read('on'))  == 'on'  ✓
              write(read('off')) == 'off' ✓
  Non-lossless: write(read('')) == 'off' != ''
    Explanation: '' is a pre-ADR-22 absent-key state; pfb_global() also normalises
    to 'off'. This is consistent behaviour, not a regression.

PfbIdnMode / pfb_idn (dnsbl_idn):
  Canonical: 'all', 'confusable', 'off'
  Legacy: 'on' (pre-ADR-08 UI value)
  Absent/blank (-> Off = 'off'): ''
  null / None (-> Off)
  Junk (-> Off): 'yes', 'enabled', 'IDN_MODE_ALL', '1'
  Round-trip: write(read('all'))        == 'all'        ✓
              write(read('confusable')) == 'confusable' ✓
              write(read('off'))        == 'off'        ✓
  Non-lossless (documented): write(read('on')) == 'all' != 'on'
  Non-lossless (normalised):  write(read(''))  == 'off' != ''


4. FIELDS NOT ROUND-TRIPPING LOSSLESSLY (EXCLUSION CANDIDATES)
----------------------------------------------------------------

PfbIdnMode / 'on' (legacy):
  write(read('on')) == 'all', not 'on'.
  This is INTENTIONAL: 'on' is a pre-ADR-08 legacy value that pfb_global() already
  migrates to 'all' at runtime (:1373). The adapter replicates that normalisation.
  New saves always write 'all'; 'on' is never re-emitted. This is a one-way migration
  that cannot corrupt stored data (the canonical 'all' is safe on older installs because
  pfb_global() accepts 'all' as a valid IDN mode value).
  Status: NOT excluded — the one-way migration is intentional and matches existing
  pfb_global() behaviour.

PfbLenient / '' (absent key):
  write(read('')) == 'off', not ''.
  This is normalisation of a pre-ADR-22 absent-key state — consistent with pfb_global()
  :1364. No functional difference: '' and 'off' both map to strict mode.
  Status: NOT excluded — normalisation is intentional.

No field required exclusion. All three fields adopt cleanly.
