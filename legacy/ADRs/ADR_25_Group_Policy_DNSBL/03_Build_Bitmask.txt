REVISED 2026-07-04 terminology note: post-ADR-54, "DNSBL alias" == dnsbl FEED GROUP (the
manifest 'group' field = DNSBL_{feedgroup name}, unchanged in shape). Bits are assigned one
per dnsbl Feed Group. Everywhere this prompt says "alias", read "Feed Group"; the mechanics
below are otherwise unchanged. "Groups absent from the manifest => off" remains the gate
(the Phase-4 manifest keys do not exist yet when this phase runs).

ROLE
Work in the per-ADR worktree on branch adr/25-group-policy-dnsbl. Phase 3 changes the BUILD
layer but is BEHAVIOUR-PRESERVING WHEN GROUP POLICY IS OFF (the default). One commit, push
directly to the branch.

WHY THIS PHASE EXISTS
Per-group alias subsetting needs to know, for a matched domain, WHICH DNSBL aliases it
belongs to (a domain can be in several). Today the build collapses a domain to one
attribution. Store an alias-membership BITMASK per domain so the Phase-5 decision layer can
intersect it with a client's subscribed-alias mask in O(1) — while keeping the matcher
group-agnostic so decisionDB stays domain-keyed (ADR SS2.1).
