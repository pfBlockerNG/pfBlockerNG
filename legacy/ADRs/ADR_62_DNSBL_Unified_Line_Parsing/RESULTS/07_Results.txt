GENUINE DEFECT DISCOVERED WHILE BUILDING ROW 7 (NOT fixed this phase)
--------------------------------------------------------------------------------
While designing the "reused feed with old-dialect .txt" row (SS7 row 7), I
traced pfb_unbound_python_sources()'s per-line handling of a feed's staging
.txt (inc:7098-7161) against a genuinely old-dialect $easylist-verbatim body
(a bare-domain line with NO commas, exactly what the old classifier used to
write verbatim for a whole-feed-ABP body). The function's "not ABP-shaped ->
extract CSV col 1" branch does `explode(',', $line, 3)` and writes `$cols[1]`
-- for a comma-less line, `$cols[1]` is unset, so the line is SILENTLY
DROPPED, not written verbatim.

VERIFIED (EXECUTED, not reasoned from memory) via a throwaway PHP script
against the REAL function (tests/php/bootstrap.php):
  $ php /private/tmp/.../repro.php
  old_abp_feed.txt: "||anchor.example^\nbare-domain.example\n"
  --- produced .raw ---
  '||anchor.example^
  '
  --- contains bare-domain.example? ---
  bool(false)

This means: on upgrade to a build carrying this ADR, an existing ABP-
classified DNSBL feed with a bare-domain line loses that domain's block
SILENTLY the first post-upgrade pass where the feed's remote content has not
changed (the reuse fork, inc:16277-16308, which is the default "nothing
changed" path every feed takes once it has succeeded once) -- until the feed
happens to actually re-download. This contradicts ADR.md Semantics #7's
literal claim ("a reused ... feed's .txt ... produces the same Python input"
for "old raw-ABP" dialect) for this one sub-case; the corpus's own
reused_manifest_abp fixture never exercised a bare-domain line (only
'||reused.example^'), so the gap was invisible to the existing oracle.

Per CLAUDE.md's ESCALATE contract, filed as a tracked issue rather than
silently built around or silently fixed (production-code fix is out of this
phase's docs/smoke scope and I could not verify a fix live):
  https://github.com/pfBlockerNG/pfBlockerNG/issues/1105

Recorded in ADR.md's Status "As-built summary" (Discovered-during-this-phase
bullet). tests/smoke/test_smoke_adr62.py's row-7a reuse test deliberately
covers ONLY the safe 6-col-dialect reuse sub-case (unaffected by this gap --
the 6-col dialect is unchanged by ADR-62) and documents the exclusion inline
in its own module-level comment block.
