DEVIATIONS
------------
1. Kept $format's derivation (the ternary reading $feed['format']) instead
   of also simplifying it to a hardcoded 'plain' literal. Justification:
   the corpus's reused_manifest_abp fixture (feeds.json format='abp') and
   Adr62DnsblCorpusManifestTest::testManifestTaggingMatchesFeedsJson()
   deliberately drive this function with format='abp' input and assert
   format_hint reflects it -- hardcoding 'plain' would have broken that
   oracle assertion (a REAL regression, not dead-code cleanup) and would
   have silently narrowed the function's documented "your call, state it"
   contract with the corpus. The brief's own note anticipated exactly this
   check ("If deleting the writer branch changes any corpus .raw byte, it
   was NOT dead -- STOP and investigate") -- I extended the same discipline
   to the format_hint TAGGING assertion, not just the .raw bytes, since
   Adr62DnsblCorpusManifestTest asserts both from the same test run. Ran
   the full corpus test BEFORE finalizing this decision (see CORPUS-STILL-
   GREEN CONFIRMATION) -- confirmed both testEveryCorpusFeedRawMatchesGolden
   AND testManifestTaggingMatchesFeedsJson pass with the derivation kept,
   proving this was the correct scope boundary, not a guess.
2. Committed the benchmark harness as permanent dev tooling under scripts/
   (bare `python3`/`php` invocation, never shipped to src/) rather than a
   throwaway scratch script, following the existing bench_pfctl_tables.sh /
   bench_aggregate_union.sh precedent -- explicitly the brief's "your call".
3. Did not rebase the worktree onto the current origin/devel tip (10 commits
   ahead) -- justified under WORKTREE BASE CHECK above (all 10 are provably
   orthogonal to this phase's files; rebasing 6 phases deep mid-ADR would
