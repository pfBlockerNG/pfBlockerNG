HELPER SIGNATURES
-------------------
1. function pfb_dnsbl_collect_feed_ip(string $guard_value, string $candidate_value,
   bool $custom, array &$domain_data_ip, array &$domain_data_ip6): bool
   -- is_ipaddrv4($guard_value): sanitize_ipaddr($candidate_value,$custom,'Disabled')
      then validate_ipv4(parsed); on pass, append PARSED to $domain_data_ip, return TRUE.
   -- is_ipaddrv6($guard_value): validate_ipv6($candidate_value) RAW (no sanitize); on
      pass, append RAW $candidate_value to $domain_data_ip6, return TRUE.
   -- neither family, or validation fails: return FALSE, arrays untouched.
   UPDATEIP-FLIP DECISION: rides the RETURN VALUE, not a $pfb-writing side effect inside
   the helper. The helper never touches $pfb['updateip'] or $ipcount -- every call site
   still does `if (pfb_dnsbl_collect_feed_ip(...)) { $pfb['updateip']=TRUE; $ipcount++; }`
   itself. Chosen because the 3 sites' surrounding control flow (continue placement,
   dnsbl_ip-guard placement) genuinely differs (asymmetries b/c/d) -- a helper that also
   owned the $pfb write would need to know about that per-site continue/guard shape,
   defeating the extraction. Returning a bool keeps the helper decoupled from $pfb
   entirely (pure w.r.t. globals beyond its declared array-by-ref params).

2. function pfb_dnsbl_is_skippable_control_line(string $line): bool
   -- TRUE iff $line === '' (exact match, NOT empty()/whitespace-trimming -- mirrors the
      pfb_is_blank_or_comment_line contract: caller trims first), OR starts '!'/'//', OR
      is a '[...]'  wrapper that pfb_dnsbl_unbracket_ip6() does NOT unwrap (i.e. NOT a
      valid bracketed IPv6 literal). Deliberately excludes '#' (hash-classifier's job).

3. function pfb_dnsbl_is_abp_rule_line(string $line): bool
   -- TRUE iff starts '||' or '@@' (blanket prefix, covers @@||/@@/re/@@-anything per
      ADR §2 Decision 2's literal wording), OR contains any of '##'/'#@#'/'#?#'/'#%#'/
      '#$#' ANYWHERE (str_contains, mirroring parse_abp's `X in s` substring test, not a
      prefix test), OR is a bare '/regex/' shape (mirrors _dnsbl_parse_abp_regex's
      closing-slash rule: ends '/' with length>1, or has a '/$' marker at index>0 for the
      $options-tail form). Bare domain lines are FALSE by design (D1, Phase 5's split).

NOT WIRED THIS PHASE (per WIRING DISCIPLINE)

and found NO site where wiring is "provably exact-equivalent":
- The ABP-branch control skip (inc:~16513, `$line===''||starts('!')||starts('[')`) sits
  AFTER the IP-extraction attempt at a point where a bracketed-IPv6 literal was NEVER
  extracted as an IP by pfb_dnsbl_abp_extract_ip() (it only recognises `||host^` and
  `<ip> <ip>` hosts shapes, not a bare `[...]` wrapper) -- swapping in
  pfb_dnsbl_is_skippable_control_line() here would newly EXEMPT a bracketed-IPv6 line
  from this skip (since the new predicate's carve-out returns FALSE for it), changing
  behaviour (today it is silently skipped/dropped here; Phase 4/5 territory). Left
  untouched.
- The plain-path '!'/'//' skip (inc:~16561, `starts('!')||starts('//')`) does NOT
  already exclude blank or '[...]' lines the way pfb_dnsbl_is_skippable_control_line()
  would additionally catch -- a blank line here already falls through harmlessly to the
  existing `if (empty($line)) continue;` a few lines later (behaviourally a no-op either
  way), but a '[...]'-non-IPv6 line here currently falls through to domain validation and
  the #1004 parse-error log (delta D3, explicitly a Phase 4 change) -- NOT wiring the
  predicate here preserves that. Confirmed exactly the brief's own worked example
  ("if that is not clean, leave the site untouched"). Left untouched.
- pfb_dnsbl_is_abp_rule_line() is strictly BROADER than every existing single check
  (ADR-21's `starts('||')||starts('@@||')` at inc:~16404; the ABP-branch's narrower
  control skip) -- wiring it anywhere would route additional shapes (regex, element-
  hiding) that today are NOT captured, a behaviour change reserved for Phase 4. Not
