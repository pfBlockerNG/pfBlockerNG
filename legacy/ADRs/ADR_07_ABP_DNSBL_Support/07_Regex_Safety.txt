WHY THIS PHASE EXISTS / THE ACCEPTED DESIGN (read carefully)
`re` does not release the GIL and Python threads cannot be killed (fact 2), so a query-time
timeout CANNOT interrupt a catastrophic match — a subprocess/re2 would be the only airtight
fix and the maintainer has declined to pay for them. The ACCEPTED design is a bounded
residual risk: a pathological pattern's FIRST match may block one query, but it is then
evicted so it cannot hang again. This phase implements that, plus an opt-in static pre-filter.

ACTION PLAN
1. OPT-IN STATIC CAP (load time, in-process, no execution): a pure function that rejects a
   pattern when "Limit long/complex regex" is enabled and it exceeds the length ceiling or
   matches the nested/overlapping-unbounded-quantifier heuristic (RESULTS/01). Dropped
   patterns are logged. Apply at the point regex is compiled/loaded — to FEED regex AND the
   user pfb_regex_list. (When the setting is OFF, nothing is dropped at load.)
2. ALWAYS-ON RUNTIME TIMING + EVICTION (query path): wrap each regex match with a per-thread
   CPU measurement — time.thread_time (NOT wall clock: it must not false-evict a good pattern
   when the thread was merely descheduled under load). If time.thread_time is unavailable on
   the target, fall back to time.perf_counter with a 2-strike guard. Defaults: WARN_CEILING
   10 ms, EVICT_CEILING 100 ms thread-CPU, both configurable (advanced). On a match:
   - if elapsed > WARN_CEILING -> log a warning (pattern + feed, RATE-LIMITED per pattern).
   - if elapsed > EVICT_CEILING -> log an error and EVICT the pattern from the live DB
     (immediately, on the first crossing — the point is it can't hang twice).
   EVICTION must be thread-safe: the scan iterates a SNAPSHOT (Phase 6) and eviction does
   regexDB.pop(k, None) / allowRegexDB.pop(k, None) AFTER the loop (dict.pop is atomic under
   the GIL; never mutate mid-iteration). Eviction applies to feed AND user regex alike.
   Ceilings come from config (Phase-1 defaults), not hardcoded magic.
3. SETTING: add the "Limit long/complex regex" opt-in to the DNSBL settings page +
   dnsblconfig (PHP/www), plumb it into the manifest config / plugin cfg so build()/load read
   it. Keep PHP lint/stub-clean; no die()/exit in lib.
4. UNIT-TEST (tests/test_adr07_regex_safety.py, pure, no live Unbound):
   - cap ON drops an over-length / nested-quantifier pattern at load; cap OFF keeps it.
   - a synthetic SLOW pattern (feed a small but >WARN/>EVICT input via a stub clock or a real
     (a+)+ against a crafted string with a tiny ceiling) triggers warn then evict; the evicted
     key is gone and the scan does NOT raise "dict changed size during iteration".
   - eviction works identically for a user-provenance regex.
   - the no-regex / no-slow common path is unchanged (no perf regression in the fast path).
