1. THE EMITTED STRUCTURE SHAPES  (what is now LIVE in the matcher)
================================================================================
All payloads widened with a numeric `band` (the P3 PRIO_* scale, 1-6). The matcher
reads every new field TOLERANTLY (.get / isinstance) so a payload missing it still
decides (the ADR-06 oracle + the strata synthetic payloads have no `band`).

  dataDB[d] / zoneDB[z]  (BLOCK)
    {"log": <flag>, "index": <int>, "important": bool, "band": int}
    band: PRIO_FEED_BLOCK(1) | PRIO_FEED_BLOCK_IMPORTANT(3) | PRIO_USER_BLOCK(5).
    Non-abp + synthetic-TLD-zone blocks are band 1, important False.

  whiteDB[d]  (ALLOW domain)
    {"wildcard": bool, "important": bool, "band": int}
    band: PRIO_FEED_ALLOW(2) | PRIO_FEED_ALLOW_IMPORTANT(4) | PRIO_USER_ALLOW(6).
    User whitelist + TOP1M -> band 6 (sovereign). A reduced feed @@/re/ or @@||d^
    -> band 2 (or 4 with $important). A feed allow NEVER downgrades a higher-band
    user-whitelist entry on the SAME key (build() guards with _white_entry_band).
    LEGACY-TOLERANT: a bare-bool whiteDB value (ADR-06 oracle, add_white helper)
    still works -- _white_entry_band derives band 6 if important else 2.

  regexDB[name]        (BLOCK regex)        allowRegexDB[name]   (ALLOW @@/re/)
    {"re": <compiled>, "important": bool, "band": int}
    name = "{feed}#{seq}" (seq is a per-build counter so duplicate patterns from one
    or many feeds DO NOT COLLIDE and EACH is independently evictable -- P7 keys off
    this). LEGACY-TOLERANT: a bare compiled pattern (the user REGEX-ini load) still
    works -- _block_entry_band / _scan_allow_regex_band treat it as band 1 / band 2.

  BuildResult also carries: important_rules (the flag, below), regex_count (the
  ADMITTED feed-regex total: block_admitted + allow_admitted -- for the DNSBL_Regex
  UI alias; see SS4), counts (unchanged: len(data)+len(zone)).

2. WHERE regexDB / allowRegexDB ARE SCANNED  (the Phase-7 eviction hook points)
================================================================================
ALL regex scans already iterate a SNAPSHOT (list(...)) so Phase 7 can evict mid-
scan by mutating the live dict AFTER the loop (never during). The hook points:

  a) evaluate_domain DISCOVERY block-regex scan (the FAST + numeric first-hit):
       for k, r in list(regex_db.items()):
           pattern = r.get("re") if isinstance(r, dict) else r
           if pattern.search(q_name): ...   # first hit sets is_found + block_band
     -> this is the per-query block-regex pass (the ADR-01-class cost site). Phase 7
        wraps `pattern.search` with thread-CPU timing here.

  b) _scan_block_band(q_name, cfg, data_db, zone_db, regex_db) -- NUMERIC branch
     only. Re-scans data/zone-suffix/block-regex (snapshot list()) to take the MAX
     block band (decide() semantics; discovery short-circuits on first hit).

  c) _scan_allow_regex_band(q_name, allow_regex_db) -- NUMERIC branch only. Snapshot
     list() over the allow-regex DB; returns the highest matching allow band.

PHASE 7 PLAN: add per-match thread-CPU timing (time.thread_time) around each
`pattern.search` in (a)/(b)/(c); collect over-warn / over-evict names into a local
list; AFTER the loop do regexDB.pop(name)/allowRegexDB.pop(name) (atomic under the
GIL). Default warn 10 ms / evict 100 ms (ADR.md SS2; Phase-1 ceilings). The
per-name keying (SS1) makes a single bad pattern evictable without dropping good
ones that share its source feed.

3. HOW important_rules GATES THE FAST vs NUMERIC PATH  (the contract, preserved)
================================================================================
build() emits important_rules = reconcile(...).important_rules: True iff any
surviving rule needs numeric resolution (any $important, any feed @@/allow, any
feed irreducible regex). init -> pfb["important_rules"] -> cfg["important_rules"].

evaluate_domain resolution stratum:
  if is_found:
      if not cfg.get("important_rules", False):     # FAST PATH -- BYTE-IDENTICAL
          if cfg["whiteDB"]:                         # to pre-P6 (the no-regression
              in_whitelist = any(whitelist_check_domain(...) for n in names)
                                                     #  anchor; ADR-06 oracle green)
      else:                                          # NUMERIC 6-BAND (now LIVE)
          block_band = max(block_band, _scan_block_band(...))   # max over all blocks
          in_whitelist = _resolve_numeric_allow(..., block_band)
  -> _resolve_numeric_allow returns (allow_band >= block_band): an ALLOW wins ->
     mapped onto in_whitelist (== "name resolves"), so the shared downstream
     hsts/null-routing logic is untouched. No allow match -> allow_band 0 -> block.

CONFIRMED byte-identical fast path: the `if not flag: if cfg["whiteDB"]:` block is
unchanged from pre-P6; allowRegexDB + the band fields are NOT read on the fast path.
A pure plain/hosts/||domain^ feed set OR a user-whitelist-only set keeps
important_rules False (RESULTS/05 SS5) -> stays on the fast path. The only fast-path
edit is wrapping the block-regex `.items()` in list() (iteration-safety; no
semantic change).

badfilter-vs-user-whitelist case asserts != "block" rather than an exact label.
