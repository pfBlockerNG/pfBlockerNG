1. THE STATIC-CAP HEURISTIC + CEILINGS AS IMPLEMENTED
================================================================================
STATIC CAP (opt-in; _regex_exceeds_static_cap, pure, NO execution):
  Drop a pattern iff:
    len(pattern) > REGEX_STATIC_LEN_CAP (200)               -- over-length, OR
    _REGEX_NESTED_QUANTIFIER.search(pattern) is not None    -- nested quantifier:
      regex = r"\([^()]*[+*][^()]*\)\s*[+*{]"  (a quantified group inside a
      quantifier: (a+)+, (a*)*, (\w+\.)+, ([a-z]+)*, (.*a){20}).
  This is the Phase-1 RESULTS/01 SS3c heuristic verbatim (caught 1/1 catastrophic,
  0 false-neg, 0 false-pos on the corpus). Applied at LOAD in BOTH:
    * _dnsbl_compile_regex_rules(..., static_cap=...)  -- ABP FEED regex.
    * the init REGEX-ini load loop                     -- USER pfb_regex_list.
  Gated by pfb["regex_cap"] (the "Limit long/complex regex" setting). OFF -> nothing
  dropped (default). Dropped patterns are logged to py_error.log via sys.stderr.

RUNTIME CEILINGS (always on; from cfg, NOT hardcoded magic):
  warn  = REGEX_WARN_MS_DEFAULT  = 10.0 ms  thread-CPU  -> rate-limited warning.
  evict = REGEX_EVICT_MS_DEFAULT = 100.0 ms thread-CPU  -> error log + evict.
  Overridable via ini MAIN regex_warn_ms / regex_evict_ms -> pfb -> cfg.
  Timing source: time.thread_time when available (_REGEX_HAVE_THREAD_TIME, jitter-
  robust so a descheduled thread can't false-evict); else time.perf_counter with a
  REGEX_PERF_STRIKES(2)-consecutive guard (a lone wall-clock spike does NOT evict;
  a fast match resets the streak). thread_time evicts on the FIRST over-evict cross.

================================================================================
2. THE EVICTION MECHANISM + ITS THREAD-SAFETY ARGUMENT
================================================================================
At each of the 3 scan points the loop iterates a SNAPSHOT (list(regex_db.items())
/ list(allow_regex_db.items())), times each match with _regex_timed_search, asks
_regex_should_evict, and COLLECTS over-evict keys into a local list `to_evict`.
AFTER the loop, _regex_evict_names does regexDB.pop(k, None) / allowRegexDB.pop(k,
None) for each. THREAD-SAFETY: the matcher runs across many Unbound query threads
sharing the live dicts; under the GIL dict.pop is atomic, and because we snapshot-
iterate and pop AFTER the loop we NEVER mutate a dict mid-iteration -> no "dict
changed size during iteration" and no torn read (ADR.md fact 3). Per-name keying
("{feed}#{seq}" for feed, the user label for user regex) means ONE bad pattern is
evicted in isolation -- good patterns from the same feed survive (pinned by
test_eviction_does_not_corrupt_scan: 5 survive, only SLOW evicted).
ACCEPTED RESIDUAL (maintainer, fact 2): the FIRST over-evict match already ran to
completion (it holds the GIL; cannot be interrupted) -- that one slow first-hit is
the bounded cost. On that hit the pattern is treated as NOT-found (evicted, not
blocked) and removed, so subsequent queries are fast and it can't hang twice.
