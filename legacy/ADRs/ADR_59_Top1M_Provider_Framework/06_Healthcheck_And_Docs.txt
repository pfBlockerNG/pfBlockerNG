WHY THIS PHASE EXISTS

token provider exists, it must classify providers by auth and handle token ones
without failing the run for lack of a secret — and never silently skip.

ACTION PLAN
1. Extend the extractor to also read each provider's `auth` from the descriptor
   (the extractor already reads pfblockerng.php; now it must know which providers
   need a token). Classify: keyless → GET-validate as today; token → validate ONLY
   if the matching CI secret (e.g. env CLOUDFLARE_RADAR_TOKEN) is present (send it
   via the Authorization header), else emit a VISIBLE "skipped: needs token, no
   secret configured" line and do NOT fail the leg for that reason.
2. Workflow: pass the optional secret into the check job's env; a token leg is
   skipped-not-failed when the secret is absent. The overall run still goes red for
   a genuinely dead keyless provider (unchanged).
3. Docs: add the `top1m_token` field to the config-gateway.md inventory; add a
   short docs/misc note (TOP1M providers: the descriptor, per-provider format +
   container + auth, the licence obligations (Majestic CC BY 3.0, Cloudflare
   CC BY-NC), and how a user supplies the Cloudflare token).
