1) THE ORACLE (load-bearing; ADR §1 fact 3 — NOT HTTP 200)
--------------------------------------------------------------------------------

New module tests/smoke/ui/render_oracle.py. A page PASSES iff ALL of:

  (a) HTTP 200.
  (b) Body contains NONE of the PHP-diagnostic substrings:
        FORBIDDEN_SUBSTRINGS = ('Fatal error', 'Parse error', 'Warning',
                                'Notice', 'Uncaught', 'Stack trace')
      (case-sensitive plain substrings — PHP emits these with this exact casing;
      this is exactly the ADR §1/§2 list. 'Deprecated' was considered and DROPPED
      to match the ADR's prescribed set and avoid false-positive surface; add it
      back only if a Deprecated regression is the target. NOTE/RISK below.)
  (c) A page-SPECIFIC content marker is present AND the body is NOT the login form
      (looks_like_login_page) — so a blank body, a redirect to the dashboard, or a
      logged-out 200 (pfSense renders login in place at 200, no 302) cannot pass.
  (d) The on-box php_error.log gained NO new bytes DURING the sweep (sweep-level,
      not per-page) — the source-of-truth log, catching a diagnostic that was
      logged but not echoed into a body.

API (reusable by Phases 3/4):
  FORBIDDEN_SUBSTRINGS: tuple[str, ...]
  body_has_php_error(body) -> first forbidden token present, or None
  evaluate_render(path, status_code, body, markers) -> RenderResult(ok, reasons, …)
      applies (a)-(c); reasons lists EVERY failing condition (specific msgs).
  class PhpErrorLogGuard(vm, candidates=PHP_ERROR_LOG_CANDIDATES):
      .snapshot()         — record byte size of each existing candidate log
      .assert_no_growth() — fail if any grew; message includes the appended tail

php_error.log diff mechanism (d):
  - Candidate paths, in pfSense order: PHP_ERROR_LOG_CANDIDATES =
      ('/var/log/php_error.log', '/var/log/php-fpm.log').
    pfSense's webConfigurator FPM pool logs PHP errors to /var/log/php_error.log;
    php-fpm.log is the daemon log on some builds. The guard snapshots WHICHEVER
    EXIST (missing => size 0), so a log CREATED mid-sweep also registers growth
    (0 -> N). Path is NOT hard-trusted: size is read on-box via
    `stat -f %z <path> 2>/dev/null || echo 0` (BSD/pfSense stat). [CLAUDE.md: read
    effective state, don't assume a path. CI VERIFICATION ITEM: confirm which of
    the two exists on the image from the smoke-diagnostics /var/log capture; if
    pfSense uses a different path, add it to PHP_ERROR_LOG_CANDIDATES.]
  - Snapshot ONCE before the parametrized sweep, assert ONCE after — a module-
    scoped fixture (php_error_log_guard) brackets the whole sweep. Each sweep test
    requests it, enrolling in the (d) check; growth from ANY page fails teardown.

      authenticated :8080 session CANNOT reach them.
      PHASE 5: fetch the VIP sinkhole directly — http://<DNSBL_VIP>:8081/ with a

4) PROVING THE ORACLE (a bare 200 NEVER passes) — runs LOCALLY (no VM)
--------------------------------------------------------------------------------

tests/smoke/ui/test_render_oracle.py — PURE LOGIC against evaluate_render, so it
EXECUTES off-box (no smoke_vm). It is under tests/smoke/ui/ (so the default
`python -m pytest` ignores it — count stays 1019) and runs under the smoke/ui
override AND requires no VM. Branch coverage (CLAUDE.md): EVERY case first asserts
the GOOD body PASSES (before-state), THEN the broken variant is REJECTED:
  - test_good_body_passes                — healthy 200+marker body passes (the baseline).
  - test_php_diagnostic_in_body_is_rejected[token] — for EACH FORBIDDEN_SUBSTRINGS
    token: the same body passes WITHOUT it, then FAILS once the token is injected.
  - test_non_200_is_rejected             — 500 fails though body is clean+marker.
  - test_missing_marker_is_rejected      — 200 with the WRONG page (no marker) fails.
  - test_login_form_body_is_rejected     — logged-out 200 (login form) fails.
  - test_multiple_failures_are_all_reported — 404 + Warning + no marker => ≥2 reasons.
=> a 200 alone, a 200 with a PHP warning, a blank/redirected 200, and the login
form are ALL rejected — the oracle is proven load-bearing, not an always-pass.

VERIFIED LOCALLY: `pytest tests/smoke/ui/test_render_oracle.py
test_page_table_covers_every_pfblockerng_page -m ui_render --override-ini="addopts="`
=> 12 passed (no VM needed).

7) REAL WARNINGS RECORDED (none yet — CI-pending)

- NOTE/RISK to watch in the FIRST CI run: FORBIDDEN_SUBSTRINGS are bare substrings.

  legitimately contains 'Warning'/'Notice' as plain text, a page could false-fail.

  the surrounding pfSense chrome was NOT exhaustively audited. If the first CI sweep
  false-fails on chrome text, tighten (b) to anchor on the PHP diagnostic shape
  (e.g. 'PHP Warning'/'<b>Warning</b>'/'on line') rather than the bare word — record
  the exact offending string here before changing the list.
