1) NEW: .github/workflows/ui-tests.yml — reusable, matrix-parametric
--------------------------------------------------------------------------------

Mirrors smoke.yml's scaffolding EXACTLY (the ADR-14 sibling of smoke.yml): the
build-pkg-linux.yml `.pkg` build, the GHCR image pull + content-keyed (digest)
cache, the KVM-perms udev fix, the SSH-key/secret handling, the
input>secret>variable image-ref resolution, and the diagnostics upload
`if: always()`.

TRIGGERS (`on:`):
  * workflow_call    — inputs: image_ref, version, tier  (the release pipeline + test.yml call it)
  * workflow_dispatch— inputs: image_ref, version, tier (choice: render|functional|browser|all)
  * schedule         — cron "0 5 * * *" (daily Tier-B run; non-PR-blocking)

INPUTS (workflow_call + workflow_dispatch, same names):
  * image_ref  GHCR pfSense CE ref; blank => SMOKE_IMAGE_REF secret/variable. Pin by @sha256:<digest>.
  * version    version LABEL for the matrix leg / screenshot dir; blank => the default CE label "ce".
  * tier       render | functional | browser | all  (default "all").

JOBS:
  * build-pkg  — `uses: ./.github/workflows/build-pkg-linux.yml` (channel: devel); one build feeds every leg.
  * prepare    — computes the (tier x version) matrix `include` JSON + the nightly
                 no-commit guard; outputs `matrix` and `run`.
  * ui         — `needs: [build-pkg, prepare]`, `if: needs.prepare.outputs.run == 'true'`,
                 `strategy: { fail-fast: false, matrix: ${{ fromJSON(needs.prepare.outputs.matrix) }} }`,
                 timeout-minutes: 30. ONE GH JOB PER (tier x version) leg.

MATRIX SHAPE (tier x version) — verified by dry-run + JSON parse:
  prepare emits `matrix={"include":[{"tier":"<t>","version":"<v>"},...]}`. Examples
  (DEFAULT_VERSIONS="ce", DEFAULT_SCHEDULE_TIERS="functional browser"):
    dispatch tier=all  -> render/ce, functional/ce, browser/ce       (3 legs)
    dispatch tier=render -> render/ce                                 (1 leg)
    schedule (ignores tier input) -> functional/ce, browser/ce       (2 legs, Tier B)
    two versions "ce plus" tier=all -> 6 legs (3 tiers x 2 versions)
  fail-fast: false => one leg's failure never cancels the others; GH "Re-run failed
  jobs" re-runs ONLY the flaky leg (C1).

  B1 (one-line image add): append a label to DEFAULT_VERSIONS in the `prepare` step
  (and wire its image ref). The axis is BUILT parametric; it runs the single CE
  image today.

TIER -> MARKER map (the `ui` job's "Map the tier" step, re-derived per leg so the
matrix stays a plain {tier,version}):
    render -> ui_render   |   functional -> ui_e2e   |   browser -> ui_browser
The `ui` job then runs:
    python3 -m pytest tests/smoke/ui -m "<marker>" \
      --override-ini="addopts=" --override-ini="timeout_func_only=true" \
      --timeout=300 --timeout-method=signal -v
  (--timeout=300 because the General save's sync pass can run ~300s, Phase-3 note;
  timeout_func_only=true scopes it to the TEST BODY, not the slow module fixtures.
  NO assertion auto-retry — C1. The only "retry" is the smoke conftest's
  wait_ready.sh polling the boot/readiness signal, never a fixed sleep.)

BROWSER DEP: the "Install the headless Chromium browser" step is gated
`if: matrix.tier == 'browser'` and runs `python3 -m playwright install --with-deps
chromium` — so only the browser leg pulls the ~150 MB binary; render/functional
stay lean.

EGRESS: unlike the smoke matrix, the UI tier does NOT set SMOKE_BLOCK_EGRESS — the
tiers are hermetic from the box's own config (no feed download to render chrome)
but want a working resolver + the Playwright browser, so egress is left OPEN.

The `ui` job's "Run the UI tier" step `env:` block now exports (the Phase-1

    SMOKE_ADMIN_USER:     ${{ vars.SMOKE_ADMIN_USER }}          # optional; default "admin"

    SMOKE_DNSBL_VIP4:     ${{ secrets.SMOKE_DNSBL_VIP4 || vars.SMOKE_DNSBL_VIP4 }}

never fail — but with it the webui fixture authenticates and the tier actually
runs. test.yml's Tier-A caller uses `secrets: inherit`, so the secret flows
through the reusable workflow.

3) TIER A — PR gate, paths-gated, FOLDED into the "All tests passed" aggregate
--------------------------------------------------------------------------------

test.yml changes (existing jobs byte-identical; only these added):

  * permissions: added `packages: read` (the Tier-A reusable workflow pulls the
    pfSense image from private GHCR). `contents: read` unchanged.

  * NEW job `ui-changes` — detects whether the PR/push touched PHP/JS, with a
    plain `git diff` (NO third-party paths-filter action, matching the repo's
    minimal-dep style). Diffs against `github.event.pull_request.base.sha` (PR) or
    `github.event.before` (push) over the ADR §2 3a path set:
        src/**/*.php   **/*.inc   src/**/*.js
    Outputs `php_js` = true|false. An all-zero / unreachable base (first push to a
    new branch) falls back to `true` (run the gate conservatively).

  * NEW job `ui-render` — `needs: ui-changes`, `if: needs.ui-changes.outputs.php_js
    == 'true'`, `uses: ./.github/workflows/ui-tests.yml` with `tier: render`,
    `secrets: inherit`. So Tier A boots a VM ONLY on a PHP/JS-touching PR; on a
    docs/Python-only PR the job is SKIPPED (it never boots a VM).

  * AGGREGATE FOLD — the exact mechanism release.yml's verify-checks reads:
    `release.yml`'s verify-checks asserts the SINGLE check-run NAMED
    "All tests passed" for the tagged commit is `success`. That check-run is the
    `all-tests-passed` job (job `name: All tests passed`). Folding Tier A in =
    extend THAT job (no new required check to wire):
      - added `ui-render` to its `needs:` list, and
      - added a result check at the end of "Check matrix results":
            case "${{ needs.ui-render.result }}" in
              success|skipped) ;;
              *) echo "Tier-A UI render-smoke failed or was cancelled."; exit 1 ;;
            esac
    `skipped` (no PHP/JS change => the gate legitimately did not run) is a PASS;
    only an actual `failure`/`cancelled` blocks. `all-tests-passed` keeps
    `if: always()`, so it still runs (and the case still evaluates) regardless of
    upstream job state. The check-run NAME is unchanged => verify-checks already
    covers Tier A with zero release.yml edit. Phase 6 adds the SEPARATE release
    gate (release.yml `needs:` the reusable UI workflow); that is NOT done here.

  REBASE NOTE: origin/devel landed a new informational `benchmarks` job (issue #42)
  in test.yml during this phase. The rebase conflict was resolved keeping BOTH —
  `benchmarks` stays (and stays INTENTIONALLY ABSENT from the aggregate `needs`,
  per its own comment) and the Tier-A jobs were added alongside. Final test.yml
  jobs: test, test-typing, ruff, shellcheck, shell-tests, php-syntax,
  php-static-analysis, php-unit, markdownlint, benchmarks, ui-changes, ui-render,
  all-tests-passed.

4) TIER B — schedule (daily-if-commits) + dispatch; NON-PR-BLOCKING
--------------------------------------------------------------------------------

Tier B (functional + browser) is triggered ONLY by ui-tests.yml's own
`schedule` (daily cron "0 5 * * *") and `workflow_dispatch` — it is NOT referenced
by test.yml, so it can NEVER gate a PR (non-blocking BY CONSTRUCTION, matching
RESULTS/04 §6's "non-PR-blocking by construction").

  * Nightly no-commit guard: the `prepare` job sets `run=false` when
    `git log --since='24 hours ago'` is empty on a `schedule` event, and the `ui`
    job is `if: needs.prepare.outputs.run == 'true'` — an idle repo boots no VM.
    On dispatch/call, `run` is always true.
  * The daily schedule runs DEFAULT_SCHEDULE_TIERS="functional browser" (Tier B).
  * §7 BROWSER DEMOTE/DROP — ONE-LINE SWITCH (documented in the workflow header +
    inline): drop `browser` from DEFAULT_SCHEDULE_TIERS in the `prepare` step to
    stop the nightly browser leg without touching anything else. (Per RESULTS/04
    §6 the browser tier is already non-blocking; the §7 reliability numbers are
    CI-measured and the demote/drop is applied on the first evidence.)
