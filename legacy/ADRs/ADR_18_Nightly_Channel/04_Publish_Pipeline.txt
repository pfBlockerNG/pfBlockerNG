WHY THIS PHASE EXISTS
GitHub Pages allows ONE deployment per repo (§1 Context 6) — a second publish workflow would
clobber ADR-17's release catalog. So the nightly catalog MUST be produced by the SAME
`repo-publish` deploy. The nightly has no Release to derive from, so the durable store is a
dated pre-release (`nightly-YYYYMMDD`), mirroring ADR-17's "derive over durable Release
assets" exactly. The "don't publish unless `devel` changed" rule reuses `repo-install.yml`'s
existing last-successful-run gate (§1 Context 2).
