WHY THIS PHASE EXISTS
Phase 1 proved a `-NIGHTLY` package with a date version + named conflict behaves on a box.
The publish pipeline (Phase 4) must produce that package reproducibly from `devel` HEAD.
Today `scripts/build-pkg-portable.py` names the package from `PORTNAME` verbatim (`:937`,
`:1166`), versions it from `PORTVERSION` (`compute_pkgversion`, `:1090`) with NO override,
and `make_manifest` (`:935-958`) emits NO `conflicts` key. This phase adds the minimal
override surface + the `conflicts` key, and PROVES a release build is byte-identical to
before (the contract, §2 "Semantics that MUST be preserved").
