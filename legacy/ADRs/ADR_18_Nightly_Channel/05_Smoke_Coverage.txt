ACTION PLAN (ordered — transitions, both branches; build the pkg via the real builder)
1. Helper: produce a builder-made nightly pkg (`--channel nightly --pkgversion <date>
   --annotate commit=<sha>`) and a hermetic `nightly/<ABI>/` catalog via
   `build-repo-portable.py`; ship the subtree to the VM (reuse `build_repo_via_portable`).
2. INSTALL the nightly (no `-f`): absent → `pkg install pfSense-pkg-pfBlockerNG-NIGHTLY`
   installs from the nightly repo (`%R == pfblockerng-nightly`), deps resolve, every
   registered file lands, `pkg info -A` shows `commit=<sha>`, pfBlockerNG runs. Before/after.
3. CONFLICT-AND-REPLACE (both directions): `-devel` installed → installing `-NIGHTLY` is a
   NAMED conflict that replaces it (`%n` `-devel` → `-NIGHTLY`); reverse install replaces
   back. Assert both befores + afters; registry consistent (`pkg check -s`).
4. DATE `pkg upgrade` (≥ 3 versions): nightly catalog with only `<date1>` → `%v == <date1>`;
   rebuild `<date2>` → upgrade moves it; rebuild `<date2>.HHMMSS` → upgrade moves it again.
   Three real before ≠ after transitions; monotonic.
5. SHIPPED bootstrap: exercise `add-repo.sh nightly` end-to-end against the hermetic catalog
   (writes the conf, `pkg update`, installs). Add the gated dispatch-only real-URL leg

6. Branch coverage + intent-named BDD specs for the non-trivial cases (Given/When/Then). VM
   left CLEAN (`finally`/CaseContext). Long cases get an explicit `@pytest.mark.timeout(...)`.
