EXPECTED RESULTS — PINNED TO SOURCE (verified, not guessed)
-------------------------------------------------------------------
DNSBL python mode (dnsbl_python + pfb_py_block):
  - The WHOLE feed is renamed raw -> pfb_py_data.txt as EXACT entries
    (inc:8966-8970). Zone files are produced ONLY by the out-of-scope TLD feature
    (tld_analysis(), inc:2684). So python mode = EXACT match only.
  - evaluate_domain() (pfb_unbound.py:1707) looks the name up in dataDB EXACTLY
    -> NXDOMAIN for a hit. find_zone_match()/iter_domain_suffixes (pfb_unbound.py
    :1607/1614) is the WILDCARD path but it consults zoneDB, which is empty in
    non-TLD python mode -> a subdomain of an exact entry is NOT blocked. (This is
    why the exact case gives the subdomain a control local-data to prove the pass
    hermetically.)
DNSBL unbound mode (dnsbl_unbound):
  - Each domain becomes `local-zone: "<d>" redirect local-data: "<d> 60 IN A
    <sink>"` (feed path inc:8670; TLD/redirect path inc:3069). An Unbound redirect
    zone is a WILDCARD: it answers for the apex AND every subdomain depth — hence
    the wildcard case probes both apex and a.b.<d>.
  - logging='disabled' -> sink 0.0.0.0 / ::0 (NULL; inc:3000/8668).
    logging='enabled' (or '') -> sink pfb_dnsvip4 (VIP).
WHITELIST: whitelist_check_domain (pfb_unbound.py:1631) short-circuits in
  evaluate_domain BEFORE null_blocking/shape -> resolves via control local-data.
DNSBL-IP dual-stack: IP literals in a DNSBL feed split by family into
  <header>_v4.ip / _v6.ip (inc:8596-8617, 8688-8702), merged into DNSBLIP_v4.txt
  / DNSBLIP_v6.txt (inc:8869-8931), loaded into alias tables suffixed per family
  pfB_DNSBLIP{_v4,_v6} (inc:9306/9903). Enabled by CFG_DNSBL_SETTINGS/action !=
  'Disabled' (inc:7022). Each table holds only its own family.

HOW TO ADD A CASE (the case_spec recipe)
-------------------------------------------------------------------
1. Register the feed body in-memory (hermetic; no fixture file needed):
       feed_url = mock_feeds.register("smoke_<name>.txt", "<body lines>\n")
   (mock_feeds is a function-scoped fixture; the guest fetches it over SLIRP at
   http://10.0.2.2:<port>/<name>.)
2. Build a spec:
   DNSBL:
       spec = h.DnsblCase(
           aliasname="<alias>", feed_url=feed_url, header="<hdr>",
           mode=h.DnsblMode.{NXDOMAIN|NULL|VIP},   # response shape (see map)
           whitelist=["<d>"],                      # optional suppression
           dnsbl_ip_action="Deny_Both",            # optional: DNSBL-IP feature
           control_local_data={"<name>": {"A": "<ip>", "AAAA": "<ip6>"}},
       )
   IP:
       spec = h.IpCase(aliasname="<alias>", feed_url=feed_url, header="<hdr>",
                       action="Deny_Both", family="v4"|"v6")
3. Run it through the composed loop (auto reload verb: updatednsbl / updateip;
   override scope= for cases that need the full `update`, e.g. DNSBL-IP):
       with h.CaseContext(deployed_vm, spec[, scope="update"]):
           ans = h.dns_probe(deployed_vm, "<name>", "A"|"AAAA")
           assert h.is_nxdomain(ans) / h.is_null_ip(ans[, "::0"]) /
                  h.is_vip(ans) / h.resolves_to(ans, "<ip>")
           members = h.pfctl_table_members(deployed_vm, "<table>")
           assert h.member_present(members, "<ip>")
           assert h.rule_references(deployed_vm, "<table>")
   __exit__ runs reset() (clearip+cleardnsbl + forced update) -> next case from
   baseline.
4. RESPONSE-MODE MAP (DnsblMode -> config):
       NXDOMAIN : dnsbl_python + pfb_py_block (EXACT match; no subdomain block)
       NULL     : dnsbl_unbound, logging='disabled' (redirect zone -> 0.0.0.0/::0)
       VIP      : dnsbl_unbound, logging='enabled'  (redirect zone -> pfb_dnsvip4)
   VIP cases need SMOKE_DNSBL_VIP4 to match the baked image's pfb_dnsvip4
   (default 10.10.10.1).
5. New module fixture deployed_vm exists in both test_smoke_helpers.py and
   test_smoke_matrix.py (module-scoped: deploy the .pkg once per module).

SURPRISING pfBlockerNG BEHAVIOUR (candidate bugs — NOT fixed here)
-------------------------------------------------------------------
None found. One worth flagging as a SEMANTIC GOTCHA (NOT a bug):
  - In DNSBL *python* mode WITHOUT the TLD feature, EVERY feed domain is an EXACT
    (dataDB) entry — there is NO wildcard/subdomain blocking. Operators expecting
    a plain blocklist domain to also block its subdomains in python mode would be
    surprised; wildcard blocking requires either Unbound mode (redirect zone) or
    the TLD feature. This is intended pfBlockerNG behaviour (matches pfb_unbound.py
    + inc:8966-8970), pinned by test_dnsbl_exact_nxdomain. If a future ADR wants
    python-mode wildcards, that's a src/ change for a separate PR — out of scope
    here.
