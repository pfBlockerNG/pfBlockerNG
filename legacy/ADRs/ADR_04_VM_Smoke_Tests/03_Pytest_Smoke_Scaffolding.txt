WHY THIS PHASE EXISTS
The harness needs a clean separation: the normal `python -m pytest` (everyone's unit
suite) MUST stay exactly as today — no VM, no new deps, no failures — while a separate
`pytest -m smoke` (only in the smoke workflow, which has KVM + the GHCR image) runs the
VM tests. This phase builds that boundary and the VM lifecycle so Phases 4-5 only write
test bodies, not infrastructure.

3. VM FIXTURE (`tests/smoke/conftest.py`, session-scoped): `oras pull` the GHCR image
   BY DIGEST (ref from 02_Results.txt) → boot via the Phase-1 qemu/hostfwd invocation ON AN
   EPHEMERAL COPY-ON-WRITE OVERLAY so the base qcow2 is NEVER mutated (either
   `-drive …,snapshot=on` = auto-discarded on qemu exit, or `qemu-img create -b base -F

   target, ssh key, dns host+port, feed base url 10.0.2.2:<port>} → teardown (kill qemu,

   safely; the SAME hardcoded MAC is fine (each user-net VM is its own isolated SLIRP NAT,
   no shared L2); the ONLY contention is `hostfwd` host ports — fixed is OK across GH jobs
   (each job = its own runner), but allocate per-instance ports if several VMs run on one
   runner. Decide and DOCUMENT the per-case isolation strategy: fresh boot per case is
   simplest but slow; prefer a snapshot-revert or a `clearip`/`cleardnsbl`+reload reset
   (Phase 4 provides the reset). State the choice in the handoff.
4. MOCK FEED SERVER FIXTURE (stdlib `http.server`, no third-party): serves fixture
   files (IP lists, DNSBL lists) from a tests/smoke/fixtures dir on a port reachable
   by the guest at http://10.0.2.2:<port>/<name>. Function/module scoped as needed.
   HERMETIC GUARD (egress block): the workflow blocks the runner's outbound *after* the
   GHCR pull — the 10.0.2.2 feed path is SLIRP-internal (loopback on the runner) so it
   survives, while real internet + the SLIRP DNS upstream 10.0.2.3 go dark. Sequence is
   pull -> block -> boot/deploy/run (Phase 6 wires the actual block; here just don't
   assume real egress).
5. TRIVIAL SMOKE TEST (`tests/smoke/test_smoke_boot.py`, `@pytest.mark.smoke`): boot
