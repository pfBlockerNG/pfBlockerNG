ACTION PLAN (ordered — transition asserts, befores AND afters, by value)
1. READ-OUR-LATEST without `-r pfSense`:
   - GIVEN our build installed from a hermetic `file://` catalog (reuse the ADR-17
     helper), with a SECOND hermetic catalog carrying a HIGHER version of the same
     package name. Write our repo conf (priority above any decoy), `pkg update -r
     <ourrepo>`.
   - WHEN `pkg rquery -r <ourrepo> '%v' <pkgname>` and `pkg query '%v' <pkgname>`.
     THEN rquery returns the catalog's higher version, query returns the installed —
     and prove the read did NOT touch the `pfSense` repo: assert no `pfSense-repo-setup`
     side effect / the `pfSense` repo conf is unchanged, and that `-r <ourrepo>` alone
     answers (a `pkg rquery` WITHOUT `-r` is not required and must not be relied on).
   - This is the §7 premise-1 gate.
2. IDEMPOTENT file_notice from a cron-like context:
   - WHEN `file_notice('pfBlockerNG', "pfBlockerNG <ver> available (devel)",
     'pfBlockerNG', '/pfblockerng/pfblockerng_software.php', 1)` is invoked once (drive
     it via `pfSsh.php`/php-cli on the box). THEN exactly one matching row appears in
     `get_notices()` (assert before: absent; after: present once).
   - Prove DE-DUPE is a CALLER concern: invoking again for the SAME version must be
     suppressible by caller-side last-notified state (demonstrate the pattern: store
     last-notified version in a file, only call file_notice when latest != last). Show
     two ticks at the same version => one notice; a higher version => a second notice.
   - This is the §7 premise-2 gate.
3. SAME-CHANNEL upgrade from our repo (confirm ADR-17 still holds for this pkg name):
   - GIVEN installed version N from our hermetic catalog; rebuild the catalog to N+1.
   - WHEN `pkg upgrade -y <ourpkg>`. THEN `pkg query '%v'` advances N -> N+1 and
     `pkg query '%R' <ourpkg>` shows OUR repo. Assert before and after.
   - This is the §7 premise-3 gate (degrade-not-reject if it fails).
4. Land minimal `repo`-marked cases (in tests/smoke/test_repo_install.py or a sibling
   tests/smoke/test_software_update.py) — deselected from `-m smoke`. Use

   cases an explicit `@pytest.mark.timeout(...)`; CLOSE any notice you raised.
5. Record the VERDICT in RESULTS/01_Results.txt: GO only if (1) reads our latest via

   `pkg`/notice output, per §7.
