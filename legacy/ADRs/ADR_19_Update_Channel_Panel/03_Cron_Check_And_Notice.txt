WHY THIS PHASE EXISTS
The notice must fire WITHOUT a page load, so a background check is required; pfBlockerNG
already runs `pfblockerng.php cron` (§1.7) — piggyback it, no new scheduler. The IO is
isolated behind a thin wrapper so the orchestration stays unit-testable (the wrapper is
doubled in PHPUnit; the live legs are Phase-5 smoke). pkg access MUST respect base pkg
locking + DNS availability or it stalls cron (§3 risks).

ACTION PLAN (ordered)
1. Thin IO wrapper in pfblockerng.inc (the ONLY new code that shells to pkg):
   - `pfb_pkg_installed_name()` -> the installed pfBlockerNG package name (e.g. via
     `pkg query '%n'` filtered to our prefix), feeding `pfb_channel_from_pkgname`.
   - `pfb_pkg_repo_name_for_channel($channel)` -> 'pfblockerng' | 'pfblockerng-devel' |
     'pfblockerng-nightly' (mirror add-repo.sh conf names).
   - `pfb_pkg_latest($pkgname, $reponame)` -> `pkg update -r <repo>` (best-effort) +
     `pkg rquery -r <repo> '%v' <pkgname>`; '' if the repo/conf is absent or pkg locked.
   - `pfb_pkg_installed_version($pkgname)` -> `pkg query '%v' <pkgname>`.
   - GUARDS: if `is_subsystem_dirty('pkg')` or `!get_dnsavailable()`, do the network
     part NOT — return cached/empty and let the orchestrator serve cache.
2. Orchestrator `pfb_software_update_check($force = false)`:
   - Detect channel from installed name; compute repo name; read installed + latest.
   - Read the cache file (e.g. `/var/db/pfblockerng/software_update.json`:
     channel, installed, latest, last_checked, last_notified).
   - Decide via Phase-2 `pfb_should_notify(installed, latest, last_notified, knob,
     channel)`; if true -> `file_notice(...)` (id/category from P1) and set
     last_notified = latest. Always refresh installed/latest/last_checked in the cache.
   - `$force` (the page "Check now") bypasses any cache-freshness short-circuit.
3. Wire into cron: call `pfb_software_update_check()` from the `pfblockerng.php cron`
   path (NOT on every sync — once per cron tick is enough). Do NOT block or slow the
   feed cron: guard + best-effort, swallow IO errors (log, never throw).
4. Register the `pfb_software_notify` field default in pfblockerng.xml
   (`default` resolving per channel via the helpers; values default|on|off).
