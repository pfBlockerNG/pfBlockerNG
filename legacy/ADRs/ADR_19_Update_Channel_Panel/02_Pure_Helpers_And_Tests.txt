silently break it. These helpers are usable off-appliance (the PHPUnit suite loads the
real pfblockerng.inc via doubles — tests/php/README.md).

ACTION PLAN (ordered — pure functions, then exhaustive PHPUnit)
1. Add PURE helpers to pfblockerng.inc (no IO):
   - `pfb_channel_from_pkgname($name)` -> 'stable' | 'devel' | 'nightly' | null.
     Map `pfSense-pkg-pfBlockerNG` -> stable, `…-devel` -> devel, `…-NIGHTLY` ->
     nightly (the ADR-18 name); unknown -> null.
   - `pfb_update_available($installed, $latest)` -> bool via `pkg_version_compare`
     (latest > installed). Handle empty/invalid inputs safely (no update).
   - `pfb_notify_default_for_channel($channel)` -> bool: nightly => true, else false.
   - `pfb_should_notify($installed, $latest, $last_notified, $knob, $channel)` -> bool:
     the state machine. Resolve effective-notify = ($knob==='on') ? true :
     ($knob==='off') ? false : pfb_notify_default_for_channel($channel). Notify ONLY
     when effective-notify AND pfb_update_available($installed,$latest) AND
     ($latest !== $last_notified). (De-dupe is by last-notified version, per P1.)
2. PHPUnit (tests/php/) — EVERY branch, before-state asserted (CLAUDE.md "Test
   coverage"; [[feedback_tests_validate_not_cover]]). Trivial maps get plain
   intent-named asserts; the de-dupe machine gets a BDD Scenario + Given/When/Then:
   - channel map: each of the three names -> channel; an unknown -> null.
   - available: newer->true, equal->false, older->false, empty->false.
   - default-by-channel: nightly->true; stable->false; devel->false.
   - should_notify matrix: knob on/off/default x channel x available/not — assert the
     OFF default for stable/devel (no notify even when available) PAIRED WITH the ON
     default for nightly (notify when available) so green proves it is a real branch,
     not an always-value path.
   - de-dupe lifecycle (BDD): GIVEN last_notified empty + a newer latest -> notify;
     WHEN last_notified set to that latest, same tick repeats -> do NOT notify; WHEN a
     yet-newer latest arrives -> notify again. Assert the before-state each step.
