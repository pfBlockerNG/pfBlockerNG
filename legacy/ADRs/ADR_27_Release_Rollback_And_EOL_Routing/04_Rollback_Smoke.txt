ACTION PLAN (BDD; assert BEFORE + AFTER — a real lifecycle, contract §2.2)
1. Build a multi-version release catalog on the runner (reuse the re-version helper to forge two
   versions of the box's OWN variant package, e.g. _lo and _hi), ship + add-repo.
2. GIVEN: pkg update; THEN `pkg install <name>` (no version) installs the HIGHER version (newest-wins).
3. WHEN: `pkg install <name>-<loversion>` (pinned older); THEN the LOWER version is now active
   (pkg_installed_version), origin is our repo (pkg_repo_origin), and RUN_DEPENDS resolved (no
   "Missing dependency"). This is the rollback assertion.
4. THEN re-upgrade: `pkg upgrade` returns to the higher version (lifecycle closed).
5. If step 3 cannot work via the catalog (only `pkg add <raw-url>` with no dep resolution does), record
   it explicitly in the handoff as a REJECT/rescope trigger (ADR §7) — do NOT fake a pass.
