batch changes behind a separate apply schedule. Switch to apply-on-change and collapse the old
explicit apply-schedule reconciliation to a single OPTIONAL "quiet hours / maintenance window" knob
for operators who still want batching. CALL ADR-40/10's apply paths — do not reimplement them.

ACTION PLAN (red→green)

   immediately via ADR-40 (IP scope) / ADR-10 (DNSBL scope). No change ⇒ no apply (unchanged from

2. Add an OPTIONAL quiet-hours/maintenance-window knob (PfbConfig, ADR-29): when set and the current
   time is OUTSIDE the window, a detected change is RECORDED as pending and DEFERRED; the next tick

3. Remove the now-redundant explicit apply-schedule reconciliation that Phase 4 left in place (the old
   separate "when to apply" path), keeping only the window knob.
4. Tests (red→green):

     first tick inside the window.
   - No change ⇒ no apply (regression guard).
   - Clock-injected window-boundary cases (just-before / just-after the window edge).
   - Smoke (live): a real feed change applies on the tick WITHOUT a manual Force; with a window set
