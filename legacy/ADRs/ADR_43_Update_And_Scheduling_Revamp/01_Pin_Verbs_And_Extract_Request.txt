WHY THIS PHASE EXISTS
The reload entrypoint overloads one `$cron` string with three concerns — trigger identity,
scope (ip/dnsbl/both), and force-vs-reuse — and `pfb_trigger()` (inc:3170) exists only to
RECOVER the trigger the string threw away. Before refactoring this live wire (HA-sync, the
smoke PFB_CLI, the GUI all depend on it), pin every current verb→behaviour mapping as an
oracle, so Phase 3's API swap changes a small, fully-pinned surface (the ADR-01 lesson: prep
is independently valuable even if a later arm is narrowed).
