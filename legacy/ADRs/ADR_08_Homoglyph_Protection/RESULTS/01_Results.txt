3. THE FINALISED RULE
---------------------
  CONFUSABLE SCRIPT SET = { Latin, Cyrillic, Greek }   (the mutually-confusable trio)

  MALICIOUS (default block): a single label whose RESOLVED script set contains
    >= 2 of {Latin, Cyrillic, Greek}. i.e. Latin+Cyrillic OR Latin+Greek OR
    Cyrillic+Greek (NOT Latin-anchored — Cyrillic+Greek qualifies). Verified TP
    on all 5 homograph labels incl. the pure Cyrillic+Greek xn--mxa00ab.

  PER-LABEL GRANULARITY (load-bearing): analyze EACH dot-separated label with
    its OWN resolved set; a name is malicious iff SOME label is. NEVER union
    scripts across the dot. Proven necessary by example.рф: per-label legit,
    whole-name union = {Cyrillic,Latin} = malicious (a false positive). Also
    catches subdomain homographs (раypal.example.com).

  LEGIT ALLOW-SET (UTS#39 Highly Restrictive): single script (incl. all-Latin/
    -Cyrillic/-Greek) OR Latin + CJK companions {Han, Hiragana, Katakana,
    Hangul, Bopomofo} (Jpan/Kore/Hanb). Common/Inherited transparent (digits/
    hyphen contribute no script). These NEVER blocked in Confusable mode.

  SUSPICIOUS (alert; block opt-in, default OFF): multi-script that fails Highly-
    Restrictive but isn't the malicious pair — e.g. Latin+Armenian, Latin+
    Cherokee, Latin+Coptic.

  CHEROKEE / ARMENIAN / COPTIC DECISION: kept OUT of the malicious set ->
    SUSPICIOUS tier. Rationale: they confuse with Latin but (a) are not part of
    the high-confidence mutually-confusable trio the authorities single out, and
    (b) have legitimate single-script use; folding them into "block by default"
    risks FP without a measured TP need. Suspicious/alert is the safe home;
    operators can escalate. (Revisit only if a future FP/TP corpus shows a real
    attack class we miss.)


4. SCRIPT vs SCRIPT_EXTENSIONS DECISION
---------------------------------------
  Use SCRIPT_EXTENSIONS when a codepoint has it, else the Script property; then
  drop Common + Inherited as TRANSPARENT (they carry no script identity). This
  is the UTS#39 resolved-script-set definition.

  WHY it matters for our cases: a char shared by several scripts (e.g. many
  punctuation/diacritic codepoints, the Arabic/Syriac shared marks, CJK shared
  punctuation) is Common/Inherited under the plain Script property but carries a
  Script_Extensions LIST. Taking the plain Script alone would either (a) mis-
  attribute a shared mark to a single script, or (b) leave it Common when it
  should narrow. For THIS corpus the two agree on every LETTER (each letter has
  a single owning script), and the only Common chars are digits/hyphen (dropped
  either way) — so the corpus numbers are identical under both. But the shipped
  Phase-4 analyzer MUST implement Script_Extensions: the intersection-with-the-
  running-set semantics (a char "belongs" if ANY of its extension scripts keeps
  the set restrictive) is what prevents a future FP on a legit name using a
  shared mark. Ship BOTH tables; resolve via Script_Extensions-first.


5. PUNYCODE DECODE CONFIRMATION + EDGE HANDLING
-----------------------------------------------
  Decoder: label[4:].encode("ascii").decode("punycode")  — the RAW 'punycode'
  codec (NOT 'idna'; 'idna' adds IDNA2003 validation that THROWS on analyzable
  attack labels). Confirmed on EVERY corpus label.

  Edge behaviour (measured, edge_decode section):
    - xn--          -> '' (empty, ok)
    - xn--a         -> '\x80' (control char, ok — flagged downstream as Unknown)
    - xn--zz        -> raises UnicodeDecodeError ("incomplete punycode string")
    - xn--0         -> raises UnicodeDecodeError
    - xn--ls8h      -> '💩' (ok)
    - xn--google    -> '䕮䕵䕶䕱' (decodes to junk CJK, ok)
    - a non-ASCII byte in the A-label (cannot occur on the DNS wire) raises
      UnicodeEncodeError at .encode("ascii").
  CONTRACT for the shipped analyzer: wrap decode in
    try: ... except (UnicodeDecodeError, UnicodeError, ValueError): flag+skip.
  These are the exception types observed; the resolver MUST NEVER propagate a
  decode error. The measurement gate fails if any label raises an UNCAUGHT
  exception — it does not.
