------------------------------------------------

  Verbatim RESULTS block:

    FP (legit/suspicious wrongly -> malicious): 0 / 20 legit-tier labels
    TP (homographs caught):                    6 / 6
    Punycode decode safe (no uncaught raise):  True
    Analyzer cost per xn-- label:              ~0.70 us
    CJK FP (must be 0):                        0
    IDN-ccTLD per-label FP (must be 0):        0

    GATE: GO

  Kill-threshold (RESULTS/01 section 6): GO requires malicious-tier FP == 0 on the
  legit set (CJK + IDN-ccTLD MUST be 0) AND TP == all homographs AND decode-safe.
  MET WITH MARGIN. No narrowing taken — the rule shipped exactly as finalised in
  Phase 1 (>=2 of {Latin,Cyrillic,Greek} per label; per-label, never cross-dot union;
  Cherokee/Armenian/Coptic -> suspicious tier; whole-script all-Cyrillic NOT caught,
  documented limitation). The on-branch number matches the Phase-1 de-risk exactly
  (no drift after the analyzer + matcher wiring landed).

  Per-tier confirmation from the measure output (all as expected):
    - LEGIT single-label (15): all -> legit (CJK, single Cyrillic/Greek, Latin-accented,
      Arabic, Thai, Hebrew, Devanagari, ASCII).
    - LEGIT IDN-ccTLD (2): example.xn--p1ai / site.xn--fiqs8s -> per-label legit
      (wrong whole-name union of example.рф = {Cyrillic,Latin} WOULD be malicious; the
      per-label rule eliminates that FP class).
    - HOMOGRAPH (6): xn--pple-43d / xn--paypa-iof / xn--cope-f9d (Latin+Cyrillic),
      xn--ggle-0nda (Latin+Greek), xn--mxa00ab (pure Cyrillic+Greek, no Latin),
      xn--ypal-43d9g.example.com (subdomain) -> all malicious (TP 6/6).
    - SUSPICIOUS (3): Latin+Armenian/Cherokee/Coptic -> suspicious (alert tier, not
      a default block, not an FP).
    - LIMITATION: xn--80ak6aa92e (all-Cyrillic 'apple') -> legit (documented out-of-scope).
    - EDGE decode: xn--zz / xn--0 raise -> CAUGHT; xn-- / xn--a / xn--ls8h / xn--google
      decode fine. No uncaught raise.
