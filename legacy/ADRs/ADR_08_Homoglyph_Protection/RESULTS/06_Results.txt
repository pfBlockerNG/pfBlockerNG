2. THE UI CONTROL + SUB-TOGGLE LABELS/DEFAULTS
----------------------------------------------
  Select  'pfb_idn'  label "IDN Blocking"  options:
      ''           -> Off
      'all'        -> All-IDN
      'confusable' -> Confusable
    Help: "IDN handling (not Regex based). Off: no IDN action. All-IDN: block every
    IDN/'xn--' domain (blunt). Confusable: block only cross-script homoglyphs
    (Latin/Cyrillic/Greek mixes, including Cyrillic+Greek). Does not catch whole-script
    confusables or pure-ASCII typosquats."  (scope + the documented limitation)

  Checkbox 'pfb_idn_block_malicious'      label "Block clearly-malicious homoglyphs"
      DEFAULT ON.  Shown only under Confusable. Disable -> alert only.
  Checkbox 'pfb_idn_escalate_suspicious'  label "Block suspicious mixed-script"
      DEFAULT OFF (opt-in). Shown only under Confusable. On -> suspicious escalates
      alert->block.


3. dnsblconfig KEYS -> PLUGIN PYTHON-CONFIG (ini) MAPPING
--------------------------------------------------------
  dnsblconfig key                  normalized $pfb            ini [MAIN] key (value)
  ------------------------------   -----------------------    -------------------------------
  pfb_idn ('' | all | confusable;  dnsbl_idn (on->all)        idn_mode = {off|all|confusable}
    legacy 'on' migrates to all)                              python_idn = on  (ONLY when all)
                                                              python_idn = off (all other modes)
  pfb_idn_block_malicious (def on) dnsbl_idn_block_malicious  python_idn_block_malicious = on|off
  pfb_idn_escalate_suspicious(def  dnsbl_idn_escalate_susp.   python_idn_escalate_suspicious = on|off
    '')

  The three ini keys are EXACTLY what Phase 5 reads (RESULTS/05 section 2):
  pfb["idn_mode"], pfb["python_idn_block_malicious"], pfb["python_idn_escalate_suspicious"].

  'on' -> All-IDN migration AS IMPLEMENTED (the backward-compat contract, end-to-end):
    UI:   pconfig 'on' -> 'all' (renders All-IDN in the select).
    PHP read:  dnsblconfig 'on' -> $pfb['dnsbl_idn']='all'.
    PHP ini:   idn_mode='all' AND python_idn='on'  (the legacy flag stays set for All-IDN,
               preserving the python_blacklist side-effect + every All-IDN code path).
    Python:    explicit idn_mode='all' -> IDN_MODE_ALL; a pre-sync upgrade config with only
               python_idn=on (no idn_mode key) -> idn_mode_from_legacy(True)=ALL. Both ALL.
    Off:   empty/'off' -> dnsbl_idn='' -> idn_mode='off', python_idn='off' -> IDN_MODE_OFF.
  All-IDN and Off remain byte-identical to today; the All/Off arm (idn_mode_decision) is
  untouched. The ADR-08 mode-baseline + confusable-matcher tests stay green.


4. COUNTS / ALERTS SURFACING
----------------------------
  - All-IDN: DNSBL_IDN alias/count exactly as before (the `=='all'` arm).
  - Confusable: NEW DNSBL_Homoglyph + DNSBL_Homoglyph_Suspect aliases created in the
    same always-rebuilt-specials block (outside the feed loop, in alias_dnsbl_all so they
    survive the unused-alias cleanup). These GROUP names match the matcher's emitted
    group labels (RESULTS/05 section 3: IDN_GROUP_MALICIOUS="DNSBL_Homoglyph",
    IDN_GROUP_SUSPECT="DNSBL_Homoglyph_Suspect"), so Reports/Alerts render their counts.
  - Alerts page (pfblockerng_alerts.php): NO code change needed. A homoglyph block lands
    in the blocked-domain field (f2 / p_domain / CNAME f7), and the page ALREADY decodes
    ANY 'xn--' domain to "<xn--...> [<decoded-unicode>]" via idn_to_utf8 (~2259/2272/2281).
    The matcher's dual-form b_eval (RESULTS/05 section 4: "<a_label> [<decoded>] <scripts>")
    additionally carries the offending script in the log/feed column. The feed/group
    (fields[5]) renders generically, so DNSBL_Homoglyph / DNSBL_Homoglyph_Suspect display
    as-is. Decoded Unicode is therefore shown beside the xn-- form for homoglyph hits with
    no alerts-page edit.
