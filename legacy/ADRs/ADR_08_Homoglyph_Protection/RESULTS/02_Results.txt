2. DECISION-LABEL DRIVER API  (Phases 3/4/5 import this)
--------------------------------------------------------
Pure module-level functions in tests/test_adr08_decision_spec.py, no Unbound symbols.
The Phase-4 analyzer and the Phase-5 matcher MUST reproduce these results:

  decode_label(a_label: str) -> str
      Raw stdlib 'punycode' decode of one xn-- label. Non-xn-- returned unchanged.
      MAY raise (UnicodeDecodeError / UnicodeError / ValueError) on malformed input
      — callers catch it. NOT the 'idna' codec (idna's IDNA2003 validation REJECTS
      analysable edge labels the raw codec decodes, e.g. xn--a -> U+0080, xn-- -> '';
      pinned by TestPunycodeDecodeFidelity.test_decode_is_not_idna_codec).

  resolved_scripts(text: str) -> set[str]
      Per-label resolved script set for DECODED Unicode. Script_Extensions preferred,
      Common/Inherited transparent (dropped). A codepoint with no letter-script
      (control char / emoji) -> the UNKNOWN_SCRIPT sentinel (never silently a script).

  restriction_level(scripts: set[str], *, ascii_only: bool = False) -> str
      UTS#39 level; one of LEVEL_ASCII / LEVEL_SINGLE / LEVEL_HIGHLY_RESTRICTIVE /
      LEVEL_NON_RESTRICTIVE. The documented intermediate the severity reads.

  severity(text: str) -> str
      ONE decoded label -> SEV_LEGIT / SEV_SUSPICIOUS / SEV_MALICIOUS / SEV_FLAGGED.
      Never unions across the dot.

  analyze_label(a_label: str) -> LabelVerdict
      Decode-safe (NEVER raises). Frozen dataclass: a_label, decoded (None if decode
      raised), scripts (frozenset), severity, decode_error (exc type name or None).

  analyze_name(a_name: str) -> NameVerdict
      Splits on '.', analyses EACH label, name severity = the most severe label
      (PER-LABEL, never union across the dot). Frozen dataclass: a_name, labels
      (tuple[LabelVerdict]), severity.

  action(sev: str, *, block_malicious: bool = True, escalate_suspicious: bool = False) -> str
      Severity -> ACT_NONE / ACT_ALERT / ACT_BLOCK under the two ADR-08 sub-toggles.
      Raises ValueError on an unknown severity.

  Constants exported: CONFUSABLE_SET={Latin,Cyrillic,Greek}, CJK_COMPANIONS=
  {Hiragana,Katakana,Hangul,Bopomofo}, SEV_*, ACT_*, LEVEL_*, UNKNOWN_SCRIPT.


3. SEVERITY -> ACTION MAPPING (as encoded)
------------------------------------------
  legit       -> none    (resolve normally; never touched in Confusable mode).
  malicious   -> block   when block_malicious (DEFAULT-ON); -> alert when the
                         operator disables that sub-toggle.
  suspicious  -> alert   by default (escalate_suspicious DEFAULT-OFF); -> block
                         when the opt-in escalation sub-toggle is enabled.
  flagged     -> alert   by default; escalatable like suspicious. (See section 4.)

  Default toggles = (block_malicious=True, escalate_suspicious=False). The default
  severity->action map is the committed `action` column in decision_table.json and
  is asserted total over all four severities under BOTH toggle states
  (TestSeverityToActionMappingTotality).


4. BORDERLINE CALLS RECORDED (consistent with RESULTS/01)
---------------------------------------------------------
  a) Cherokee / Armenian / Coptic + Latin -> SUSPICIOUS, not malicious. Outside the
     high-confidence {Latin,Cyrillic,Greek} trio; legitimate single-script use;
     default-block would risk FP without a measured TP need. (Revisit only on a
     future corpus showing a real missed attack class.)
  b) Cyrillic+Greek with NO Latin -> MALICIOUS. The rule is ">=2 of the trio", NOT
     Latin-anchored (proven by xn--mxa00ab = сαр).
  c) FLAGGED (new severity introduced this phase): an undecodable label (malformed
     punycode, caught) OR a decoded label whose codepoints carry NO letter-script
     (empty xn--, control char xn--a -> U+0080, emoji xn--ls8h -> 💩) resolves to
     FLAGGED — NOT malicious (no confusable mix) but NOT silently legit either. It
     is surfaced (action=alert, escalatable) so anomalies are never silently passed,
     and the decode NEVER crashes the resolver. This is the action-mapping home for
     the ADR's "decode error caught + flagged" robustness contract.
     NOTE for Phase 4: the corpus.json edge_decode section labels these as decode
     SUCCESS/FAILURE only (no severity); the JUNK-CJK case xn--google decodes to
     single-script Han -> LEGIT (it has a real letter-script). The empty/control/
     emoji cases are the ones that land in FLAGGED.

  RESTRICTION-LEVEL collapse recorded: UTS#39 distinguishes Moderately/Minimally
  Restrictive/Unrestricted; ADR-08 does not — anything failing Highly Restrictive
  that isn't the malicious pair is "non_restrictive" -> suspicious. Pinned so a
  later phase can't silently reintroduce the finer levels.


5. THE WHOLE-SCRIPT LIMITATION (pinned as a no-op)
--------------------------------------------------
  xn--80ak6aa92e (аррӏе, all-Cyrillic 'apple' look-alike) is single-script ->
  passes restriction-level analysis -> severity LEGIT -> action NONE. Asserted as a
  deliberate NO-OP (TestWholeScriptConfusableNotCaught) so the documented out-of-
  scope limitation (ADR-08 §7) is pinned: if a future change started catching it,
  that test goes red and forces a deliberate decision. Mixed-script detection
  catches MIXED homographs only; whole-script + pure-ASCII typosquats are out of
  scope (need a confusables + protected-brand table, not built here).


6. TEST DESIGN (branch coverage, before-state, BDD — per CLAUDE.md)
-------------------------------------------------------------------
  - Branch coverage: every severity (legit/suspicious/malicious/flagged), every
    restriction level (ascii/single/highly-restrictive/non-restrictive), and BOTH
    states of each sub-toggle get their own failable assertion. The CJK FP-guard
    and the suspicious tier each assert the OFF side (it IS multi-script / it is NOT
    malicious) before the ON side (it is legit / it is suspicious) so green proves
    the rule branch, not an always-pass.

    asserts the WRONG whole-name union of example.рф {Cyrillic,Latin} WOULD be
    malicious, then that analyze_name keeps it legit — the FP the per-label rule
    eliminates.
  - Malformed-not-raised proven real: test_raw_decode_actually_raises_for_the_
    raising_rows asserts the raw decoder DOES raise on xn--zz/xn--0, so
    analyze_label's catch is load-bearing (not dead code).
  - Cross-checked against Phase-1: the oracle reproduces corpus.json's
    expected_severity for every single- and multi-label entry.
