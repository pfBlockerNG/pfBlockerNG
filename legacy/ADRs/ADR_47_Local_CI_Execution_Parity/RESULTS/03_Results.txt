AMENDMENT 2 — resolve-stamp job (release.yml)
  Added job resolve-stamp (needs: [prepare-release]), parallel with read-matrix.
  Checks out the SAME ref as build-pkgs-portable:
    ${{ github.event.inputs.dry_run != 'true' && github.event.inputs.tag || github.ref }}
  Emits created (tagged commit epoch) and commit (tagged SHA) as job outputs.
  build-pkgs-portable adds needs.resolve-stamp and gates on resolve-stamp.result == 'success'.
  portversion (ref-independent, derived from the tag string) stays in read-matrix and
  is emitted as a new output; the build loop consumes it via needs.read-matrix.outputs.portversion.

build-leg.sh CLI CONTRACT
  build-leg.sh [OPTIONS]
    --ports-repo  OWNER/NAME|URL     default: pfBlockerNG/FreeBSD-ports (→ GitHub HTTPS)
    --ports-ref   REF                default: pfblockerng/use-github
    --channel     devel|stable|nightly  default: devel
    --abi         ABI                default: FreeBSD:15:amd64
    --py-flavor   PYxx               default: py311
    --php         X.Y                default: 8.3
    --local-src   DIR                default: .
    --pkgversion  V                  optional; omit → builder uses ports Makefile
    --annotate    K=V                repeatable; each → --annotate to builder
    --ports-dir   DEST               optional; default is run-keyed
    --out-dir     OUT                optional; default is run-keyed

  Stdout: exactly one line — the resolved absolute .pkg path (AMENDMENT 1).
  Stderr: all progress, including sparse-clone step.

  Run-keying:
    RUN_ID already exported → used as-is (CI callers set via select-box.sh --print-id).
    RUN_ID absent + GITHUB_RUN_ID set → pfb_mint_run_id_ci (LEG slugged from ABI if not set).
    RUN_ID absent + GITHUB_RUN_ID absent → pfb_mint_run_id_local (local mode).
    PFB_RUN_DIR = ${PFB_RUN_DIR:-${PFB_RUN_ROOT:-/var/tmp/pfb-runs}/${RUN_ID}}

PARITY-GUARD RULES
  Rule 1: direct build-pkg-portable.py call in workflow YAML → violation
  Rule 2: direct sparse-clone-ports.sh call in workflow YAML → violation
  Rule 3 (amendment 4/5 teeth): an inline-derived arg fed to build-leg.sh — a command
    substitution $(...) OR a backtick positioned AFTER the build-leg.sh token on the
    same line → violation. Implemented by taking the substring AFTER the first
    build-leg.sh occurrence and testing THAT for $( or backtick. The legit capture
    wrapper PKG="$(sh scripts/build-leg.sh ...)" has its $( BEFORE the token (not
    flagged); an evasion build-leg.sh --pkgversion "$(release-version.sh ...)" has $(
    AFTER (flagged). Verified false-positive-free: parity-guard over the 3 real
    rewired workflows reports 0 violations (all use the BEFORE-token capture form).
  YAML comment lines (first non-space char = #) are exempt.
  Allowed: build-leg.sh calls whose args are GitHub ${{ ... }} or env-sourced $VAR/${VAR}.

  RESIDUAL (Verify floor — amendment 5; documented in parity-guard.sh header too):
    Rule 3 is LINE-scoped. A value derived on a PRIOR step/line or via an env: block
    and passed in as a bare $VAR is NOT provenance-tracked — full deny-by-default would
    need real shell/YAML parsing. The env-sourced case is pinned PASSING by the spec
    (the documented residual). Generalizing provenance tracking is a P5 item.
