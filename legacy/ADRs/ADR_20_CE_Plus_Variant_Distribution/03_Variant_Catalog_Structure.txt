WHY THIS PHASE EXISTS
Splitting manifests per variant (Phase 2) is useless without a catalog that serves
each pfSense version from a distinct URL path. This phase creates version-keyed
catalog dirs (`ce-2.8/${ABI}/`, `plus-26.03/${ABI}/`, etc.) on GitHub Pages and
generates a `routing.json` manifest that maps pfSense UA patterns to those dirs.
The Cloudflare Worker (Phase 5) fetches this manifest to route pkg requests; Phase 4's
`add-repo.sh` writes the Worker URL into the conf. Together they let the conf be
written once and never changed on pfSense upgrades.

The matrix may contain N CE + M Plus entries simultaneously (N, M ≥ 1) during
version-transition windows. `build-repo-portable.py --catalog-name ce-2.8` handles
one entry; the publish pipeline loops over all active entries.
