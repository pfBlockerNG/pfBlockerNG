WHY THIS PHASE EXISTS
The primary goal of this phase is to ensure the client conf is written with the
Cloudflare Worker URL (`pkg.pfblockerng.io/${ABI}`) so it NEVER needs to be re-run
when pfSense upgrades — the Worker re-routes automatically based on the UA. The
channel (`devel`/`stable`/`nightly`) is the only user argument; variant and pfSense
version are handled entirely server-side.

The fallback path (active ONLY if Phase 1 returned REJECT) writes a version-specific
direct GitHub Pages URL — this is the degraded mode where the user must re-run
`add-repo.sh` after a major pfSense upgrade.

     add-repo.sh after a major pfSense version upgrade`.
