ACTION PLAN (ordered — each case has befores AND afters, BDD-style spec)
1. CASE: CE install from `ce/${ABI}` (CI-runnable, `repo` marker):
   Scenario: CE package is installed from variant-correct `ce/${ABI}` catalog.
   Background: hermetic `file://` CE catalog at `ce/FreeBSD:15:amd64/` (built by
   `build_repo_via_portable(variant="CE", pkgs=[ce_pkg])`).
   Given: conf pointing to `ce/${ABI}`, no package installed.
   When: `pkg install -y <pkgname>` (via the CE catalog).
   Then: `pkg query '%d %v' <pkgname>` confirms `php83` dep satisfied, version N
         installed; `pkg query '%R' <pkgname>` shows our repo.
   Assert BEFORE: package not installed (`pkg query '%n' <pkgname>` returns empty).
   Assert AFTER: dep list contains `php83`, version matches catalog.

2. CASE: wrong-variant guard — CE VM, Plus catalog (CI-runnable, `repo` marker):
   Scenario: Installing a Plus package on a CE VM fails with unsatisfied dep.
   Background: hermetic `file://` Plus catalog at `plus/FreeBSD:16:amd64/` (built
   with `build_repo_via_portable(variant="Plus", pkgs=[plus_pkg])`).
   Given: conf pointing to `plus/${ABI}` (note: ABI mismatch — CE VM has FreeBSD:15;
          attempt install anyway to trigger the guard).
   When: `pkg install -y <pkgname>` (from Plus catalog; pkg resolves whatever ABI
         matches the repo URL).
   Then: `pkg install` returns a non-zero exit code AND the error output contains
         `php85` unsatisfied dep (or ABI mismatch error — either is an acceptable
         wrong-variant guard failure; assert the install DID NOT succeed).
   Assert BEFORE: CE package from `ce/${ABI}` installs CLEANLY (dep satisfied) —
   this proves the CE path is correct and the failure in the AFTER is caused by the
   variant mismatch, not an unrelated issue.
   Assert AFTER: `pkg query '%n' <pkgname>` confirms the package is NOT installed.

3. CASE: legacy `${ABI}/` path still serves CE build (CI-runnable, `repo` marker):
   Scenario: Old-conf CE box (pointing to legacy `${ABI}` path) still upgrades.
   Background: hermetic `file://` legacy catalog at `FreeBSD:15:amd64/` (no variant
   prefix — the Phase 3 `build_repo_via_portable()` without `--variant`).
   Given: conf pointing to legacy `${ABI}`, CE package version N installed.
   When: catalog bumped to N+1; `pkg upgrade -y <pkgname>`.
   Then: `pkg query '%v' <pkgname>` shows N+1; `pkg query '%R'` shows our repo.
   Assert BEFORE: version N installed; version N+1 available from catalog.
   Assert AFTER: version N+1 installed.

4. CASE (if Phase 5 GO — routing layer live): routing URL delivers CE/Plus correctly:
   Scenario: pkg fetch via routing URL gets variant-correct meta.conf.
   Background: conf pointing to the routing URL (`pkg.pfblockerng.io/${ABI}`).
   Given: CE VM; conf with routing URL; `pkg update -r <ourrepo>`.
   Then: the fetched `meta.conf` or packagesite contains only the CE package (no
         Plus package present). Verify by `pkg rquery -r <ourrepo> '%n' <pkg>` and
