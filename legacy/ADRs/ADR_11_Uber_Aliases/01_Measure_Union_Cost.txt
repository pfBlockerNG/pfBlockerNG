ROLE
You are on the `adr/11` branch performing Phase 1 of ADR-11. DE-RISKING measurement,
not a feature: characterise the cost of unioning the effective block set so we know
whether a full per-pass rebuild fits, or whether an incremental (rebuild-on-member-

numbers only. Work inline on `adr/11`, one commit, push directly (PR only if rejected).

WHY THIS PHASE EXISTS
The feature is already proven in production (the maintainer runs the union via an
external-script workaround), so this is NOT a viability gate — it is a COST gate that
decides the build strategy (full vs incremental) and the documented RAM caveat. The
union of all deny feeds can be millions of CIDRs; the loaded (unused) pf table costs
kernel memory, and cat+sort -u+cidr_aggregate costs pass time.
