## #281 surface

The pfb_keep default repair: the registry default 'on' matches the old ?? 'on' fallback
exactly. No stored-value change; no runtime behaviour change. The migration (pfb_keep_migrate)
seeds this into config.xml for existing installs (Phase 2); the runtime default via PfbConfig
is now formal, not scattered per-site. The #281 class is structurally closed.

## Watch-outs for Phase 5

- pfb_global() cron loop (pfb_min/pfb_hour/pfb_dailystart) still reads from $pfb['config']
  cache array after the section is readSection'd. Parity holds. Phase 5 can route these
  individually if desired, but it's not required for correctness.
- SafeSearch now goes fully through the gateway. The old code had explicit 'Disable' fallbacks
  in config_get_path; the registry defaults match ('Disable'). Confirmed by parity tests C.
- pfb_remove_config_settings() is now gateway-routed; deleteSection wraps config_del_path
  — same semantic, same behaviour. The pre-deinstall hook calls this unchanged.
- pfb['keep'] comparison at pre-deinstall: $pfb['keep'] != 'on' — now gets '' (PfbToggle::Off
  ->value) or 'on' (PfbToggle::On->value), same as before.
- www/ pages and install.inc writes NOT touched — Phase 5.
