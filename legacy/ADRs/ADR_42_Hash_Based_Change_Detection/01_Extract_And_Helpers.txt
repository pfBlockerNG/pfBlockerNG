ACTION PLAN (oracle tests FIRST — behaviour-preserving)
1. Add a `pfb_content_hash($path_or_data, $is_file = TRUE)` helper in pfblockerng.inc using
   `hash_file('xxh128', …)` / `hash('xxh128', …)`. Pure; no I/O side effects beyond reading.
2. Add a tagged persisted-hash helper pair:
   - read: given a base `{pforig}/{header}`, prefer `{base}.xxhash128` (compare with xxh128);
     else legacy `{base}.md5` or a bare/untagged digest (compare with md5); return (algo, digest).
     An unreadable/unknown tag → return a sentinel meaning "treat as changed" (downgrade-safe).
   - write: compute xxh128, write `{base}.xxhash128` (LOCK_EX), and `unlink_if_exists({base}.md5)`.
3. Add a `pfb_files_equal($a, $b)` file-vs-file helper — `cmp -s` via escaped exec (PFBL-01:
   precede with the appropriate validation; escapeshellarg both paths), returning bool.
4. Extract the local/remote change decision out of `pfb_update_check()` into a named pure-ish
   helper (inputs: paths + the validators it has) that returns the verdict, callable off-appliance.
   DO NOT change `pfb_update_check`'s live behaviour — call the extracted helper from it so the
   observable result is identical this phase.
5. Add PHPUnit tests in tests/php/ for: the extracted decision pinned on fixtures (oracle, matches
   today); round-trip (`write→read` equal); legacy `.md5` read; bare/untagged → md5; unknown tag →
   "changed"; and a KNOWN-ANSWER vector proving PHP `hash('xxh128', X)` equals the documented
   `xxh128sum` hex for the same bytes (pin the exact hex so a future drift is caught).
