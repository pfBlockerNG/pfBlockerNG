WHY THIS PHASE EXISTS
Today the reload scope is gated on which FEEDS were refetched, which (a) defers cross-list dedup
realignment of sibling tables to the next Force Reload and (b) makes reputation amplify one feed
change into an all-tables reload (ADR §1.2). Gating on each table's FINAL MEMBERSHIP SET instead
fixes both: a table reloads iff its set actually changed. Apply still via `-T replace` here — the
delta is Phase 4 — so this phase is a pure gating change, low risk.
