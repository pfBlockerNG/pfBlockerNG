## 4. Self-heal rc.d hook

Installed path:        /usr/local/etc/rc.d/pfblockerng_repo_selfheal.sh
Source (in repo):      scripts/rc.d/pfblockerng_repo_selfheal.sh
Installed by:          scripts/add-repo.sh (cp of the file shipped alongside it)

rc.d ordering:
  PROVIDE: pfblockerng_repo_selfheal
  REQUIRE: NETWORKING
  BEFORE:  pfblockerng unbound

HARD RULE: every code path ends in `exit 0`. The hook NEVER wedges boot.

Logic on each boot:
  a. GUARD: if neither PFB_RELEASE_CONF nor PFB_NIGHTLY_CONF exists → return 0 (inert).
  b. Source PFB_DETECT_HELPER (the detection helper installed alongside the hook).
  c. For each present conf: parse <varver>/<arch> from the url: line.
  d. Detect the box's current <varver>/<arch> via pfb_detect_catalog().
  e. MATCH → return 0 (no-op; zero pkg calls; fast path on every normal boot).
  f. MISMATCH → rewrite only the <varver>/<arch> segment of the url: line in-place
     (every other byte is preserved); run `pkg update -r <repo>`; reconcile the
     pfBlockerNG package (install/upgrade). All pkg failures are logged and swallowed.

Testable env overrides (all default to on-box paths):
  PFB_DETECT_HELPER  (default /usr/local/lib/pfblockerng/detect_variant.sh)
  PFB_RELEASE_CONF   (default /usr/local/etc/pkg/repos/pfblockerng.conf)
  PFB_NIGHTLY_CONF   (default /usr/local/etc/pkg/repos/pfblockerng-nightly.conf)
  PFB_PKG_BIN        (default /usr/local/sbin/pkg)

## 8. Deviations from the brief

None. All deliverables per 02_AddRepo_And_Hook.txt implemented as specified.

Notable implementation details:
- _parse_catalog_from_conf() uses sed (not parameter expansion) to extract the URL
  from the conf's url: line, avoiding \"  inside ${...} which is not POSIX-portable
  in dash (the sh on this CI runner).
- add-repo.sh installs the hook via `cp` (not a heredoc) — the hook lives as a
  standalone file at scripts/rc.d/pfblockerng_repo_selfheal.sh in the repo, and
  cp preserves it byte-for-byte on the box.
- --catalog-path <varver>/<arch> was added to all three generators to enable
  deterministic byte-identity tests without needing a live pfSense box.

## 10. Post-ADR follow-up — piped-invocation fix (branch fix/add-repo-embed-hook)

The Phase-2 note above ("add-repo.sh installs the hook via `cp` — the hook lives as a
standalone file") describes the checkout case correctly, but the published one-file
bootstrap breaks when piped: `$0` is `sh` (not the script path), so
`dirname "$0"` resolves to the shell's directory (`/root`, `/tmp`, etc.) and
`HOOK_SRC` points at a non-existent path → `cp` fails with "No such file or directory".

Fix committed on branch fix/add-repo-embed-hook:

  scripts/add-repo.sh        — pfb_emit_embedded_hook() stub; install block now
                               `if [ -f "${HOOK_SRC}" ]; then cp ...; else emit > ...; fi`
  scripts/gen_landing.py     — write_add_repo() splices the hook via a single-quoted
                               heredoc between PFB_EMBED_{BEGIN,END} markers;
                               write_site() calls it → site/add-repo.sh is self-contained
  tests/test_gen_landing.py  — BDD test: pipes published add-repo.sh via stdin to sh,
                               asserts hook installed + conf written with the marker

Public landing page one-liners updated from:
  fetch -qo - https://raw.githubusercontent.com/.../scripts/add-repo.sh | sh
to:
  fetch -qo - https://pfblockerng.github.io/pkg/add-repo.sh | sh

(self-hosted, self-contained, always in sync with the published catalog).

Phase 3 is NOT blocked on any Phase 2 item.
