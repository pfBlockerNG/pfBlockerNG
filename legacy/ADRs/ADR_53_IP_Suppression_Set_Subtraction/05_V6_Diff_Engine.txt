WHY THIS PHASE EXISTS
IPv6 suppression is impossible by host enumeration (/64 - /128 = 2^64 hosts)
and iprange MANGLES v6 input (proven — parses '2001:db8::/64' as hostname
'2001'; ADR §1.2). But covering-CIDR subtraction costs only (b - a) entries
(/64 - /128 = 64), and pfSense already ships the emitter:
ip_range_to_subnet_array() (util.inc; stubbed at stubs/pfsense/util.php:150)
handles v6 natively via fixed-width binary-string math. This phase builds the
pure engine; Phase 6 wires it.

ACTION PLAN
1. Tests FIRST (red) — tests/php/V6CidrSubtractTest.php against the
   not-yet-existing functions:
   a. pfb_cidr_subtract_v6(array $cidrs, array $holes): array — known vectors:
      - ['2001:db8::/64'] minus ['2001:db8::5353/128'] -> exactly 64 covering
        CIDRs; the hole absent; a sibling (::5352, ::5354) covered;
      - hole == entry -> entry removed entirely;
      - hole outside every entry -> input set unchanged (set-wise);
      - two adjacent /128 holes in one /64; two holes in different entries;
      - hole CONTAINING an entry (suppress /48, feed /64 inside) -> entry gone;
      - full suppression of every entry -> [] (legitimately empty);
      - malformed token in either array -> token skipped + reported (return
        shape/by-ref errors — design it, keep it simple), never a throw that
        aborts the whole file.
   b. SET-EQUIVALENCE property check on randomized-ish fixed-seed cases: verify
      via an INDEPENDENT representation — expand result + holes + input to
      (start,end) pairs using inet_pton hex strings compared lexically (NOT the
      engine's own helpers) — result ∪ holes ⊇ input, result ∩ holes = ∅,
      result ⊆ input.
   c. pfb_suppress_file_v6(string $file, string $suppfile): bool — streaming
      rewrite: atomic tmp+rename publish on success; missing/unreadable inputs
      -> FALSE + previous file intact; empty result -> empty file published
      (the §2.2 empty-is-legit contract); non-IP lines dropped + logged.
   d. Vector-pin the ip_range_to_subnet_array double itself (e.g. the
      documented pfSense behaviour on a v4 range and a v6 range) so a stale
      double fails loudly.
