DEVIATIONS / JUDGMENT CALLS
--------------------------------------------------------------------------------
1. Seed-content design: the retired ADR-30 test_log_rotate.py's seed constants
   (_SEED_IP_BLOCKLOG etc.) used a 3-space-token, no-CSV-details format
   specific to that ADR's calendar-reset mechanism (which never parsed
   per-line timestamps -- it only truncated to empty or kept the last K
   lines). This phase's seed content is NEW, written from scratch to match
   the REAL current per-type CSV shapes this ADR's Phases 2-4 established
   (verified against pfblockerng.inc/pfb_unbound.py source, not assumed --
   see REALITY CHECK #2), because the whole point of this live-VM case is to
   exercise Phase 6's real per-line timestamp parser (pfb_log_line_timestamp/
   pfb_log_age_cutoff) on realistic input. Filler CSV fields beyond the
   timestamp (interface names, protocol, hostnames) are semantically inert
   placeholders (RFC 5737 TEST-NET-1 IPs, "Unknown"/"pfB_TestList" labels) --
   the age-cutoff parser only reads field 0 (ip_blocklog) / field 1 (dnslog),
   so filler-field realism beyond "looks like a real CSV row" was not
   required and would have added no coverage value (ponytail: YAGNI).
2. Reused `h.unique_domain()` for the dnslog test's q_name values instead of
   a fixed literal -- not strictly required (a byte-identity harness may use
   fixed inert literals per the fixtures policy), but free and avoids any
   theoretical cross-run collision on a shared module VM; costs nothing.
3. Added a `_reset_log_max_days` autouse fixture (not present in the retired
   ADR-30 test, which relied only on per-test try/finally). This is a
   strengthening, not a weakening: CLAUDE.md's test-coverage mandate
   ("Self-encapsulated — never order-dependent... Reset per-test state
   explicitly with an autouse fixture") applies here just as it did to
   test_smoke_tick.py's `_reset_ledger`, and this module's 3 cases share a
   module-scoped VM the same way.
4. Kept the module-scoped `deployed_vm` fixture DNSBL-free (no
   ensure_dnsbl_vip/use_system_dns_upstream), matching the retired ADR-30
   test's own reasoning verbatim: log retention needs neither DNSBL nor feed
   infrastructure. Added `h.collect_host_diagnostics(smoke_vm)` in a
   try/finally around the fixture body (the retired test had none) to match
   the CURRENT house convention seen in test_smoke_tick.py/
   test_smoke_apply_on_change.py (both post-date the retired test).
None of the above weakens any CLAUDE.md MUST rule; all are additive/
strengthening relative to the retired template.
