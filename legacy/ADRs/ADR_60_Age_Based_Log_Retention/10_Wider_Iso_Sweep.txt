WHY THIS PHASE EXISTS
Once the "something might parse our old log format" excuse is gone for the 10 managed log types
(Phases 2-4), it no longer applies anywhere else in this codebase either. §1.8's sweep found several
more non-ISO date sites — two of which (`dnsbl_alias_update()`, `pfBlockerNG_clearsqlite()`) are
genuine latent wrong-year bugs (a value updated in December and viewed in January renders with the
wrong year), the rest are lower-risk normalization the user explicitly asked to fold into this ADR.

ACTION PLAN
1. `dnsbl_alias_update()` (`:5370`/`:5404`): convert `date('M j H:i:s', ...)` to
   `pfb_log_iso_timestamp()`'s format (or the equivalent call — this is a DNSBL group stat, not one
   of the 10 managed logs, so use whatever this file's existing ISO-8601 helper convention is, per
   ADR.md's note that 6 sites already use `'Y-m-d H:i:s'` directly).
2. `widget.php:390`'s call to `pfb_iso_timestamp()`: now that `dnsbl_alias_update()`'s stored value is
   already ISO with a real year, decide whether `pfb_iso_timestamp()` (the year-GUESSING reformatter)
   can be simplified to a straight pass-through/removed entirely, or whether it still serves a purpose
   (e.g. formatting old already-stored values from before this phase landed — a real upgrade
   consideration: existing installs have old-format values sitting in their DNSBL stats table until
   the next `dnsbl_alias_update()` call overwrites them). Your call, justify it in the handoff — don't
   silently delete a function that still protects an upgrade window without saying so.
3. `pfBlockerNG_clearsqlite()` (`:14133`/`:14137`): convert to the same ISO format. `widget.php:797`-
   `:798` displays this raw — confirm it renders correctly with no further change needed (it's a
   straight display of the stored string), or add a thin reformat if the display expects a specific
   shape.
4. `pfblockerng.inc:16534` (`/tmp` debug filename): convert `'M_j'` to `'Y-m-d'` (or similar
   fixed-width, sortable, year-bearing shape) — zero external consumer, trivial.
5. `pfblockerng.php:843` (MaxMind `gmdate('D, j M Y H:i:s T')`): this already has a year and is purely
   cosmetic — convert to `'Y-m-d H:i:s'` for consistency, verify `widget.php:524`'s display of it
   still reads sensibly.
6. `pfblockerng_update.php:291`/`:292` (`'Y-m-d H:i'`): add seconds (`'Y-m-d H:i:s'`) for consistency
   with every other ISO timestamp in the codebase.
7. `pfb_unbound.py:893`/`:898` (`strftime("_%Y%m%-d%H%M%S.log")`): drop the `-` (`"_%Y%m%d%H%M%S.log"`)
   so the filename is fixed-width and lexically sortable.
8. Do NOT touch `www/index.php:101`'s HTTP `Expires:` header — RFC 7231/2822 is protocol-mandated;
   confirm in the handoff that you looked at it and left it alone deliberately, not by oversight.
