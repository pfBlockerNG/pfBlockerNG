WHY THIS PHASE EXISTS
`log`/`extraslog` currently only get a timestamp if the caller embeds a literal `NOW` token, and even
then a process-global same-second dedup (`$pfb['pnow']`) can strip it to nothing (ADR.md §1.4 — this
predates the repo by over a decade and has no documented rationale). `errlog` has 6 bypass writes
(`pfb_open_sqlite()`) with zero timestamp. This phase makes all three always, unconditionally
stamped with the same ISO-8601 format, and deletes the dedup bug.

ACTION PLAN
1. In `pfb_logger()`: delete the `strpos($log, 'NOW') !== FALSE` branch and `$pfb['pnow']` entirely.
   Every call now: `$now = pfb_log_iso_timestamp();` (wire in Phase 1's helper), then for
   `log`/`extraslog` (cases 1/3/4) prefix `$log` with `"{$now} "` before writing; for `errlog`
   (`$elog`, cases 2/6) prefix similarly. Defensively `str_replace()` out any literal `NOW`/
   `" [ NOW ]"` substring still present in the caller's raw message BEFORE prefixing (the exact
   substrings you enumerated above) — so a caller that embedded the old token doesn't end up with a
   dead "NOW" or empty "[ ]" artifact sitting mid-line.
2. Route the 6 `pfb_open_sqlite()` bypass writes through the same prefix (call
   `pfb_log_iso_timestamp()` and prepend it), so `errlog` has zero unstamped writes left.
3. Do NOT touch `pfb_failures()`'s logic (`grep 'FAIL' | grep {$today_date}`) — verify (don't just
