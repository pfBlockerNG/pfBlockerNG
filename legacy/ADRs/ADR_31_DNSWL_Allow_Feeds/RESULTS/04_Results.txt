Per-row field name and stored vocabulary
-----------------------------------------
Field name : ``action``
Path       : ``installedpackages/pfblockerngdnsbl/config/{group_idx}/row/{row_idx}/action``
Values     : ``'Permit'`` | ``'Deny'`` | absent (treated as ``'Deny'``)

Why it fits the pattern
-----------------------
The IP-side group action uses identical vocabulary: ``Deny_Inbound``, ``Deny_Outbound``,
``Deny_Both``, ``Permit_Inbound``, ``Permit_Outbound``, ``Permit_Both``, etc.
(``pfblockerng_category_edit.php:398``). The bare ``Deny``/``Permit`` vocabulary for a
per-DNSBL-row action follows the same root terms — shorter because the DNSBL action is not
directional (it applies to DNS resolution, not firewall rules).

This is a dynamic per-row key (parallel to ``custom`` and ``logging``) — read directly via
``$row['action'] ?? ''`` without going through PfbConfig (foreign-key exclusion, like
``pfblockerngdnsbl/config/{group}/row/{idx}/custom``). No registration in
``pfb_cfg_registry()`` required or performed.

ADR-28 storage freeze: the key is only ADDED with a default-on-absent of 'Deny'. No
existing stored value is changed; absent is treated as 'Deny' at read time.

Call-site change
-----------------
Location : ``src/usr/local/pkg/pfblockerng/pfblockerng.inc``

One ``$mode`` derivation block inserted once per row in ``sync_package_pfblockerng()``,
immediately after the ``$custom`` flag set (before the logging/state code):

    // ADR-31 P4: per-row action → manifest mode.
    // 'action' is a dynamic per-row key (like 'custom') — read
    // directly; default/absent ⇒ 'Deny' (deny path, byte-identical).
    // Config storage freeze (ADR-28): only 'Permit'/'Deny' are stored;
    // absent is treated as 'Deny'.
    $mode = (($row['action'] ?? '') === 'Permit') ? 'permit' : 'deny';

Both existing ``pfb_feed_manifest_row()`` call sites in the same per-row body (reuse path
and download/parse path) updated to pass ``$mode`` as the sixth argument:

    $pfb_py_feeds[] = pfb_feed_manifest_row(
        $header, $alias, $logging_type,
        …format…, …provenance…,
        $mode);           // ← was omitted (defaulted 'deny'); now explicit

Permit rows now emit ``"mode": "permit"`` in the manifest; Deny/absent rows omit the key
(byte-identical with every pre-ADR-31 manifest entry — the P3 contract is preserved).

Validation seam reused
-----------------------
No new validation surface: the per-row ``action`` field contains only the well-known
strings ``'Permit'``/``'Deny'`` (or absent). ``$mode`` is derived by a simple equality
check (``=== 'Permit'``), no exec/path/json_encode derivation touches it; PFBL-01 is
unaffected. ``pfb_filter(PFB_FILTER_WORD)`` on the ``$header`` (already present in the
download loop) continues to guard all exec/path derivations — no new scope needed in
``RequirePfbFilterSniff.php``.

Test methods:

Note for Phase 5 (UI select)
-----------------------------
Phase 5 adds a per-row Action select to the DNSBL feed-row editor in
``src/usr/local/www/pfblockerng/pfblockerng_category_edit.php``.

The field name and vocabulary the UI select must round-trip:

  Config path : ``installedpackages/pfblockerngdnsbl/config/{group_idx}/row/{row_idx}/action``
  PHP row key : ``$row['action']``
  Stored values : ``'Permit'`` (allow) | ``'Deny'`` (block, default)
  Default-on-absent : ``'Deny'`` (read: ``$row['action'] ?? ''`` === 'Permit' → only Permit triggers)

The UI must:
  - Present a select with exactly two options: ``Deny`` (default, selected when absent or 'Deny')
    and ``Permit``.
  - Save the selected string byte-exactly to the row's 'action' sub-key via
    ``config_set_path("installedpackages/pfblockerngdnsbl/config/{$rowid}/row/{$r_id}/action",
    $value)`` — same pattern as other rowhelper keys (``category_edit.php:819`` generic loop).
  - The absent ⟷ 'Deny' round-trip must be transparent: pre-Phase-5 rows (no stored 'action')
    display as Deny and continue to work correctly — Phase 4 already handles absent as Deny.
