Manifest ``mode`` contract
--------------------------
Field name : ``mode`` (optional string in each ``feeds[]`` entry of the manifest JSON)
Values     : ``'permit'`` | ``'deny'`` | absent
Semantics  : absent / ``'deny'``   → existing block build path, byte-identical behaviour
             ``'permit'``          → permit-mode build branch (Phase 2 implements this)
Back-compat: absent treated as ``'deny'`` — no required field; additive and optional
             (ADR-31 §2.2.5).

Note for Phase 4 (PHP manifest writer)
---------------------------------------
PHP must emit exactly ``"mode": "permit"`` (string, lowercase) in the JSON manifest
entry for each DNSWL feed row.  Block/deny feed entries omit the field entirely
(or emit ``"mode": "deny"`` — both are equivalent on the Python side).  The field
must appear inside the per-feed object in ``feeds[]``, NOT in the top-level ``config``
block.  Example manifest entry:

    {
      "feed": "MyDNSWL",
      "group": "AllowFeeds",
      "format_hint": "plain",
      "log_flag": "1",
      "mode": "permit",
      "raw": "pfb_py_raw/myDNSWL_raw.txt"
    }

Where / how a permit host enters whiteDB
-----------------------------------------
Function : ``build()`` in ``src/usr/local/pkg/pfblockerng/pfb_unbound.py``
Location : the new ``if feed_row.get("mode") == "permit":`` branch inside the
           ``for feed_row in manifest.get("feeds", []):`` loop (inserted before the
           existing ``provenance``/``block_band`` logic).

Flow:
  1. For each line of the raw feed, skip empty lines, ABP comment/control lines
     (``!``, ``[``), and ABP anchors (``@@…``, ``||…``) — in v1 every plain host = allow.
  2. Call ``parse(fmt, stripped)`` to extract the host token (handles plain/hosts/csv:pon
     formats; returns None for invalid lines).
  3. Call ``normalise(entry.value)`` to lowercase + validate the domain shape.
  4. Call ``index_for(feed, group)`` to record provenance (same convention as block entries).
  5. Insert into ``white_db[domain]`` as::

       {"wildcard": True, "important": False, "band": PRIO_FEED_ALLOW, "index": idx}

  6. Monotonic-widen on collision: if an existing entry has ``band >= PRIO_FEED_ALLOW``
     (e.g. a band-6 manual whitelist entry), keep the existing higher band entry.
     ``_white_entry_band(existing) < PRIO_FEED_ALLOW`` → replace; same or higher → keep.
  7. After the permit loop, ``continue`` to skip the rest of the deny-path logic.

Band asserted: ``PRIO_FEED_ALLOW = 2`` (same as an ABP ``@@||host^`` allow).
``wildcard=True`` → subdomain-covering (the suffix walk in ``evaluate_domain`` covers
``sub.example.com`` when ``example.com`` is in whiteDB with ``wildcard=True``).

Provenance tag
--------------
Each permit feed's host entry carries an ``"index"`` key (``int``) that maps back to
``feed_group_index_db[idx]`` → ``{"feed": "<FeedName>", "group": "<GroupName>"}``.
This is the same provenance convention as block entries; reports can attribute a
permit allow to its DNSWL feed.

Host extraction
---------------
Host extraction reuses the existing ``parse(fmt, raw_line)`` → ``normalise(entry.value)``
call path (not ``_dnsbl_parse_abp_line()``):
  - ``parse()`` handles all existing plain/hosts/csv:pon/abp formats.
  - ``normalise()`` lowercases and validates the domain shape.
  - ABP directives inside a permit feed (``@@||``, ``||``, ``!``, ``[Adblock``) are
    skipped BEFORE ``parse()`` via the stripped-prefix guards (v1: every plain host = allow;
    ABP directives are not honoured inside permit feeds).
