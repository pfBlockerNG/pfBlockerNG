  Same pattern as ``tests/test_adr06_build_module.py::_evaluate_build``.

Fixture shape
-------------
Block feed:  ``format_hint='abp'``, provenance='feed' (default) or 'user' (band-5).
              Lines: ``||domain^`` anchors -> band-1 block entries in data_db/zone_db.
Allow feed:  Same ABP feed (combined lines) after block lines.
              Lines: ``@@||domain^`` anchors -> band-2 allow entries in white_db.
User whitelist: ``config.user_whitelist`` list -> band-6 entries in white_db.
User block:  Separate feed with provenance='user' -> band-5 entries in data_db/zone_db.

Band-5 fixture notes
--------------------
Band 5 (PRIO_USER_BLOCK) is produced by a manifest feed entry with
``"provenance": "user"``, which triggers the ``block_band = PRIO_USER_BLOCK``
path in ``build()`` (pfb_unbound.py:4648).  The test
``test_user_important_block_beats_feed_allow`` drives two manifest entries in
one build() call: a ``provenance='user'`` block feed (band 5) and a normal
feed-provenance allow feed (band 2).  The BEFORE state (band-5 block alone)
is verified first; then the AFTER state (band 5 with band-2 allow present)
confirms band 5 > band 2 and the block still wins.
