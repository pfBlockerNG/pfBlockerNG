WHY THIS PHASE EXISTS
ABP feeds reach Python verbatim (ADR-06/07); every entry the Python gates
drop — a malformed host in normalise(), an unqueryable name under the #753
wire caps — is counted NOWHERE (issue #789). Count, don't guard: Python
tallies rejects per feed, writes a stats artifact next to the built DBs, and
PHP emits the canonical stage=entries line. Buckets are RESOLVED: exactly
`shape` + `wire_cap`. Deliberate skip classes are NOT rejects and tally zero.
Python never logs the line itself — sinks stay PHP-only.

ACTION PLAN (ordered)

1. Classified normalise verdict (public contract UNCHANGED):
   - Extract the body into _normalise_verdict(value: str) -> tuple[str | None, str | None]
     returning (domain, None) on accept, (None, 'shape') or (None, 'wire_cap')
     on reject per the bucket mapping above (split the L3962 compound test).
   - normalise() becomes a thin wrapper returning only the domain — every
     existing caller and test stays green (this is the behaviour-preserving
     half; the existing TestNormalise suite is the oracle).

2. Tally plumbing (explicit param — parse_abp PURITY is test-pinned, no
   module-global counter):
   - A tally is a plain dict[tuple[str, str], dict[str, int]] keyed
     (feed, group) with bucket keys 'shape'/'wire_cap' (helper
     _tally_reject(tally, feed, group, bucket) — one place that does the
     defaulting; no class unless you genuinely need one).
   - parse_abp(..., tally=None): at its three normalise-fail sites use
     _normalise_verdict and, when tally is not None, count the bucket.
     tally=None => byte-identical behaviour (purity tests untouched).
   - build(): create the tally; pass it to both parse_abp call sites; count
     at the plain path (L4845-4846) and permit path (L4790-4792) via
     _normalise_verdict.
   - reconcile(..., tally=None): the fold-drop at L4252-4253 counts
     'wire_cap' attributed to the originating rule's feed/group (inspect
     what provenance is in scope at that line; if the folded key genuinely
     aggregates rules from several feeds, attribute to each contributing
     rule — document the choice in the handoff).
   - BuildResult gains the tally (a `rejects` field); build() returns it.

3. Stats artifact:
   - New chroot-relative bare name in init_standard beside pfb_py_count:
     pfb['pfb_py_reject_stats'] = "pfb_py_reject_stats.json".
   - dnsbl_emit_reject_stats(path, rejects) sibling of dnsbl_emit_count():
     atomic pattern (copy L356-374) + json.dump of a LIST of objects
     [{"feed": f, "group": g, "shape": n, "wire_cap": m}, ...] containing
     ONLY nonzero-total feeds, sorted (stable output for tests). An empty
     tally writes "[]" (PHP must distinguish "ran, zero rejects" from "no
     artifact").
   - Call it at BOTH dnsbl_emit_count call sites (init ~L1403, reload
     ~L5149). Python writes the artifact; it NEVER emits the log line.

4. PHP emission:
   - $pfb['unbound_py_reject_stats'] = '/var/unbound/pfb_py_reject_stats.json'
     beside L129.
   - New small function pfb_emit_entry_reject_stats(string $path): void in
     pfblockerng.inc: @file_get_contents; json_decode; on missing/unreadable/
     invalid/non-array -> return silently (fresh boot / old python module);
     else per entry, per bucket with count > 0:
       pfb_validate_log($feed, 'entries', $bucket, (string) $count);
   - Call it in pfb_update_unbound() right after the L7899 count read.
