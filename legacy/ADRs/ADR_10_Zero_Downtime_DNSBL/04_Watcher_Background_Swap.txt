ROLE
You are on the `adr/10` branch performing Phase 4 of ADR-10. This is the core change:
add a daemon watcher thread that, on a sentinel flip, runs `rebuild_and_swap()` OFF
the query threads — so a DNSBL update applies with NO Unbound restart. The Phase-2
single-ref swap + Phase-3 fail-closed make it safe. Work inline on `adr/10`, one
commit, push directly (PR only if rejected).

WHY THIS PHASE EXISTS
Phases 2-3 made the swap atomic + fail-closed but still synchronous at init. This
phase makes it happen at RUNTIME without a restart: a watcher wakes on the sentinel
the PHP side will flip (Phase 5), rebuilds in the background while query threads keep
serving the OLD snapshot (zero downtime, briefly stale by design), then atomically
swaps. The module already runs daemon workers (pfb_db_worker, pfb_async_worker) — this
adds one more of the same kind.

ACTION PLAN (ordered)
1. SENTINEL + GENERATION. Define the sentinel file + a monotonically-advancing
   generation id (the PHP side writes it in Phase 5; here, define the contract +
   reader). The watcher acts on a generation ADVANCE, not on bare mtime, so a missed/
   coalesced event only delays — never corrupts (correctness rides on Phase-5's atomic
   publish, not on notify latency).
2. WATCHER THREAD. Add a daemon thread started in init_standard next to the existing
   workers (gated on pfb["mod_threading"]): wait on the sentinel via select.kqueue
   EVFILT_VNODE on the sentinel's DIRECTORY where available (FreeBSD; inotify is
   Linux-only — do NOT use it), with a low-frequency mtime-poll FALLBACK. On a
   generation advance -> call rebuild_and_swap().
3. SINGLE-FLIGHT. Guard against overlapping rebuilds (a rebuild-in-progress flag /
   lock): a trigger during a build is coalesced; after the build, re-check the
   generation and rebuild once more if it advanced. Never run two builds at once
   (protects the ~2x-RAM ceiling from Phase 1).
4. LIFECYCLE. Clean start/stop: join the watcher on deinit (mirror :1603-1637); the
   build runs off the query threads; the swap is the only writer of the snapshot ref.
5. TESTS (no live Unbound): drive the watcher with a stubbed rebuild + a temp sentinel
   dir — detects a generation advance, coalesces concurrent triggers, keeps the old
   snapshot when the stubbed build fails, and joins cleanly. Cover the mtime-poll
   fallback path (kqueue may be unavailable on the test host).
