WHY THIS PHASE EXISTS
The whole ADR (one background build + one atomic global-ref swap serving all query
threads) holds ONLY IF Unbound's `pythonmod` worker threads share one interpreter
and one set of module globals. If they are isolated, a single swap is invisible to
the other workers and the design is REJECTED. Separately, the build transiently
doubles DNSBL RAM (~274 B/entry x millions) — on a small box that can OOM mid-swap.
Building anything before these are settled would repeat the ADR-01 trap (machinery
on an unproven premise). We also need the CURRENT restart downtime as the baseline
the swap must beat, and the cache benchmarks that drive Phases 3/5.
