ACTION PLAN (ordered)
1. CONFIG SCHEMA: define the hooks list shape — entries `{command, when: pre|post,
   enabled: bool, description, timeout?}` under the pfBlockerNG config. A read helper
   returns the enabled entries for a given `when`, in list order.
2. RUNNER `pfb_run_hooks(string $when, array $ctx): void`:
   - For each enabled hook matching `$when` (in order): build the env from `$ctx`
     (PFB_* vars), run the command **as root** via `mwexec` **with a per-hook timeout**
     (default e.g. 60s, overridable), capture stdout+stderr to `pfb_logger` under a
     clear per-hook header.
   - **Non-zero exit OR timeout → log it and CONTINUE** (never throw, never abort).
   - Confirm the timeout reliably kills a child (this is the reject-criteria check from
     §7 — if mwexec's timeout can't kill a hung child, record it and propose the
     detached-exec pivot).
3. CLI TEST PATH: a small manual invocation (e.g. an argv branch) to run a `when` with a
   synthetic ctx, for live testing — without touching the update pass.
4. Keep it UNWIRED: sync_package_pfblockerng is NOT modified this phase.
