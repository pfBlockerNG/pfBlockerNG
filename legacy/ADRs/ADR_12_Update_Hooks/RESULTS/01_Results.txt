1. CONFIG SCHEMA (keys + defaults)
----------------------------------
Hooks live under the existing pfBlockerNG config node:
    installedpackages/pfblockerng/config/0/hooks   (a list)

Each entry (mirrors pfSense shellcmd's {cmd,cmdtype} shape):
    command      string   the sh command line (run via /bin/sh -c). REQUIRED (blank => skipped).
    when         string   'pre' | 'post'. REQUIRED (other values => skipped).
    enabled      string   pfSense checkbox convention: 'on' enables; anything else (''/unset) => skipped.
    description  string   optional free text; used as the per-hook log label (falls back to "#<idx>").
    timeout      string   optional per-hook timeout in seconds; <=0 / invalid => default.

Defaults (PHP constants, define()-guarded so re-include is safe):
    PFB_HOOK_TIMEOUT_DEFAULT = 60   (per-hook timeout when unset/invalid)
    PFB_HOOK_KILL_GRACE      = 5    (seconds after SIGTERM before SIGKILL)

Read helper (PURE, unit-tested):
    pfb_get_hooks(array $pfbconfig, string $when): array
      Returns enabled entries matching $when, IN LIST ORDER. Skips: non-array entries,
      enabled!=='on', when mismatch, blank/missing command, invalid $when ('' / not pre|post),
      and a missing/malformed 'hooks' key. Never throws.
    pfb_hook_timeout(array $hook): int
      Resolves timeout to a positive int, falling back to PFB_HOOK_TIMEOUT_DEFAULT.


2. RUNNER SIGNATURE + ENV-VAR NAMES
-----------------------------------
    pfb_run_hooks(string $when, array $ctx = array()): void   (declared as `function pfb_run_hooks($when, $ctx = array())`)

Behaviour: reads the live config (config_get_path), selects via pfb_get_hooks(), runs each
enabled hook in list order as root, captures stdout+stderr to pfb_logger under a per-hook
header, logs each outcome. Returns early (no-op) when there are no enabled hooks for $when
=> with no hooks the pass is byte-identical (the additive contract).

Env vars set for the child (PFB_ + uppercased $ctx key; values escapeshellarg'd):
    PFB_WHEN        ALWAYS set by the runner to $when ('pre'|'post').
    PFB_<KEY>       one per $ctx entry, e.g. ctx['TRIGGER']='cron' => PFB_TRIGGER=cron.

Phase 1 does NOT define the canonical ctx contents — that is Phase 2's context builder.
Per ADR §2 the canonical names Phase 2 will pass are:
    pre : PFB_TRIGGER, PFB_WHEN
    post: PFB_TRIGGER, PFB_WHEN, PFB_IP_CHANGED, PFB_DNSBL_CHANGED, PFB_STATUS, PFB_CHANGED_ALIASES
The runner is name-agnostic (it exports whatever keys $ctx carries), so the Phase 2 builder
just supplies that map.


3. TIMEOUT MECHANISM + KILL VERDICT
-----------------------------------
Mechanism (per hook), built and run with PHP exec() — the file's established capture idiom
(exec("/usr/bin/... 2>&1", $output, $retval)):

    PFB_K=V ... /usr/bin/timeout -s TERM -k 5 <timeout> /bin/sh -c <escapeshellarg(command)> 2>&1

  - Root: the update pass already runs as root (cron/manual), so the child inherits root.
  - Timeout: FreeBSD /usr/bin/timeout(1) sends SIGTERM at <timeout>, then SIGKILL after the
    -k grace (5s). Exit code 124 == timed out.
  - Capture: 2>&1 folds stderr into stdout; exec() collects it into $output for the log.
  - Env: the VAR=val prefix is inherited by timeout(1) and exported to the /bin/sh child only
    (verified: a var-assignment prefix passes through an intermediate binary to the sh child).

KILL VERDICT: timeout reliably kills a hung child TREE on the FreeBSD target. NO PIVOT NEEDED.
  Why it is reliable (verified against the FreeBSD timeout(1) man page): WITHOUT --foreground
  (our invocation), timeout manages the command AS A PROCESS GROUP and propagates the signal
  (then SIGKILL after -k) to the command AND ITS DESCENDANTS. So a hook like `sleep 30` (run as
  a grandchild under /bin/sh -c) is killed as a group at the deadline+grace — no descendant
  survives to hold the stdout pipe, so PHP exec() returns promptly with rc 124. The runner then
  logs "TIMED OUT ... (killed); continuing" and proceeds. The update is never stalled.

  Local kill-test caveat (NOT a production defect): macOS lacks /usr/bin/timeout and setsid, so
  a hand-rolled shim could not replicate the process-GROUP kill; with only the direct child
  killed, a surviving grandchild kept stdout open and PHP exec() blocked until the grandchild
  ended (proven: a backgrounded grandchild holding stdout blocks exec() ~ its full lifetime).
  This is exactly the failure mode FreeBSD timeout(1)'s pgroup kill prevents — confirming the
  production wrapper is correct and the macOS hang is a test-environment limitation only.

  What WAS faithfully verified locally (macOS, real PHP exec()):
    - PFB_* env vars reach the child with correct values (incl. post-style multi-var ctx).
    - escapeshellarg() makes the command a single sh -c argument => injection-safe
      (embedded `; rm -rf ...` is data, not executed).
    - Non-zero exit captured (rc=3) with stderr folded into the log; loop continues.
    - Success (rc=0) captured + logged.
