1. THE DOCUMENTED HAPROXY RELOAD COMMAND (the recipe's post hook)
-----------------------------------------------------------------
  [ "$PFB_IP_CHANGED" = "1" ] && echo 'require_once("haproxy/haproxy.inc"); haproxy_check_run(1);' | /usr/local/sbin/pfSsh.php

  - Guarded on the ACCURATE flag PFB_IP_CHANGED (=1 only when IP-side data changed).
  - GRACEFUL reload, not a hard restart: haproxy_check_run(1) (haproxy.inc:2491; wrapped
    by haproxy_configure() at :1347-1350) re-writes the config — which re-emits the -f
    ACL files including ipalias_pfB_Aggregate_v4.lst — and restarts with -sf (finish
    existing connections; hitless). It is the package's own supported reload entry.
  - Why pfSsh.php, NOT `php -r`: haproxy.inc opens with bare require_once("functions.inc")
    etc. that resolve only via pfSense's PHP include_path. /usr/local/sbin/pfSsh.php
    bootstraps the pfSense env (globals.inc/functions.inc/config.inc/util.inc — verified
    against upstream pfSsh.php) so require_once("haproxy/haproxy.inc") + its dependency
    chain load; pfSsh.php evals PHP piped on stdin (php://stdin fgets — verified upstream).
    Install path /usr/local/sbin/pfSsh.php (verified, shebang #!/usr/local/bin/php-cgi -f).
  - POSIX-sh-safe: single-quoted PHP literal (no shell expansion of the metacharacters),
    `[ … ] && cmd` short-circuit. Runs on the node that performs the update (CARP: each
    node reloads its own HAProxy).
  - SOURCE FACTS verified against
    /Users/andre/git/FreeBSD-ports/net/pfSense-pkg-haproxy-devel/files/usr/local/pkg/haproxy/haproxy.inc:
      :2491  haproxy_check_run($reload, $keep_server_state=true) — the reload core
             (:2504 haproxy_writeconf re-emits ACL files; :2557-2569 -sf hitless reload).
      :1347-1350 haproxy_configure() => return haproxy_check_run(1) (the public wrapper).
      :1084-1092 ipalias_{value}.lst emitted ONLY for a source_ip ACL whose value is_alias;
                 written as `src -f $configpath/ipalias_<alias>.lst`.
                 $configpath = {$g['varetc_path']}/haproxy = /var/etc/haproxy (:2496).
      :1562  stats socket /tmp/haproxy.socket level admin (+expose-fd listeners) — socket
             is stats + hitless-reload only; CANNOT inject ACL data => reload required.

2. THE DOCUMENTED HAPROXY CONFIG PATTERN (hack-free)
----------------------------------------------------
  - One source_ip ACL (type "Source IP matches IP or Alias") on the alias pfB_Aggregate_v4
    (ADR-11) — purely so the HAProxy package emits + maintains
    /var/etc/haproxy/ipalias_pfB_Aggregate_v4.lst (:1084-1092).
  - A custom header ACL matching the CF real-client IP against that file:
      acl cf_blocked req.hdr_ip(CF-Connecting-IP) -f /var/etc/haproxy/ipalias_pfB_Aggregate_v4.lst
      http-request deny if cf_blocked
    (XFF variant: req.hdr_ip(X-Forwarded-For)).
  - SECURITY note documented: CF-Connecting-IP / XFF is spoofable unless the TCP source is
    a Cloudflare edge range — gate the deny on a Cloudflare-range source ACL first.
  - HACK-FREE: ADR-11's never-empty pfB_Aggregate_* consumer file means an empty aggregate
    still validates + reloads, so NO /../../ path trick and NO dummy-IP hack is needed.
    Documented explicitly; reject-criterion "recipe can't be made hack-free" = NOT triggered.
