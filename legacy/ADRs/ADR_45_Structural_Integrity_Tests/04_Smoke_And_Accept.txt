ACTION PLAN (ordered — new cases alongside the ADR-44 archive cases ~L1951+)

Use inert IP bodies (RFC 5737), an IpCase (format auto), Force Update via
CaseContext, and pfctl_table membership — same as test_zip_feed_imports.

1. CORRUPT-ARCHIVE-REJECTED (Phase-2 proof), one case per format the box supports
   (zip + gzip + bzip2; 7z only if /usr/local/bin/7z is on the image — else
   document it as an out-of-CI item, do not fake it):
   - Build a VALID archive of a tiny inert IP body, then TRUNCATE it (e.g. first
     half of the bytes, or corrupt the trailing checksum/footer). register() the
     corrupt bytes.
   - Assert the alias is ABSENT before AND remains ABSENT after a Force Update
     (the structural probe rejects it pre-extraction), and that no pf rule
     references it. Optionally assert the pfBlockerNG log shows the
     "structural probe failed" rejection (read it on-box). Print
     expected-vs-actual on failure.
   - Pair each corrupt case conceptually with the existing healthy-archive case
     (test_zip_feed_imports / test_gzip_feed_imports already prove the valid side
     imports) so green proves the probe is a real branch, not an always-reject.

2. OCTET-STREAM-RECOVERED (Phase-3 primary #581 proof):
   - Build a VALID ZIP of a tiny inert IP body, then PREPEND a few junk bytes
     before the first local header so `file -b --mime-type` on the box reports
     application/octet-stream while bsdtar can still list/extract it (the Top1M
     `top-1m.csv.zip` is the real-world analogue — note this in the test
     docstring).
   - On-box guard: read `file -b --mime-type` of the staged download; if the
     box's magic db does NOT report octet-stream, the recovery path is not
     exercised — still assert the feed IMPORTS (it would via the normal zip
     branch) and LOG the observed verdict, rather than failing. When it DOES
     report octet-stream, assert the member loaded — proving recovery adopted
     application/zip and the feed imported where today it is rejected.
   - Assert the alias ABSENT before, member PRESENT after.

3. JUNK-OCTET-STREAM-REJECTED (Phase-3 reject branch — ADR §7):
   - register() a random/non-archive blob that `file` reports as octet-stream
     (guard the verdict). Assert the alias is ABSENT before and AFTER Force
     Update — no probe passes, so it is still rejected. This is the
     "never blanket-accept octet-stream" pin; it MUST accompany the recovery
     case (both branches).

4. HEALTHY-FEED-STILL-IMPORTS: confirm the existing test_zip_feed_imports /
   test_gzip_feed_imports still pass unchanged (the probe is a pass-through on
   valid input). If a bzip2 healthy case is missing, add a small one for parity
   so every decompression branch has a valid+corrupt pair.

5. Mark every new case with the same pytest marker(s) the sibling archive cases
