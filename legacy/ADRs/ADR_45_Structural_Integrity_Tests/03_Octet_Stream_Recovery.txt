WHY THIS PHASE EXISTS
This is the reconciled PRIMARY #581 fix. file(1) sometimes returns
application/octet-stream (or empty) for a PERFECTLY VALID, extractable archive —
self-extracting ZIP stubs, archives with leading bytes before the first local
header, an older magic database. The canonical LIVE case (ADR §1): the Top1M
`top-1m.csv.zip` (alexa/tranco/umbrella), fetched via pfblockerng.php's
$pfb['extras'], is reported as octet-stream. Today the MIME gate rejects it
outright. This phase recovers it by POSITIVE structural identification — never a
blanket accept: probe each supported archive type; on the first passing probe,
adopt that canonical type and proceed. If no probe passes (random binary, an HTML
error page), reject exactly as today.
