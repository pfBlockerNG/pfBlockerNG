# Copilot adapter — pfBlockerNG

Scope: GitHub Copilot-specific surfaces and the canonical-noun → Copilot translation.
Canonical policy is `AGENTS.md` + its routed `.agents/policy/` / `.agents/context/` files;
this adapter only maps them onto Copilot mechanics.
Load when: every Copilot session, at start (`.github/copilot-instructions.md` sends you
here). Claude and Codex sessions never read this file.

Copilot translates canonical nouns mechanically:

| Canonical / Claude surface | Copilot surface |
| --- | --- |
| `/name` or `.claude/skills/name` | `/name` from `.agents/skills/name` (same source — Copilot scans `.github/skills/`, `.agents/skills/`, `.claude/skills/` and deduplicates by skill name). |
| `Agent` / planner / implementer / verifier | Copilot custom agent per `.github/agents/*.agent.md`, launched with `/agents`; roles + tier bindings in `.agents/policy/agent-roles.md` (checked by `scripts/check_agent_roles.py`). The mutation boundary rides a `<!-- mutation: ... -->` marker in the body: CLI 1.0.78 logs `unknown field ignored` for any front-matter key outside its schema. |
| `AskUserQuestion` | Ask in the conversation; Copilot has no structured question tool. |
| Background `run_in_background: true` | No harness-tracked background task exists — run waits in the foreground with a hard cap, or hand the wait to the user. Never a shell `&`. |
| Claude `Co-authored-by` attribution | Never credit Copilot as a co-author: no verified Copilot identity exists here. Keep the human's signed identity and disclose Copilot authorship in the PR audit/footer. |
| Claude public-comment footer | `🤖 Generated by GitHub Copilot and posted on behalf of @<login>.` Never identify Copilot output as Claude or Codex. |
| Claude-only status/token/UI hooks | No equivalent unless `.github/hooks/pfblockerng.json` maps one. |

Copilot specifics:

- **Hooks need the user-level install.** `sh scripts/agent/install-copilot-hooks.sh` writes
  `~/.copilot/hooks/pfblockerng.json` pointing at `scripts/agent/copilot-session-hook.sh`;
  run it once per machine (the dispatcher no-ops outside a pfBlockerNG-org checkout, so a
  global install is safe). Probed 2026-08-05 on CLI 1.0.78 with `copilot -p`: the documented
  repo-level `.github/hooks/*.json` and inline `.github/copilot/settings.json` fired NOTHING,
  while an identical user-level file fired both `sessionStart` and `userPromptSubmitted`
  (interactive mode untested). `.github/hooks/pfblockerng.json` is kept as the
  forward-compatible definition and calls the same dispatcher.
- **Hook schema:** repo-level at `.github/hooks/*.json`, events camelCase. Only `sessionStart`,
  `subagentStart`, `postToolUse`, and `postToolUseFailure` have their stdout parsed for
  `additionalContext`; `userPromptSubmitted` output is discarded, and per-turn injection
  would need `userPromptTransformed` returning `modifiedTransformedPrompt`. `preToolUse` is
  fail-closed: a crash or any non-zero exit denies the tool call.
- **The mode capsules ride the instructions file first.** `sessionStart` also emits them,
  but a CLI build that drops `sessionStart` output (upstream bug) must not take the modes
  with it, so `.github/copilot-instructions.md` is the reliable carrier.
- **Session records.** Copilot sets no environment variable in the shells it spawns, so
  `sessionStart` (via that install) records the CLI pid under
  `<common-git-dir>/pfb-copilot-sessions/` and `sessionEnd` removes that one record;
  `.githooks/prepare-commit-msg` and `.githooks/pre-push` treat ANY live record as an agent
  runtime, so ending one of several concurrent sessions cannot disarm the guards. A record
  whose pid is gone is ignored and pruned. The pid is resolved by walking up to the `copilot`
  ancestor — the hook's own shell exits immediately, so recording it would expire on the
  spot. The cloud agent sets `COPILOT_AGENT_PROMPT` and needs no record.
- **Reviews** use `adversarial-reviewer`(-`top`/-`mid`) from `.github/agents/` per
  `.agents/policy/landing.md`. The Copilot **code-review bot** stays disabled by owner
  directive — an unrelated surface.
- `work-branch.sh --worktree` resolves the primary checkout from a session worktree exactly
  as it does for the other clients.
- Plugins install from `.github/plugin/plugin.json` inside the plugin root; the vendored
  set is `plugins/mattpocock-skills/.github/plugin/` and `plugins/ponytail/.github/plugin/`.
